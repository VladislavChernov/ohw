# Proposal: лаборатория качества обученной модели (Dz9)

## Почему

В ДЗ9 нужно закрыть полный цикл проверки качества обученной модели:

- загрузить датасет и разделить на обучающий/тестовый набор;
- реализовать модель на Python 3 и обучить её;
- провести предсказания на тестовом наборе;
- вычислить метрики качества (accuracy, precision, recall);
- написать автотесты, проверяющие загрузку, обучение, метрики и сохранение;
- визуализировать метрики.

Сейчас в репозитории нет такого самостоятельного ML-конвейера: Dz2/Dz8 —
это LLM-контролируемые контуры генерации и проверки, здесь задача
прикладная: классический ML.

## Что делаем

- **Новый код в `dz9/`**: пакет `<package>` с модулями dataset, model,
  train, predict, metrics, persistence, visualize, config.
- **Датасет**: загрузка CSV, стратифицированный train/test split.
- **Модель**: scikit-learn, детерминированный training.
- **Метрики**: confusion matrix + accuracy/precision/recall, формулы с
  fail-safe на нулевой знаменатель.
- **Сохранение**: pickle-модель в `dz9/output/`.
- **Визуализация**: matplotlib, сохранение PNG в `dz9/output/`.
- **Тесты**: unit-тесты на микроданных, без сети, без внешних файлов.

## Чего не делаем

- Не поднимаем новые контейнеры/сервисы/порты.
- Не добавляем LLM-агента и API.
- Не добавляем UI.
- Не добавляем новые зависимости без необходимости.
- Не тюним пороги после первого прогона.

## Спека

Дельта `model-quality-lab`: загрузка/разбиение, обучение, предсказания и
метрики, автотесты, визуализация.

## Проверка

- `pytest -m "not integration"` (unit без сети) — зелёный.
- `ruff check src tests` — чисто.
- `mypy src` — чисто.

## Вне рамок

- Файнтюнинг модели.
- CLI/UI поверх этого конвейера.
- Онлайн-валидация датасета.
