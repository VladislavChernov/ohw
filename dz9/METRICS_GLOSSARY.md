# Глоссарий метрик

Краткий справочник по метрикам и понятиям, которые используются в
`model_quality_lab`. Все метрики считаются по матрице ошибок на тестовой
выборке — той части данных, которая не участвовала в обучении.

## Матрица ошибок (confusion matrix)

Для бинарной классификации класс `1` считается «положительным», класс `0` —
«отрицательным».

| | Предсказано `1` | Предсказано `0` |
|---|---|---|
| **Истинно `1`** | TP (true positive) | FN (false negative) |
| **Истинно `0`** | FP (false positive) | TN (true negative) |

- **TP** — модель верно предсказала положительный класс.
- **TN** — модель верно предсказала отрицательный класс.
- **FP** — модель предсказала `1`, а на самом деле `0` (ложное срабатывание).
- **FN** — модель предсказала `0`, а на самом деле `1` (пропуск цели).

`N = TP + TN + FP + FN` — общее число объектов в тестовой выборке.

## Accuracy (доля правильных ответов)

```text
accuracy = (TP + TN) / N
```

Доля объектов, для которых модель угадала класс. Простая и понятная метрика,
но при сильном дисбалансе классов может вводить в заблуждение: модель,
которая всегда предсказывает `0`, получит высокий accuracy на данных, где
класс `0` встречается часто.

## Precision (точность)

```text
precision = TP / (TP + FP)
```

Из всех объектов, которые модель назвала положительными, — какая доля
действительно положительна. Отвечает на вопрос: **«насколько можно верить
положительному предсказанию?»**

Высокий precision важен, когда цена ложного срабатывания велика (например,
отправка письма в спам).

## Recall (полнота)

```text
recall = TP / (TP + FN)
```

Из всех реально положительных объектов — какую долю модель нашла. Отвечает
на вопрос: **«сколько положительных объектов мы пропустили?»**

Высокий recall важен, когда нельзя пропускать цель (например, поиск
заболевания при скрининге).

## Precision vs recall

Метрики конфликтуют: можно найти все положительные объекты (recall → 1),
но получить много ложных срабатываний (precision ↓), или наоборот.
Поэтому их смотрят вместе, а не по отдельности.

## Нулевой знаменатель (fail-safe)

В проекте принято безопасное поведение вместо деления на ноль:

- если `TP + FP = 0` (модель не предсказала ни одного `1`), то
  `precision = 0.0`;
- если `TP + FN = 0` (в тестовой выборке нет объектов класса `1`), то
  `recall = 0.0`.

Это позволяет пайплайну не падать на вырожденных предсказаниях.

## Train/test split и стратификация

- **Train/test split** — данные делятся на обучающую и тестовую части.
  Модель учится только на train, а метрики считаются на test. Это проверяет
  обобщение, а не запоминание.
- **Стратификация** (`stratify=y`) — доли классов в train и test сохраняются
  такими же, как в исходном датасете. Особенно важно при дисбалансе.
- **`random_state`** — фиксированный seed делает разбиение и обучение
  воспроизводимыми.

## Стандартизация признаков

`StandardScaler` приводит каждый признак к среднему `0` и стандартному
отклонению `1`. Для линейных моделей (особенно перцептрона) это критично:
без масштабирования признаки с большим диапазоном доминируют, и качество
падает. В проекте масштабирование встроено в `Pipeline`, поэтому при
предсказании применяются те же преобразования, что и при обучении.

## Как читать сравнительный график

`output/metrics_comparison.png` содержит сгруппированные столбцы
`accuracy`, `precision`, `recall` для каждого прогона
(`dataset:model`). Он нужен, чтобы:

- сравнить модели на одном датасете при одинаковом split;
- увидеть, где модель «жертвует» recall ради precision или наоборот;
- заметить, что датасет влияет на качество сильнее, чем выбор модели.

## Что не входит в проект

F1-мера, ROC-AUC, PR-AUC и калибровка вероятностей не вычисляются: по ТЗ
достаточно accuracy, precision и recall. Матрица ошибок используется как
основа для этих трёх метрик.
