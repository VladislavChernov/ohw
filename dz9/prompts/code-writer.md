## Принципы написания кода

### Харнес: общие правила

1. **Never cite a document you have not read.** Прежде чем утверждать, что
   спека/ADR/конвенция такова — открой и процитируй/перефразируй. Вероятное
   объяснение ≠ доказательство.
2. **Read what the code already does before framing the question.** В коде с
   историей поведение уже — это решение; вопрос чаще «менять ли уже принятое
   решение и почему так сделано», чем «какое решение принять».
3. **Spec-first.** Код — это *что*, предложение/спека — это *почему*. Сначала
   спека, потом код, потом — при необходимости — правка спеки.
4. **Решение, не прошедшее проверку, исправляется в документе первым.** Аменд
   спеки — часть изменения, а не follow-up.
5. **Открытое решение → сначала анализ, потом код.** Не писать код на
   незафиксированном предпроектном решении.
6. **Правило вместо списка не enforced.** Не перечисленные в спеке правила —
   это карта опасностей, а не бэлог.
7. **Критерий пишется до прогона.** Артефакт без заранее объявленного
   критерия — это лог, не доказательство.

### Харнес: измерение

1. Счётчик, который невозможно измерить, SHALL говорить `unknown`, а не `0`.
2. Деноминатор рядом с числом; единицы — правильные. Деление на «отношения»
   вместо «слотов» даёт ошибку в два раза.
3. **`n = 1` — не результат.** Достаточно отвергнуть гипотезу одной пробойной
   выборкой — не достаточно принять её.
4. Гипотеза, опровергнутая вторым материалом, — пишется как опроверженная,
   а не отбрасывается.

### Харнес: код и ревью

1. Контракт формулируй как положительную инвариантность, а не как застывший
   список: «поле, которое онтология называет каноническим, SHALL резолвить
   endpoint'ы» — переживёт правку списка полей; «id не должно быть в списке» —
   провалится на первой легитимной правке и научит работать вокруг теста.
2. **Ничего не хардкодить там, где живёт само.** Порог, размер, число фиксируй
   до результата, а не подбирай после него.
3. **Регрессионный тест должен собирать то, что собирает модель.** Если
   упал результат модели — тест должен использовать форму выходных данных.
4. **Чинить класс, а не экземпляр.** Нашёл один сбой — ищешь остальные того же
   класса и закрываешь одним решением.
5. **Тишина хуже падения.** Любой сбой SHALL быть виден в трёх местах:
   лог, отчёт/счётчик, контекст. «Кажется, работает» — запрещённый исход.
6. **Предпочтителен guard-тест к заметке.** Ошибку, легко и быстро сделать —
   закрывай тестом, а не абзацем.
7. **Само-ревью до коммита, не после.** Adversarial reviewer проверяет diff;
   подтверждённые баги фиксируются через основного агента, затем —
   пере-проверка и пере-ревью.

### Харнес: окружение и процесс

1. Хост владеет git и файловыми операциями; контейнер — код, тесты, линтеры.
2. Один постоянный dev-контейнер; не плодить throwaway-контейнеры.
3. Не считать edit видимым до теста: подтверждать mount, доказывать наличие
   правки через сравнение содержимого, а не через предположение.
4. PowerShell quoting/encodings — обычная причина падений, не код. `;` вместо
   `&&`, скрипт в файл, не в `bash -c`. Не-ASCII — одним путём, проверять чтением
   файла. Replacement-characters = сигнал mojibake.

### Проект: правила кода

1. Python 3.13, type hints, `from __future__ import annotations` при необходимости.
2. Determinism: фиксированные `random_state` для split и обучения.
3. Split применяется один раз и только к исходным данным; тест никогда не
   участвует в обучении (no leakage).
4. Метрики — только из фактической матрицы ошибок; знаменатель 0 → fail-safe
   `0.0`, без деления на ноль.
5. ML-график — headless backend (`Agg`), сохранение в файл; в unit-тестах не
   открывать окно.
6. Никаких `print` в библиотеке: `logging`; CLI — в stderr.
7. Никаких `shell=True`.
8. Все новые зависимости — только с обоснованием.
8.1. **Критический запрет на Pandas:** В коде пакета `model_quality_lab` категорически ЗАПРЕЩЕНО использовать библиотеку `pandas` (`import pandas` под полным запретом). Весь парсинг, валидация и чтение CSV-файлов должны выполняться строго с помощью встроенного модуля `csv` или функции `numpy.genfromtxt`.
9. Тесты: unit — без сети и внешних данных, на синтетических микроданных;
   `ruff check src tests` и `mypy src` — чисто; не `assert True`; не поднимать
   пороги, чтобы скрыть падение.
10. Не писать «всё работает», если проверки не запускал.

### ML: загрузка данных

1. `dataset.load(name) -> DatasetSplit` — generic mechanism: registry
   (`breast_cancer`, `pima_indians`) + локатор `csv:<path>`.
2. Формат размеченного CSV: колонки `feature_1…feature_N` + бинарная метка
   `label ∈ {0, 1}`.
3. Датасет выбирается ключом конфигурации (`dataset`); конвейер выполняется
   для каждого выбранного ключа.
