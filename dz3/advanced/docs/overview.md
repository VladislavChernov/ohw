# Dz3/advanced — простое объяснение

> Человекочитаемый обзор для QA-инженеров, менеджеров и всех, кто хочет
> понять суть без глубокого кода. Технические детали — в [README](../README.md)
> и [openspec](../openspec/changes/).

## Это вообще что?

**Одной строкой:** генератор автотестов на API, где **нейросеть придумывает
план тестов, а надёжный «движок» его исполняет** — нейросеть код не пишет и не
запускает.

## В чём идея

Обычно автотесты пишут так: человек (или ИИ) пишет код вида
`def test_...()`, и этот код потом выполняют. Минусы: код, сгенерированный
нейросетью, бывает некорректным, а запускать непроверенный код рискованно.

В Dz3/advanced пошли иначе — **поменяли контракт**:

1. **Локальная нейросеть (Ollama)** получает только документацию API и выдает
   **структурированный план тестов (JSON)** — «вот тест: сходить на такой
   эндпоинт, сделать такой запрос, проверить, что ответ такой-то». Это
   **данные, а не код**.
2. **Детерминированный «движок» (ядро)** читает план и **сам** делает
   HTTP-запросы к API, проверяет результаты по критериям из плана, приводит
   состояние API в порядок и формирует **отчёт**.
3. Итог — понятный отчёт: какие тесты прошли, какие упали и **почему** (на
   каком шаге, какая проверка не сработала).

## Как это работает (коротко)

```
 Документация API ──► Нейросеть выдумывает план тестов (JSON)
                             │
                             ▼
                Валидатор: всё ли покрыто? есть ли «откат»?
                             │  если нет ──► нейросеть переделывает план
                             ▼
           ЯДРО: реально шлёт запросы, проверяет ответы,
                             делает откат состояния
                             ▼
                  Отчёт: прошло / упало, с причинами
```

## Ключевые свойства

| Свойство | Что это значит |
|---|---|
| Нейросеть не запускается | Убрали риски выполнения непроверенного кода |
| Ядро — «тупое и надёжное» | Только HTTP + проверки по плану, всё предсказуемо |
| План — данные | Его структура версионируется (сейчас `v3`), легко расширять |
| Покрытие API | Валидатор следит, что план покрыл нужные ресурсы |
| Безопасность данных | Для изменяющих операций (POST/PUT/DELETE) план обязан включать «откат» — возврат API в исходное состояние, чтобы тесты не загаживали данные |
| Отчёт без pytest | Движок сам собирает результат в понятный markdown-отчёт |
| Работает с локальной LLM | Безоблачно, данные не уходят наружу |
| Переиспользует общую библиотеку | Общий LLM-клиент, оценщик условий, чтение контрактов — из `ohw-kit`, ничего не изобретаем заново |

## Роль в ДЗ3

- **`../simple`** — учебный вариант «для самых маленьких»: нейросеть пишет
  pytest-код, и он запускается. Простой и явный, но требователен к
  надёжности сгенерированного кода.
- **`advanced` (этот проект)** — эволюция идеи: нейросеть проектирует план
  данных, а исполняет его надёжное ядро. Более устойчиво и масштабируемо.

## Куда двигаемся

Раз план — это структурированные данные, его легко расширять: подключать
дополнительные источники требований (RAG), динамически выбирать формат схемы,
добавлять новые версии контракта без переделки ядра.
