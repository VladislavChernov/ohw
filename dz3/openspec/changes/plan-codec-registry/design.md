# Design: PlanCodec — много версий JSON-плана через реестр кодеков

## Проблема, которую лечим

Сейчас «версия формата» в `plan.py` — это не абстракция, а четыре разрозненных
привязки, которые при смене структуры надо менять **вместе и не забыть**:

| Сегодняшняя привязка | Роль | Строка в `plan.py` |
|---|---|---|
| `SCHEMA_VERSION = "v3"` | идентичность версии (промпт, отчёт) | `:21` |
| `_SCHEMA = .../plan_schema/v3.json` | файл схемы | `:20` |
| `TestPlan/.../from_dict` | приведение JSON → модель | `:35..:180` |
| `validate_plan_schema` | структурная валидация | `:276` |

При смене формы надо править все четыре + `input/prompt.txt`. С несколькими
активными версиями это несовместимо с «выбором на лету» (РАГ / требования
аналитиков).

## Целевая архитектура

```
raw JSON-план (с полем version или сигнатурой структуры)
      │
      ▼
get_codec(version?, raw)  ── выбирает PlanCodec по реестру
      │
      ├─ PlanCodecV3 ── decode ──► TestPlan (единая внутренняя модель)
      └─ PlanCodecV4 ── decode ──► TestPlan        (будущее)
                          │  validate ──► ValidationResult
                          │  matches ──► bool (детект версии)
                          │  schema_file ──► Path (JSON-схема версии)
```

Ядро (`core`), валидатор покрытия (`validate_plan`), отчёт, `docs` работают
**только с `TestPlan`** и не знают, из какой версии он пришёл. Это ровно тот
инвариант, который и делает замену версии «добавь ещё один кодек».

## Контракт PlanCodec

```python
class PlanCodec(Protocol):
    version: str                      # "v3"
    schema_file: Path                 # ../plan_schema/v3.json
    def matches(self, raw: object) -> bool: ...
    def decode(self, raw: object, *, doc_mode: str = "unknown") -> TestPlan: ...
    def validate(self, raw: object) -> ValidationResult: ...
```

- `matches` — детект «это моя версия»: по полю `version` в плане, при
  отсутствии — по сигнатуре структуры (v3: `service`+`tests`, и плоская v1
  `request`/`expect` на тесте, которую v3-кодек нормализует как раньше).
- `decode` — перевод «формат → модель»; вся структура-специфичная логика
  (парсинг, нормализация плоской формы) живёт ТОЛЬКО здесь.
- `validate` — структурная валидация именно этой версии (экс-`validate_plan_schema`).

## Реестр

```python
_DEFAULT_VERSION = "v3"
_REGISTRY: dict[str, PlanCodec] = {"v3": PlanCodecV3()}

def get_codec(version: str | None, raw: object) -> PlanCodec:
    v = version or _plan_version_hint(raw) or _DEFAULT_VERSION
    try:
        return _REGISTRY[v]
    except KeyError:
        raise ValueError(f"unknown plan schema version: {v}") from None
```

- `version` на верхнем уровне плана (например `"version": "v4"`) — явный
  признак; при его отсутствии — детект по структуре, иначе default.
- Неизвестная версия → **жёсткая ошибка**, не тихий fallback (чтобы
  промпт ↔ ядро ↔ схема не расходились молча).

## Изменение поведения — НЕТ

Это **чистый рефакторинг** с выделением структуры. Никакие ключи, значения,
нормализации и сообщения ошибок не меняются. `PlanCodecV3` переносит текущую
логику `v3` без изменений. Поэтому существующие 39 тестов должны остаться
зелёными без правок; новые тесты проверяют только сам реестр и паритет.

## Что остаётся вне codec'а (осознанно)

- **`input/prompt.txt`** — человекочитаемая инструкция модели под конкретную
  версию. Это НЕ код и НЕ сможет быть в codec'е. При смене версии его
  переписывают всегда — codec лишь делает так, чтобы это была ЕДИНСТВЕННАЯ
  обязательная ручная правка при смене структуры (а не одна из пяти).
- **Семантический валидатор** `validate_plan(plan, required_resources)` —
  покрытие/cleanup/переменные — работает над `TestPlan` и потому версия-агностичен.
  Это никуда не переносим: он относится к *модели*, а не к *формату*.
- **`ohw-kit`** — не трогаем. `ValidationResult` и т.п. используются как есть;
  PlanCodec — домашне-специфичный слой advanced, в кит его не поднимаем
  (это выходной контракт домашки, у kit его фиксировать незачем).

## Инвентарь замены на будущее («что трогать при v4»)

| Что меняем | Без PlanCodec | С PlanCodec |
|---|---|---|
| Схема-файл `v4.json` | ✅ | ✅ |
| Идентичность версии | `SCHEMA_VERSION` (код) | сам кодек `version` |
| Парсер формата | `TestPlan/...from_dict` (ядро!) | изолирован в `PlanCodecV4.decode` |
| Структ. валидация | `validate_plan_schema` (ядро) | изолирована в `PlanCodecV4.validate` |
| Регистрация | — | `_REGISTRY["v4"] = PlanCodecV4()` |
| core / отчёт / валидатор покрытия | не трогаем | не трогаем |
| `input/prompt.txt` | переписать | переписать (единственная неизбежная) |
| Обратная совместимость v3 | ручное ветвление в ядре | бесплатна (оба кодекa в реестре) |

## Отклонённые альтернативы

- **`--schema-file` (рантайм-подмена схемы пользовательским JSON)** —
  антипаттерн: ядро/парсер/prompt устроены под конкретные ключи; рантайм-подмена
  разъедает все три сайта истины и рвёт типобезопасность. Отвергнуто.
- **Свободная форма с произвольными ключами без версии** — недетерминировано,
  ломает feedback-луп и отчёт. Отвергнуто.
- **Ветвление `if version=="v3": ... elif "v4"` прямо в парсере** — расползание
  логики версий по ядру, противоположно цели. Отвергнуто.
