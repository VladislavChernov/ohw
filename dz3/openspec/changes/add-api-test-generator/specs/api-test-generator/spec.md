# Delta Spec: api-test-generator (простой вариант)

## ADDED Requirements

### Requirement: Локальный LLM-сервис (Ollama)

Программа ДОЛЖНА использовать общий ollama-сервис из `infra/` монорепо
(shared `ohw-ollama`). Адрес и модель берутся из `.env`
(`OLLAMA_BASE_URL=http://host.docker.internal:11434`, `OLLAMA_MODEL`).
Для изолированного запуска доступен `--profile standalone` (per-project
ollama-контейнер с общим volume `ohw_ollama_models`).

#### Scenario: Shared ollama запущена

- **WHEN** `docker compose -f infra/compose.yaml up -d` выполнен, модель скачана
- **THEN** программа подключается по `OLLAMA_BASE_URL` и может отправить промпт

#### Scenario: Shared ollama недоступна

- **WHEN** `ohw-ollama` не запущен или не отвечает
- **THEN** программа завершается с ошибкой и сообщением о недоступности

### Requirement: Парсинг Swagger-спецификации целевого сервиса

Программа ДОЛЖНА загружать Swagger/OpenAPI-спецификацию целевого сервиса
(https://jsonplaceholder.typicode.com) и извлекать из неё перечень
эндпоинтов с описанием: HTTP-метод, путь, тело запроса, коды ответов,
схема/структура ответа.

#### Scenario: Спецификация успешно загружена

- **WHEN** программа обращается к JSONPlaceholder и получает OpenAPI-спеку
- **THEN** из неё извлекается список эндпоинтов с их описанием

#### Scenario: Спецификация недоступна

- **WHEN** JSONPlaceholder не отвечает или формат спецификации неожиданный
- **THEN** программа завершается с ошибкой и сообщением о причине

### Requirement: Формирование промпта для генерации тестов

Программа ДОЛЖНА собрать промпт, содержащий:
а) описание API-сервиса (URL, перечень эндпоинтов из Swagger с описанием
методов, тел и кодов ответов);
б) задание: сгенерировать 4 pytest-теста — по одному на каждый тип CRUD-
операции (создание ресурса, получение ресурса, изменение ресурса,
удаление ресурса);
в) требование: модель САМА выбирает подходящие эндпоинты для каждого
типа операции из описания;
г) требование: каждый тест ДОЛЖЕН проверять не только статус-код, но и
тело ответа (наличие ключевых полей, корректность данных).

#### Scenario: Промпт отправлен модели

- **WHEN** Swagger-спека загружена и промпт собран
- **THEN** промпт передаётся в Ollama для генерации

### Requirement: Генерация кода pytest-автотестов

Модель ДОЛЖНА сгенерировать Python-файл с 4 тестовыми функциями
(pytest-формат), каждая из которых:
- использует библиотеку `requests` для HTTP-запросов к JSONPlaceholder;
- выполняет один CRUD-тип операции (POST/GET/PUT/DELETE);
- проверяет статус-код ответа;
- проверяет тело ответа (наличие ключевых полей, корректность типов/данных).

#### Scenario: Модель вернула корректный код

- **WHEN** модель сгенерировала код с 4 тестовыми функциями на стеке
  Python 3 + Pytest + Requests
- **THEN** код сохраняется в файл и запускается через `pytest`

#### Scenario: Модель вернула некорректный код

- **WHEN** сгенерированный код содержит синтаксические ошибки или не
  соответствует стеку (не pytest, не requests)
- **THEN** программа повторяет запрос (не более --max-retries попыток)
  с указанием на ошибку; после исчерпания попыток — завершается с ошибкой

### Requirement: Запуск и проверка тестов

Программа ДОЛЖНА запустить сгенерированные тесты через `pytest` и отчитаться
о результате: сколько тестов прошло, сколько упало, ошибки (если есть).

#### Scenario: Все 4 теста прошли

- **WHEN** pytest завершился успешно, все 4 теста зелёные
- **THEN** программа выводит сообщение об успехе с указанием количества

#### Scenario: Есть упавшие тесты

- **WHEN** pytest завершился, но часть тестов упала
- **THEN** программа выводит отчёт pytest (какие упали, почему) и код
  возврата ненулевой

### Requirement: Выходной артефакт

Программа ДОЛЖНА сохранить сгенерированный pytest-файл в выходную папку
(`--output-dir`, по умолчанию `./output`).

#### Scenario: Файл создан

- **WHEN** генерация и запуск завершены
- **THEN** в `--output-dir` появляется pytest-файл (например, `test_generated.py`)
  с 4 тестовыми функциями

### Requirement: Dev Container для разработки

Проект ДОЛЖЕН содержать конфигурацию VS Code Dev Container с Python
актуальной версии, установленным uv и доступом к Docker для
интеграционных проверок.

#### Scenario: Открытие проекта в VS Code

- **WHEN** разработчик открывает проект через «Reopen in Container»
- **THEN** окружение готово к работе после `uv sync --dev`

## ADDED Requirements (Advanced)

### Requirement: JSON-описание тестов от LLM

Модель ДОЛЖНА вернуть JSON-массив тестов, где каждый тест содержит:
эндпоинт (URL), HTTP-метод, данные для запроса. Формат — открытый вопрос
(обсуждается отдельно).

#### Scenario: Модель вернула корректный JSON

- **WHEN** модель вернула JSON-массив с тестами
- **THEN** движок парсит его и формирует HTTP-запросы

#### Scenario: Модель вернула некорректный JSON

- **WHEN** ответ модели — не JSON или не соответствует ожидаемому формату
- **THEN** программа повторяет запрос (до --max-retries) или завершается с ошибкой

### Requirement: Движок выполнения тестов

Программа ДОЛЖНА содержать движок, который принимает JSON-описание тестов
и выполняет CRUD-запросы к целевому API. Движок проверяет ответы:
статус-код, тело ответа (наличие ключевых полей, корректность данных).

#### Scenario: Движок выполнил все тесты

- **WHEN** JSON содержит 4 теста (CRUD), API доступен
- **THEN** движок выполняет все запросы и формирует отчёт

#### Scenario: API недоступен

- **WHEN** целевой API не отвечает
- **THEN** движок отмечает все тесты как упавшие с причиной «connection error»

### Requirement: Отчёт advanced-варианта

Программа ДОЛЖНА вывести отчёт: для каждого теста — статус (прошёл/упал),
статус-код ответа, время ответа, при необходимости — тело запроса/ответа.

#### Scenario: Отчёт выведен

- **WHEN** движок завершил выполнение
- **THEN** в консоль/файл выводится отчёт с результатами по каждому тесту
