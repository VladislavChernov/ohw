# Delta Spec: request-engine

## ADDED Requirements

### Requirement: Чтение файлов запросов из входной папки

Программа ДОЛЖНА читать файлы запросов из входной папки (`--input-dir`, по
умолчанию `./input`, в контейнере `/data/input`) и считать входными файлами
только файлы с расширением `.md` или `.txt`. Пути к отдельным файлам вручную
не указываются.

#### Scenario: Значения по умолчанию

- **WHEN** пользователь запускает `llm-engine` в каталоге проекта
- **THEN** программа читает файлы из `./input`

#### Scenario: Поддерживаемые расширения

- **WHEN** во входной папке рядом с `a.md` и `b.txt` лежит `notes.pdf`
- **THEN** файл `notes.pdf` пропускается, а `a.md` и `b.txt` обрабатываются

#### Scenario: Входная папка отсутствует или пуста

- **WHEN** каталог `--input-dir` не существует или не содержит файлов .md/.txt
- **THEN** программа завершается с кодом 2 и понятным сообщением об ошибке

### Requirement: Разрешение коллизий имён входных файлов

Если во входной папке обнаружены файлы с одинаковым именем, но разными
поддерживаемыми расширениями (например, `auth.md` и `auth.txt`), программа
ОБЯЗАНА завершиться с ошибкой, не выполняя генерацию: такие файлы претендуют
на один и тот же выходной документ.

#### Scenario: Дубли имени с разными расширениями

- **WHEN** входная папка содержит одновременно `auth.md` и `auth.txt`
- **THEN** программа завершается с кодом 2 и перечисляет конфликтующие файлы,
  предлагая удалить или переименовать один из них

### Requirement: Пакетная обработка файлов запросов

Программа ДОЛЖНА обрабатывать каждый файл из входной папки как отдельный
независимый запрос к модели. Успешный или неуспешный результат одного файла
не влияет на обработку остальных файлов пакета.

#### Scenario: Три файла во входной папке

- **WHEN** входная папка содержит `auth.md`, `cart.txt`, `search.md`
  и все запросы к модели успешны
- **THEN** в выходной папке появляются `auth.md`, `cart.md`, `search.md`

#### Scenario: Ошибка обработки одного файла

- **WHEN** для файла `auth.md` все попытки к модели не удались, а остальные
  файлы обработаны успешно
- **THEN** по `auth.md` выходной документ не создаётся, при этом выходные
  документы по `cart.txt` и `search.md` присутствуют, а программа сообщает
  об ошибке по `auth.md`

### Requirement: Отправка запроса локальной модели через ollama

Программа ДОЛЖНА подключаться по HTTP к локальному ollama-сервису (адрес —
переменная окружения `OLLAMA_BASE_URL`, по умолчанию `http://localhost:11434`,
внутри compose — `http://ollama:11434`) и отправлять содержимое входного файла
как запрос к модели, заданной переменной окружения `OLLAMA_MODEL`.

#### Scenario: Успешный ответ модели

- **WHEN** ollama доступна и модель отвечает
- **THEN** программа получает текст ответа модели и считает файл обработанным

#### Scenario: Ollama недоступна

- **WHEN** сервис по `OLLAMA_BASE_URL` недоступен (сеть или HTTP-ошибка)
- **THEN** программа завершается с кодом 3 и сообщением о недоступности сервиса

#### Scenario: Модель не задана

- **WHEN** `OLLAMA_MODEL` не задана и не указана в конфигурационном файле
- **THEN** программа завершается с кодом 2 и сообщением об отсутствии модели,
  не обращаясь к ollama

### Requirement: Повторные попытки при пустом ответе

Если модель вернула пустой ответ, программа ДОЛЖНА повторить запрос (не более
`--max-retries`, по умолчанию 3) с тем же содержимым файла.

#### Scenario: Пустой ответ и попытки не исчерпаны

- **WHEN** модель вернула пустой ответ и число попыток меньше `max-retries + 1`
- **THEN** программа выполняет повторный запрос

#### Scenario: Пустой ответ и попытки исчерпаны

- **WHEN** после всех попыток ответ модели остаётся пустым
- **THEN** файл считается необработанным, программа переходит к следующему файлу

### Requirement: Выходной markdown-документ

Программа ДОЛЖНА записывать ответ модели по каждому обработанному файлу в
отдельный markdown-документ в выходной папке (`--output-dir`, по умолчанию
`./output`, в контейнере `/data/output`): `<имя исходного файла>.md`.
Выходная папка создаётся автоматически; существующие документы
перезаписываются.

#### Scenario: Успешная запись результата

- **WHEN** получен непустой ответ модели по файлу `summary.txt`
- **THEN** выходной документ создаётся как `<output-dir>/summary.md`
  и содержит ответ модели

#### Scenario: Перезапись существующего документа

- **WHEN** выходной документ с тем же именем уже существует
- **THEN** программа перезаписывает его новым содержимым

### Requirement: Конфигурирование через файл и переменные окружения

Программа ДОЛЖНА читать параметры из конфигурационного файла `light-llm-engine.toml`
(расположение — текущий каталог или `--config <path>`) и переменных окружения
`OLLAMA_*`. Приоритет, от низшего к высшему: значения по умолчанию, файл
конфигурации, переменные окружения, аргументы CLI. Отсутствие файла ошибкой
не считается.

#### Scenario: Параметры заданы в TOML

- **WHEN** в `light-llm-engine.toml` заданы `base_url`, `model`, `temperature`
- **THEN** программа использует эти значения, если они не переопределены
  env или CLI

#### Scenario: Битый конфигурационный файл

- **WHEN** файл конфигурации существует, но содержит невалидный TOML
- **THEN** программа завершается с кодом 2 и сообщением об ошибке
