# Proposal: запуск обоих контейнеров через Docker Compose (самодостаточный проект)

## Зачем

Ручной `docker run` для приложения плюс отдельно созданный ollama-контейнер —
два несвязанных шага с дублированием флагов. Нужна одна команда, поднимающая
весь стек, чтобы проект можно было склонировать и запустить на любой машине
с NVIDIA GPU без ручных шагов.

## Что делаем

- `compose.yaml`:
  - сервис `ollama` — GPU через device reservations; entrypoint сам
    поднимает `ollama serve` и докачивает модель из `OLLAMA_MODEL`, если её
    нет в volume (идемпотентно); healthcheck = наличие модели
    (`ollama show`), т.е. приложение стартует только когда модель реально
    готова; порт 11434 наружу;
  - volume моделей — локальный именованный `ollama_models`
    (`dz2_ollama_models`), проект ни от чего внешнего не зависит;
    на машине автора данные мигрированы из старого volume копированием;
  - сервис `app` — сборка из Dockerfile, дефолтная команда `--count 10`,
    монтирование `./input` и `./output`;
- `.env` c `OLLAMA_MODEL=qwen2.5:7b-instruct` — единая точка смены модели;
- `./input` добавлен в `.gitignore` как рабочий каталог пользователя.
- Приложение ходит на ollama по внутренней сети compose: `http://ollama:11434`
  (env-слой конфигурации перекрывает дефолт `host.docker.internal`).

## Спека

Изменений требований к поведению CLI нет — это change уровня развёртывания,
дельта спеки не пишется. README дополнен секцией «Запуск через Docker Compose».

## Проверка

- `docker compose up -d ollama` → healthy, внутри контейнера CUDA
  (RTX 2070 SUPER), генерация 2×10 кейсов в `./output`.
- Свежий volume (имитация клона репозитория, `-p dz2pulltest` +
  `OLLAMA_MODEL=smollm2:360m`) → модель скачалась автоматически за ~40 c.
- Отказ от отдельного init-сервиса: его успешный exit 0 ронял стек через
  `--abort-on-container-exit`; pull встроен в entrypoint ollama.

## Дополнение: платформенные профили GPU

Изначальная резервация `driver: nvidia` в базовом compose ломала запуск
везде, где CUDA недоступен (macOS не пробрасывает GPU в контейнеры
принципиально; AMD в Docker живёт только на Linux через ROCm). Схема
пересобрана: базовый `compose.yaml` универсален (CPU), GPU подключается
override-файлами:

- `compose.gpu.yaml` — NVIDIA/CUDA (резервация всех устройств);
- `compose.amd.yaml` — AMD/ROCm: образ `ollama/ollama:rocm`, устройства
  `/dev/kfd` и `/dev/dri`, группы `video`/`render`;
- без override — CPU, работает на любой машине.

Проверено на машине автора: рендер всех трёх комбинаций (`compose config`);
CPU-стек поднимается и отвечает (`library=cpu`, короткий чат qwen);
после возврата на GPU — `library=CUDA`, полная генерация по всем шести
BR-входам; volume моделей пересоздан с корректными метками проекта.
