# Proposal: настройки нормализатора отдельным файлом и в UI

## Почему

Параметры канонического вида требований были захардкожены в
`ai_testgen/normalizer.py`: префикс `BR`, заголовок `## Requirements`, подпись
`**URL:**`, запасной заголовок `Требования`, список кодировок `cp1251/cp866`
и порог абзаца 20 символов. Из-за этого:

- в проекте с другим соглашением об ID (`REQ-1`, `FR-3`) нормализатор выдаёт
  неподходящие идентификаторы, и матрица покрытия ссылается на несуществующие
  требования;
- требования на русском нельзя оформить с заголовком `## Требования`;
- выгрузки в `koi8-r` не открываются, хотя декодер уже умеет работать со
  списком кодеков;
- порог «абзац — это требование» нельзя подстроить под конкретный документ,
  не правя код.

При этом настройки нормализации меняются по другому поводу, чем модель или
каталоги, поэтому держать их в общем `ai-testgen.toml` неудобно: файл читают
и CLI, и рабочее место, а правит его человек, который занимается только
требованиями.

## Что делаем

- **Отдельный файл** `dz2/normalizer.toml` (плоский TOML, без секций) с
  комментариями к каждому ключу.
- **Загрузчик** `normalizer.load_settings()`: порядок поиска
  `--normalizer-config` → `AI_TESTGEN_NORMALIZER_CONFIG` → `./normalizer.toml`
  → встроенные значения. Неизвестные ключи не ломают запуск.
- **`NormalizerSettings`**: `id_prefix`, `requirements_heading`, `url_label`,
  `fallback_title`, `encodings`, `paragraph_min_length`. Валидация в
  `__post_init__`, отдельная ошибка `NormalizerSettingsError`.
- **Прокидывание настроек**: `normalize_text`, `normalize_bytes`,
  `decode_bytes`, `load_docs(..., settings=...)`, CLI-флаг
  `--normalizer-config` (ошибка конфигурации — код 2).
- **UI**: раскрывающийся блок «Настройки нормализации» над кнопкой
  «Нормализовать» — те же шесть параметров, кнопка «Вернуть значения из
  файла», область действия — сессия. Смена настроек после нормализации
  помечает результат устаревшим (сравнение по значению `NormalizerSettings`).
- **Docker**: `normalizer.toml` копируется в образ и монтируется в оба сервиса;
  образ выставляет `AI_TESTGEN_NORMALIZER_CONFIG=/app/normalizer.toml`, потому
  что рабочий каталог контейнера — `/data`. Правка на хосте видна без
  пересборки.
- **Документация**: `dz2/NORMALIZER-SETTINGS.md` — глоссарий по каждому
  параметру, порядок поиска, влияние на промпт, типовые ошибки и рецепты;
  ссылки из `dz2/README.md` и `dz7/docs/NORMALIZER.md`.

## Совместимость

Значения по умолчанию совпадают с прежним хардкодом, поэтому существующие
документы нормализуются байт-в-байт как раньше: e2e-артефакты и их
`prompt_sha256` не меняются. Порядок стратегий извлечения остаётся
фиксированным — это ограничение задокументировано.

## Проверка

- `tests/test_normalizer.py`: файл настроек меняет префикс, заголовки и
  подписи; идемпотентность с нестандартными настройками; порог абзаца;
  кодеки; валидация и предупреждение о неизвестных ключах.
- `tests/test_cli_normalize.py`: `--normalizer-config`, автопоиск
  `normalizer.toml` в рабочей директории, коды возврата 2 на отсутствующий и
  битый файл.
- `tests/test_ui_app.py`: виджет префикса меняет `### REQ-1` в промпте; файл
  задаёт значения по умолчанию для виджетов.
- Полный прогон в Docker: `pytest`, `mypy`, `ruff`.
