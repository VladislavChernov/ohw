# Proposal: типы артефактов и форматы ответа (JSON / markdown)

## Зачем

Запрос пользователя включает три сущности: тест-кейсы, чек-лист и
тест-план. Сейчас утилита генерирует только тест-кейсы, жёстко требуя
JSON. Документы (чек-лист, план) — это связный markdown; гонять их через
JSON-схему неестественно и ломает маленькие модели. Нужен формат ответа,
привязанный к типу артефакта: JSON там, где нужна машинная проверка
полей, markdown — где нужен документ; и валидация своего формата для
каждого случая.

## Что делаем

- Тип артефакта объявляется во front-matter входного файла:

  ```
  ---
  type: checklist
  ---
  ```

  Значения: `testcases`, `checklist`, `testplan`; без front-matter —
  `testcases` (обратная совместимость); неизвестный тип или битый блок —
  exit 2.
- Формат ответа — атрибут типа:

  | Тип | Формат | Валидатор |
  |---|---|---|
  | `testcases` | JSON `{"cases": [...]}` | существующий: pydantic + ограничения набора |
  | `checklist` | markdown-документ | структурный линт markdown |
  | `testplan` | markdown-документ | структурный линт markdown |

- Валидатор выбирается по типу (реестр хендлеров):
  - для JSON — текущая логика без изменений;
  - для markdown — линт: срезаются возможные ограждения кода
    (\`\`\`), ответ не должен быть JSON-ом, обязательные заголовки
    разделов присутствуют и непусты, у каждой зоны чек-листа есть
    пункты списка.
- Промпт на тип: для markdown-типов точно перечисляет обязательные
  заголовки разделов (те же строки, что проверяет линт) и запрещает
  ограждения кода.
- Клиент ollama: флаг `format="json"` отправляется ТОЛЬКО для
  JSON-типов; для markdown-типов ответ свободный.
- Retry-цикл общий: issues от любого валидатора уходят в повторную
  попытку; после исчерпания — exit 4.
- Рендер: отчёт `<stem>.md`; для markdown-типов тело документа
  переносится в отчёт под общей шапкой (сводка: тип артефакта);
  `--count` значим только для `testcases`.

## Спека

Дельта в capability `testcase-generator`: требования «Объявление типа»,
«Формат ответа по типу», «Генерация чек-листа», «Генерация тест-плана»;
изменено требование про применение `--count`.

## Проверка

- Unit: парсер front-matter; линтеры markdown (ограждения, JSON-ответ,
  отсутствующий/пустой раздел, пустая зона чек-листа); выбор формата
  в реестре; клиент не шлёт `format="json"` для markdown-типов.
- CLI: смешанный батч из трёх типов → три отчёта; битый тип → exit 2.
- Интеграционно: живая модель по всем шести входам из `./input`.
