# Дельта спеки: testcase-generator

## ADDED Requirements

### Requirement: Объявление типа входного файла

Входной файл МОЖЕТ содержать front-matter с полем `type`.

- Система SHALL распознавать блок front-matter как строки между двумя
  разделителями `---` в начале файла и читать из него только поле `type`.
- Система SHALL принимать значения `testcases`, `checklist`, `testplan`.
- **WHEN** front-matter отсутствует, система SHALL считать тип файла
  равным `testcases`.
- **WHEN** значение `type` неизвестно или блок front-matter некорректен,
  система SHALL завершиться с кодом 2, не обращаясь к ollama.

### Requirement: Формат ответа по типу артефакта

Формат ответа модели определяется типом артефакта.

- Система SHALL требовать от модели JSON для типа `testcases` и SHALL
  применять к ответу JSON-валидацию (схема кейса и ограничения набора).
- Система SHALL требовать от модели markdown для типов `checklist` и
  `testplan` и SHALL НЕ отправлять параметр `format="json"` в запросе.
- Система SHALL выбирать валидатор по типу артефакта; ответы других
  форматов SHALL порождать issue для повторной попытки.

### Requirement: Валидация markdown-документа

Markdown-ответ проверяется структурным линтом.

- Система SHALL срезать ограждения кода (```` ``` ````) вокруг ответа
  перед проверкой.
- **WHEN** markdown-ответ является корректным JSON, система SHALL
  зафиксировать issue «ответ в формате JSON вместо markdown».
- Система SHALL проверить наличие каждого обязательного заголовка
  раздела, перечисленного в промпте этого типа, и непустое содержимое
  под ним; отсутствие или пустота — issue с именем раздела.
- Для чек-листа система SHALL требовать минимум один пункт списка под
  каждой зоной.

### Requirement: Генерация чек-листа

**WHEN** входной файл имеет тип `checklist`, система SHALL запросить
чек-лист как markdown-документ: заголовок-зона и пункты проверок под ней,
по зонам, указанным во входном файле.

### Requirement: Генерация тест-плана

**WHEN** входной файл имеет тип `testplan`, система SHALL запросить
тест-план как markdown-документ с фиксированными разделами: цели
тестирования, объём тестирования, подход и виды тестирования, критерии
начала и окончания, риски.

## MODIFIED Requirements

### Requirement: Применение count

`--count` применяется к каждому входному файлу типа `testcases`.

- Система SHALL требовать валидное количество кейсов только для файлов
  типа `testcases`.
- **WHEN** батч содержит файлы других типов, система SHALL игнорировать
  `--count` для них без ошибки.
