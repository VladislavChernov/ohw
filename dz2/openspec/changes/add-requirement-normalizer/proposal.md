# Proposal: детерминированная нормализация требований

## Почему

Требования приходят из разных источников: страницы otus.ru, таблицы, протоколы
встреч, текст без разметки. Контракт генератора при этом жёсткий:

- правило трассировки включается только при наличии `BR-N`
  (`prompt._requirement_rule`), иначе тест-кейсы остаются без поля
  `requirement`, а чек-лист, тест-план и матрица покрытия — без ссылок на
  требования;
- матрица покрытия строится по строкам «одно требование — одна строка», и без
  `BR-N` ей не на что ссылаться;
- оценка качества привязывает артефакт к файлу, но не к требованию.

При этом Dz2 читает входные файлы только как UTF-8 (`input_doc.load_docs`), а
реальные выгрузки бывают в cp1251 и cp866: UI просто отказывается открывать
такой файл. Ручная разметка `BR-ID` даёт дубли, пропуски в нумерации и разный
формат у разных людей.

В ветке `normalizer` эта возможность была заявлена в корневом README, но кода
не было: только битый файл `dz7/docs/NORMALIZER.md` (CP866), пустой
`dz7/docs/optnspec/format.txt` и устаревшее `dz7/review.md`. Этот бандл
заменяет заявку реализацией.

## Что делаем

- **Модуль `ai_testgen/normalizer.py`** — чистые детерминированные функции без
  обращений к LLM: декодирование, извлечение URL/заголовка/требований, сборка
  канонического документа.
- **Определение кодировки**: BOM (UTF-8/UTF-16/UTF-32), затем строгий UTF-8,
  затем cp1251/cp866 с эвристикой по доле кириллицы. Результат сообщает
  определённую кодировку.
- **Стратегии извлечения в фиксированном приоритете**: заголовки `BR-N` →
  Markdown-таблица с колонкой ID → список под разделом «Требования» → строки
  `BR-N:` → абзацы (с явным предупреждением, что структура не распознана).
- **Стабильные идентификаторы**: существующие `BR-N` сохраняются, отсутствующим
  выдаются следующие свободные номера; дубли отбрасываются с предупреждением.
- **Канонический документ**: `# <заголовок>`, `**URL:** …`, вступление,
  `## Requirements`, далее `### BR-N` с текстом требования. Повторная
  нормализация не меняет результат (идемпотентность).
- **CLI**: `--normalize` (нормализовать входные файлы перед сборкой промпта),
  `--normalize-only` (только записать нормализованные файлы и выйти, без
  модели), `--normalized-dir` (по умолчанию `<output>/normalized`). В режиме
  `--normalize-only` аргумент `-n` не обязателен.
- **Загрузка входных файлов**: `load_docs(..., normalize=True)` декодирует с
  определением кодировки; строгий UTF-8 остаётся поведением по умолчанию.
- **Рабочее место**: на вкладке «Требования» — блок нормализации с кодировкой,
  числом найденных требований, предупреждениями, предпросмотром «исходный /
  нормализованный», скачиванием и переключателем «использовать нормализованный
  текст в промптах».
- **Документация**: `dz7/docs/NORMALIZER.md` переписан в UTF-8 и описывает
  формат и правила; обновлены `dz2/README.md`, `dz7/README.md` и корневой
  README. Удаляются устаревшее `dz7/review.md` и пустой
  `dz7/docs/optnspec/format.txt`.
- **Попутно**: флаг `--timeout` (появился в ветке без покрытия) получает тест и
  строку в таблице CLI.

## Спека

Дельта capability `testcase-generator`:

`ADDED` — нормализация требований (декодирование, канонический формат,
стабильные идентификаторы, предупреждения, детерминизм и идемпотентность),
флаги `--normalize`/`--normalize-only`/`--normalized-dir`, шаг нормализации в
рабочем месте.

`MODIFIED` — загрузка входных файлов (не-UTF-8 при `--normalize` не ошибка, а
определённая кодировка; в UI кодировка показывается, а не скрывается),
поверхность CLI (`--timeout`).

## Проверка

- `uv run pytest -m "not integration"`, `uv run mypy src tests`,
  `uv run ruff check .`; отдельный модуль тестов `tests/test_normalizer.py`.
- `uv run ai-testgen --normalize-only --input-dir docs --output-dir output` —
  код 0 без запущенной модели, файлы в `output/normalized/`.
- `uv run ai-testgen -n 5 --normalize` — в отправленном промпте есть
  `## Requirements` и `### BR-N`.
- Повторная нормализация уже нормализованного файла не меняет содержимое.
- UI: загрузить документ без BR-ID и файл в cp1251 — блок нормализации
  показывает кодировку, найденные требования и предупреждения; с включённым
  переключателем промпт содержит `BR-N`.

## Связанные бандлы

`workbench-and-presets` — рабочее место и общее ядро;
`dz7/openspec/changes/prompt-generator` — контракт шаблонов и правило `BR-N`.
Дельта уточняет их поведение на входе и не заменяет их требования.
