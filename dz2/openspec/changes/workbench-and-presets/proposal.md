# Proposal: пресеты, рабочее место и единое ядро генерации

## Почему

Dz2 умеет генерировать пять артефактов по внешним шаблонам, но пользоваться
им неудобно:

- требования лежат в `input/`, хотя настоящий источник — рабочий документ
  `docs/business-requirements_catalog-courses.md`; новичок запускает
  `ai-testgen -n 10` и получает ошибку «нет входных файлов»;
- тип артефакта задаётся только front-matter: чтобы получить чек-лист,
  приходится править файл требований или заводить его копию;
- «хочу те же кейсы, но с граничными значениями» решается копированием
  шаблона: тематические дополнения не переиспользуются;
- промпт нельзя посмотреть перед отправкой и поправить под задачу;
- доработать готовый артефакт можно только повторной генерацией с нуля;
- оценка качества промптов ДЗ7 собирается вручную, без фиксации того, какой
  промпт и какая модель дали результат.

## Что делаем

- **`docs/` — источник по умолчанию** в Dz2 (`input_dir = "docs"`),
  Dz7 читает `../dz2/docs`. `input/` остаётся для батч-зеркал.
- **Явный тип артефакта**: `--type <type>` и `--all-types`. При явном типе
  файлы пишутся как `<stem>.<type>.md`, чтобы не затирать соседние типы;
  front-matter по-прежнему работает.
- **Пресеты** — TOML-файлы с тематическими инструкциями (граничные значения,
  негативные сценарии, доступность, валидация, регрессия, локализация).
  Подставляются в новый плейсхолдер `{extra}`; `types` ограничивает
  применимость; выбор пресета для неподходящего типа — ошибка, а не
  молчаливый пропуск. Источник правды — `dz7/presets`, копируется в
  `dz2/presets` через `--emit-presets`.
- **Общее ядро**: цикл «промпт → ollama → валидация → retry → рендер»
  вынесен в `service.generate_artifact`, CLI и UI вызывают его.
- **Streamlit-рабочее место** (`ai-testgen-ui`, extra `ui`): требования →
  промпт (с пресетами и правкой) → генерация → чат-доработка с явным
  «Применить как новую версию» → оценка по рубрике в
  `output/quality/<type>[-<preset>]-<run-id>.json`.
- **Docker**: образ от общего `ohw-python:3.13` с `ARG EXTRAS`; один образ
  `ohw/dz2:local` на CLI и UI, compose-сервис `ui` на порту 8501, `./docs`
  только на чтение, `./output` на запись; стенд-скрипты поднимают общий
  `ohw-ollama` (GPU-оверлей `infra/compose.gpu.yaml`).

## Спека

Дельта capability `testcase-generator`:
`ADDED` — источник `docs/`, `--type`/`--all-types`, пресеты и `{extra}`,
общее ядро генерации, рабочее место, рубрика качества, поставка UI в Docker;
`MODIFIED` — конфигурация (`presets_dir`), имена выходных файлов,
приоритеты поиска каталогов.

## Проверка

- `pytest -m "not integration"` (185 тестов), `mypy src tests`, `ruff check`.
- Dz7: `python3 -m unittest discover -s tests` (37 тестов).
- Синхронность `dz7/templates` ↔ `dz2/prompts` и `dz7/presets` ↔
  `dz2/presets` проверяется тестами по байтам.
- UI-тесты на Streamlit `AppTest` с подменённым клиентом Ollama.
- e2e: `docker compose up --build` (CLI) и `docker compose up ui` с общим
  Ollama; результаты — в `dz7/docs/prompt-quality.md`.

`{extra}` добавлена дельта, документация — `dz7/docs/workbench.md` и
`dz7/docs/prompt-quality.md`.
