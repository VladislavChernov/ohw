# Design: пресеты, рабочее место и общее ядро

## Поток данных

```
dz2/docs/<file>.md ──┐
                     ├─► prompt.py + presets.py ─► user prompt
dz7/templates/*.txt ─┘                                 │
                                                       ▼
                                        service.generate_artifact
                                       (ollama → validate → retry)
                                                       │
                                    ┌──────────────────┴────────────┐
                                    ▼                               ▼
                              cli.py (батч)                 ui/app.py (сессия)
                                    │                               │
                                    ▼                               ▼
                          output/<name>.md              output/*.md + quality/*.json
```

CLI и UI не дублируют логику: оба вызывают `generate_artifact`. UI
дополнительно принимает отредактированный промпт
(`user_prompt=...`), поэтому правка в интерфейсе доходит до модели без
пересборки шаблона.

## Пресеты

```
dz7/presets/<id>.toml ──(--emit-presets)──► dz2/presets/<id>.toml
                                              │
                         --preset / UI-multiselect
                                              ▼
                       select_extras(presets, ids, artifact_type)
                                              ▼
                              {extra} в шаблоне
```

Формат:

```toml
id = "boundary-values"           # обязан совпадать с именем файла
label = "Граничные значения"     # подпись в интерфейсе
types = ["testcases", "checklist"]
text = "Add boundary-value scenarios: ..."
```

- `types` по умолчанию — все пять типов; пустой список запрещён.
- Текст пресета нормализуется в одну строку на пункт: блок выглядит как
  ```
  Additional instructions:
  - <текст пресета 1>
  - <текст пресета 2>
  ```
- Без пресетов `{extra}` раскрывается в пустую строку — промпт совпадает с
  версией без пресетов (кроме схлопнутых пустых строк).
- Если шаблон не содержит `{extra}`, а пресет выбран — `PromptError`, код 2.

Решение: пресет — **данные, а не код**. Новый набор проверок добавляется
TOML-файлом без правки Python и без нового шаблона; один и тот же пресет
работает в CLI, UI и Docker.

Альтернативы, которые отклонили:

- отдельный шаблон на каждую комбинацию — комбинаторный взрыв;
- флаг `--with-boundary` в коде — правка кода на каждую тему;
- жёсткая привязка пресета к одному типу — теряется переиспользование.

## Тип артефакта и имена файлов

| Режим | Тип | Имя в `output/` |
|---|---|---|
| front-matter | из файла | `<stem>.md` |
| `--type X` | X | `<stem>.X.md` |
| `--all-types` | все пять | `<stem>.<type>.md` |

`--type` и `--all-types` взаимоисключающие (argparse group). Явный тип
отменяет front-matter для всех файлов — это предсказуемее, чем смешивать
источники.

## Общее ядро

`service.py`:

```python
@dataclass(frozen=True)
class GenerationOptions:   # count, temperature, max_retries
@dataclass(frozen=True)
class RetryNotice:         # attempt, total_attempts, issues
@dataclass(frozen=True)
class GeneratedArtifact:   # artifact_type, result, user_prompt, attempts
```

`generate_artifact(client, handler, doc, options, *, on_retry, user_prompt)`
— единственная точка цикла «запрос → валидация → retry». `on_retry`
позволяет CLI печатать в stderr, а UI — показывать предупреждения, не
дублируя цикл. Исчерпание попыток — `GenerationError`.

## Рабочее место

`ai_testgen/ui/app.py` (Streamlit, extra `ui`, entry point `ai-testgen-ui`).

| Вкладка | Состояние в `st.session_state` |
|---|---|
| Требования | `requirements_text`, `url_input`, `source_name`, подпись содержимого (sha256) |
| Промпт | `artifact_type`, `count`, `preset_ids`, `prompt_text` + подпись состава |
| Результат | `artifact` — последний применённый `GeneratedArtifact` |
| Чат | `chat_history`, `pending_revision` |
| Оценка | `llm_evaluation`, `score_*`, `quality_note` |

Подключение к модели — в боковой панели, и каждый параметр выбирается двумя
способами:

- адрес: готовые пресеты (`localhost`, `ohw-ollama`, `host.docker.internal`)
  или «Свой адрес»; пресет — ярлык, поле URL остаётся редактируемым;
- модель: список из `GET /api/tags` или ручной ввод имени.

Значения по умолчанию разрешаются как в CLI: `OLLAMA_BASE_URL` /
`OLLAMA_MODEL`, затем `ai-testgen.toml`. В контейнере это важно: конфига в
образе нет, и без env-приоритета UI показывал бы адрес хоста Docker Desktop
вместо `ohw-ollama`.

Смена адреса сбрасывает загруженный список моделей — он относится к прежнему
сервису.

Решения:

- **Требования — только загрузка файлов.** Как в `QA_RAG_Studio`, вкладка
  использует `st.file_uploader` (`.md`/`.txt`, несколько файлов); поля
  «каталог» нет, поэтому UI не зависит от того, что смонтировано в контейнер.
  Подпись — sha256 содержимого: текст перезаполняется только при смене файла,
  а ручная правка переживает перерисовку.
- **Промпт редактируемый.** Подпись состава (`файл|тип|count|пресеты`)
  пересобирает текст только при смене состава, поэтому ручная правка не
  теряется при перерисовке виджета.
- **Чат не меняет артефакт.** Ответ складывается в `pending_revision` и
  применяется кнопкой; перед применением проходит тот же валидатор, что и
  генерация. Иначе любая реплика модели становилась бы «документом» в обход
  проверок.
- **История версий** хранится списком в `versions`; отображается последняя.
- **Оценка — LLM-судья.** Отдельный запрос к той же модели видит текст
  промпта (не артефакт) и возвращает JSON 1–5 с комментариями; `temperature=0`
  делает повторные прогоны сравнимыми. Ручная правка остаётся, но помечается
  `source=human`, поэтому видно происхождение баллов. JSON, а не markdown:
  таблица в `dz7/docs/prompt-quality.md` собирается без ручного разбора.
  В имени файла — UTC-метка прогона (`<type>[-<preset>]-<run-id>.json`), иначе
  оценка второго документа того же типа затирала бы первую. В JSON пишется
  `generated_artifact` — относительный путь, sha256, размер и mtime
  оценённого артефакта: по хешу видно, что оценён именно этот файл, а не
  перезаписанный позже.
  Один вызов оценивает один критерий: первый вариант просил все четыре балла
  одним ответом и приводил заполненный пример — локальная 7B-модель вернула
  ровно примерные 3/4/4/3 на всех десяти промптах, то есть не оценивала их.
  Рубрика без числовых примеров это убирает; версия
  рубрики пишется в JSON (`judge_version`). Судья обязан сначала привести 3–5
  дословных цитат из промпта: цитаты проверяются на вхождение (допускаются
  различия в регистре и пунктуации, потому что 7B-модель добавляет кавычки),
  выдуманные отбрасываются, а ответ без единой реальной цитаты после трёх
  попыток считается ошибкой. Исключение — балл 1: отсутствующий элемент
  цитировать нечем, комментарий называет пропуск. В v4 отдельно сказано, что
  ссылка внутри блока
  требований — это тот же URL, а пресет с негативными сценариями учитывается в
  покрытии: иначе 7B-судья называл URL отсутствующим, цитируя его же как
  доказательство. Без
  этого шага 7B-модель писала «absent» вместо чтения и ставила 1 за читаемость
  всем промптам подряд.
- **Матрица покрытия зависит от тест-кейсов.** Это единственный артефакт со
  ссылками на другой: `--all-types` передаёт в её промпт список сгенерированных
  кейсов, одиночный запуск получает явное «кейсов ещё нет» и пишет `—`.
  Альтернатива — разрешить модели придумывать номера — уже давала матрицу с
  `TC-01…TC-14`, которых не существует.

## Docker

Образ проекта собирается от общего базового `ohw-python:3.13`
(`infra/python/`) и параметризуется extra-зависимостями:

```dockerfile
FROM ohw-python:3.13 AS builder
ARG EXTRAS=""
RUN uv sync --frozen --no-install-project --no-dev $EXTRAS
RUN uv sync --frozen --no-dev --no-editable $EXTRAS
FROM ohw-python:3.13
```

- **один** образ `ohw/dz2:local` с `--extra ui`: extra добавляет только
  Streamlit, поэтому CLI (`python -m ai_testgen`) и UI (`ai-testgen-ui`) живут
  в одном образе; отдельного CLI-only образа нет;
- compose `ui` собирает образ, `app` переиспользует тот же тег;
- стенд-скрипты (`scripts/up-cpu.ps1`, `up-gpu.ps1`, `up-gpu.sh`) поднимают
  компоненты из `infra/` (общий `ohw-ollama`) с GPU-оверлеем и ждут health,
  а не запускают per-project ollama.

## Источник требований

`docs/` — рабочий документ `business-requirements_catalog-courses.md`
(BR-1…BR-7, otus.ru). `input/` остаётся для зеркал и батча, поэтому compose
монтирует оба каталога. Dz7 по умолчанию читает `../dz2/docs`.
