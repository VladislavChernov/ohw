# Proposal: внешние промпты и два новых артефакта (Dz2 — основной проект)

> Исторический бандл. Источник требований по умолчанию (`docs/` вместо
> `input/`), пресеты и рабочее место описаны в
> `../workbench-and-presets/`.

## Почему

Dz2 — основной проект домашки. По ТЗ он должен генерировать документацию по
промптам, которые готовит отдельный генератор Dz7, и поддерживать пять типов
артефактов, включая QA-отчёт и матрицу покрытия требований.

Сейчас в Dz2:

- правка «читать промпт из `llm_prompt.txt`» не работает: файл загружается,
  но `_fill_prompt_template()` игнорирует аргумент `template` и заново
  собирает старый захардкоженный промпт;
- `ArtifactHandler` удалён, модуль `handlers.py` не импортируется
  (`F821` в трёх местах);
- внешний промпт подключён только к `testcases`; чек-лист и тест-план
  продолжают использовать хардкод из `prompt.py`;
- типов артефактов три, а не пять: `qareport` и `coveragematrix` невозможно
  даже объявить во front-matter;
- путь к промпту вычисляется от `__file__` и в нередактируемой
  Docker-установке указывает в `site-packages`, где файла нет;
- при отсутствии файла — молчаливый откат на хардкод.

## Что делаем

- **Один шаблон на тип артефакта**: `prompts/<type>.txt`
  (`testcases`, `checklist`, `testplan`, `qareport`, `coveragematrix`).
  Все пять типов собирают user-prompt через общий рендерер.
- **Подстановка плейсхолдеров** `{url}`, `{count}`, `{positive}`,
  `{negative}`, `{requirement_rule}`, `{content}` через regex — литеральный
  JSON-пример `{"cases": [...]}` не ломается.
- **Явные ошибки**: нет каталога, нет файла типа, неизвестный плейсхолдер —
  `PromptError`, код 2 **до** обращения к Ollama. Никакого молчаливого
  fallback.
- **Поиск шаблонов**: `--prompt-dir` → `DZ2_PROMPT_DIR` → `./prompts` →
  каталог репозитория → пакетный каталог.
- **Поставка в Docker**: `COPY prompts /app/prompts`,
  `ENV DZ2_PROMPT_DIR=/app/prompts`, монтирование `./prompts` в compose.
- **Пятый и четвёртый типы**: `QAREPORT`, `COVERAGEMATRIX` в `ArtifactType`,
  алиасы front-matter, валидаторы, заголовки renderer.
- **Требования берутся из `dz2/input`** — это входная директория основного
  проекта; Dz7 по умолчанию читает её же (`../dz2/input`).
- **Тесты**: подстановка, отсутствие шаблона, все пять типов, алиасы,
  сквозной `--prompt-dir` с sentinel-промптом.

## Спека

Дельта capability `testcase-generator`:
`ADDED` — внешние шаблоны, QA-отчёт, матрица покрытия;
`MODIFIED` — формат ответа по типу, валидация markdown, конфигурация,
поставка промптов.

## Проверка

- `uv run pytest -m "not integration"` в `dz2`.
- `uv run ruff check . && uv run mypy src tests` в `dz2`.
- e2e: `dz7` читает `dz2/input/<file>` → отдаёт промпты → `dz2`
  прогоняет их через Ollama в Docker → артефакты в `dz2/output`.
- Результаты качества — `dz7/docs/prompt-quality.md`.

## Связанный бандл
