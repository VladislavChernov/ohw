# Настройки нормализатора: глоссарий и руководство

Нормализатор требований (`dz2/src/ai_testgen/normalizer.py`) больше не хранит
параметры канонического вида в коде. Они лежат в отдельном файле
[`dz2/normalizer.toml`](normalizer.toml), а не в общем `ai-testgen.toml`:
настройки нормализации нужны и CLI, и рабочему месту, но меняются по другому
поводу, чем модель или каталоги.

## Откуда берутся значения

Порядок поиска (первое найденное побеждает):

1. флаг CLI `--normalizer-config <path>`;
2. переменная окружения `AI_TESTGEN_NORMALIZER_CONFIG`;
3. файл `normalizer.toml` в текущей рабочей директории;
4. встроенные значения по умолчанию (они совпадают с содержимым
   `dz2/normalizer.toml`).

В Docker файл примонтирован в `/app/normalizer.toml` (см. `compose.yaml`), а
образ задаёт `AI_TESTGEN_NORMALIZER_CONFIG=/app/normalizer.toml`; поэтому правка
на хосте видна и CLI, и UI без пересборки образа. Одна и та же переменная
работает и при обычном `docker run`: файл уже скопирован в образ.

Формат — плоский TOML: только пары `ключ = значение`, без секций и вложенных
таблиц. Неизвестные ключи не ломают запуск: CLI печатает
`warning: ... ignoring unknown keys`, UI показывает предупреждение.

## Параметры

| Параметр | Тип | По умолчанию | Допустимые значения | Что делает |
|---|---|---|---|---|
| `id_prefix` | строка | `"BR"` | 1–10 латинских или кириллических букв | Префикс новых идентификаторов требований (`BR-1` по умолчанию, `REQ-1` при `"REQ"`). Уже существующие ID в исходнике (`## BR-1`, `| BR-1 |`, `BR-1: ...`) сохраняются, а `BR-N` распознаётся всегда — независимо от значения параметра. |
| `requirements_heading` | строка | `"Requirements"` | непустая строка без перевода строки | Заголовок раздела с требованиями в нормализованном документе: `## Requirements`. Он же считается разделом требований при повторной нормализации. |
| `url_label` | строка | `"URL"` | непустая строка без перевода строки | Подпись строки с адресом сайта: `**URL:** https://...`. Влияет только на вид документа, не на поиск URL. |
| `fallback_title` | строка | `"Требования"` | непустая строка без перевода строки | Заголовок `# ...`, если в исходнике нет ни `H1`, ни короткой первой строки. |
| `encodings` | массив строк | `["cp1251", "cp866"]` | имена кодеков Python, например `utf-8`, `cp1251`, `cp866`, `koi8-r`, `cp1252` | Кодировки, которые пробуются после строгого UTF-8 и BOM. Порядок важен: при равном счёте побеждает та, что стоит раньше. |
| `paragraph_min_length` | целое | `20` | ≥ 1 | Минимальная длина абзаца, который считается требованием в резервном режиме «по абзацам» (когда структура не распознана). Короткие абзацы отбрасываются. |

### `id_prefix`

Меняйте, если в вашем трекере требования называются иначе (`REQ-1`, `FR-3`,
`ТР-2`). Нормализатор:

- сохраняет уже существующие ID из заголовков, таблиц, списков и строк
  `BR-1: ...` или `REQ-1: ...`;
- выдаёт свободные номера новым требованиям;
- отбрасывает дубликаты и пустые тексты с предупреждениями.

Смена префикса не перенумеровывает документ: `BR-N` остаётся валидным ID при
любом значении `id_prefix`, новый префикс применяется только к требованиям без
ID. Иначе первый же прогон с `REQ` сломал бы ссылки в уже сгенерированных
тест-кейсах и матрице покрытия.

Регистр в исходнике не важен (`br-1` → `BR-1`, `req-1` → `REQ-1`). Префикс
должен состоять из букв: цифры и дефисы запрещены, иначе нормализатор не сможет
отделить номер от текста.

```toml
id_prefix = "REQ"
```

Результат: `### REQ-1`, `### REQ-2`. Промпт получает `requirement: "REQ-1"` —
проверьте, что валидатор и матрица покрытия ждут именно такой формат.

### `requirements_heading`

Заголовок раздела в каноническом документе. Меняйте, если требования должны
называться по-русски или по стандарту компании.

```toml
requirements_heading = "Требования"
```

Результат: `## Требования` вместо `## Requirements`. Повторная нормализация
такой документ узнаёт: заголовок сравнивается и по общим правилам
(`Requirements`, `Требования`), и с текущим значением параметра.

### `url_label`

Подпись строки с адресом. На поиск URL не влияет: адрес берётся из флага
`--url`, поля URL в UI или первого `http(s)`-ссылки в тексте.

```toml
url_label = "Сайт"
```

Результат: `**Сайт:** https://shop.example.com/login`.

### `fallback_title`

Заголовок на случай, когда в исходнике нет `# ...` и нет короткой первой
строки. Часто встречается в требованиях, скопированных из чата.

```toml
fallback_title = "Требования из письма"
```

### `encodings`

Список кодеков для файлов, которые не являются корректным UTF-8 и не имеют
BOM. UTF-8 и BOM (`UTF-8/16/32`) проверяются всегда и раньше списка — их
убрать нельзя. Кандидаты декодируются все, победитель определяется по числу
кириллических букв и штрафам за «мусорные» символы; при равенстве выигрывает
первый в списке.

```toml
encodings = ["koi8-r", "cp1251", "cp866"]
```

Когда список пуст или содержит неизвестный кодек, запуск завершается ошибкой
конфигурации (CLI — код 2, UI — предупреждение), а не молчаливым fallback.

### `paragraph_min_length`

Работает только в резервной стратегии «абзацы», когда не нашлось ни заголовков
`BR-N`, ни таблицы `ID | описание`, ни списка под разделом требований.
Увеличьте значение, если в требования попадает мусор из коротких строк;
уменьшите, если короткие требования теряются.

```toml
paragraph_min_length = 40
```

## Как проверить, что настройки применились

CLI печатает кодировку, число требований и стратегию:

```powershell
docker compose -f dz2/compose.yaml run --rm app `
  --normalize-only --input-dir /data/input --output-dir /data/output
# normalized: /data/output/normalized/doc.md (cp1251, 2 requirements, strategy: table)
```

В UI блок «Нормализация требований» показывает кодировку, число требований и
стратегию; после нажатия «Нормализовать» видно «Исходный / Нормализованный».
Настройки меняются в разделе «Настройки нормализации» (раскрывающийся блок над
кнопкой) и действуют в пределах сессии; кнопка «Вернуть значения из файла»
сбрасывает правки. Если поменять настройки после нормализации, результат
помечается устаревшим и требует повторного нажатия «Нормализовать».

## Ограничения

- Порядок стратегий извлечения (`заголовки → таблица → список → строки BR-N →
  абзацы`) фиксирован: настраивать его в файле нельзя.
- Регулярные выражения для таблиц и разделов не настраиваются; меняются только
  перечисленные выше параметры.
- `normalizer.toml` не влияет на генерацию промпта: он меняет только вид
  требований, которые в промпт попадают.

## Типовые ошибки

| Сообщение | Причина | Что делать |
|---|---|---|
| `файл настроек не найден` | `--normalizer-config` указывает на отсутствующий файл | Проверьте путь; без флага файл ищется в текущей директории |
| `id_prefix must be 1-10 letters` | в префиксе цифры, дефис или он пуст | Оставьте только буквы, например `REQ` |
| `unknown codec in encodings` | опечатка в имени кодека | Возьмите имя из `codecs.lookup`: `cp1251`, `koi8-r` |
| `paragraph_min_length must be positive` | ноль или отрицательное число | Укажите целое ≥ 1 |
| `документ пуст: нет текста требований` | после чистки не осталось текста | Проверьте исходный файл, а не настройки |
