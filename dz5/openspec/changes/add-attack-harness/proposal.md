# Proposal: add-attack-harness (OWASP LLM Top 10 2026 × 5 пресетов)

## Why

Сейчас есть только разрозненные заготовки: `scripts/test_security.py` (16
payload'ов без оркестратора), `scripts/augustus/augustus.config.yaml` и ручной
`reports/red-team.md` без измерений. Нет раннера, который:

- прогоняет один и тот же набор атак по всем пресетам;
- делает `n>=3` и сохраняет сырые ответы;
- отделяет `blocked` от `bypass` и `unknown`;
- фиксирует модель, commit, окружение и метрики;
- восстанавливает БД между разрушительными сценариями.

Без этого любые выводы в отчёте — мнение, а не результат.

## What changes

- Python-раннер `attack-runner/` с CLI и YAML-сценариями.
- 16 базовых сценариев, покрывающих все 10 категорий OWASP LLM 2026 (см.
  `reports/red-team.md`), плюс два Poison RAG сценария из
  `docs/STANDARD_SECURITY_CHECKS.md`.
- Матрица целей: preset 1–4 (`agent:8080`), preset 5
  (`agent-fixed:8080`).
- `n>=3` по умолчанию; агрегация по каждому сценарию × пресету.
- Вердикты: `blocked`, `bypass`, `mixed`, `unknown`, `error`,
  `not_applicable`.
- `manifest.json` + `results.jsonl` + `details/<scenario>/<run>.json` в
  `reports/<run-id>/`.
- Метрики: HTTP-код, latency, размер ответа, CPU/RAM контейнеров (если
  доступны), признак изменения БД.
- Augustus как дополнительный источник атак; его вывод сохраняется отдельно
  и не подменяет собственные evaluator'ы.
- Восстановление БД (`db-restore`) перед сценариями с записью.
- Compose-сервис `attack-runner` (профиль `tools`/`attack`).

## Non-goals

- Генерация отчётов `latest.md` — бандл `add-reports`.
- Демо-оркестрация — бандл `add-demo-scripts`.
- Замена Guardrails Server или fixed agent.
- Атаки на реальные данные/внешние сервисы: только локальный стенд и
  синтетическая БД.

## Risks

- Недетерминированность LLM: один и тот же payload может дать разные ответы.
  Отсюда `n>=3` и `mixed`, а не бинарный вердикт.
- Ложные `blocked`: HTTP 403 может быть ошибкой конфигурации, а не защитой.
  Проверять, что легитимный запрос в том же пресете проходит.
- Ложные `bypass`: ответ может содержать слово `password` без утечки.
  Evaluator'ы должны проверять маркеры/структуру, а не любое совпадение.
- Разрушение БД: `DROP/DELETE` сценарии выполнять только после `db-seed` и
  восстанавливать `db-restore` в `finally`.
- Augustus может измениться/быть недоступным: раннер не должен падать, если
  внешний инструмент не установлен; фиксировать `error`/`skipped`.

## Definition of done

- `attack-runner` запускается одной командой и делает прогон по выбранному
  пресету.
- 16 базовых сценариев + Poison RAG, `n>=3`, сырые ответы сохранены.
- `manifest.json` содержит модель, commit, образы, preset, время.
- Вердикты не путают `unknown`/`error` с `blocked`.
- БД восстанавливается после деструктивных сценариев.
- Есть smoke-прогон на preset 1 и 5; результаты пригодны для `add-reports`.
