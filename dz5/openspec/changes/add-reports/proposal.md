# Proposal: add-reports (артефакты прогонов и сводный отчёт)

## Why

Сейчас `reports/red-team.md` — ручной черновик, в котором все атаки были
помечены `blocked` без прогонов. Нет структуры `reports/<run-id>/`, нет
манифеста, нет агрегации, нет `latest.md`. Из-за этого нельзя доказать ни
уязвимость baseline, ни эффект защиты.

## What changes

- Единая структура `reports/<run-id>/`:
  `manifest.json`, `results.jsonl`, `details/`, `summary.json`, `summary.md`.
- Генератор сводного `reports/latest.md` из самого свежего **полного** прогона.
- Таблица «атака × пресет → вердикт + latency + CPU/RAM».
- Генерация red-team-таблицы из результатов; `unknown`/`mixed`/`error`
  сохраняются, а не превращаются в `blocked`.
- Валидация manifest и результатов; неполный прогон не публикуется как
  `latest`.
- Атомарная запись, чтобы не оставить половину отчёта.
- Удаление недоказанных выводов из старого `red-team.md`.

## Non-goals

- Сам раннер атак (`add-attack-harness`).
- Демо-скрипты (`add-demo-scripts`).
- Красивые графики/PDF; только Markdown + JSON.

## Risks

- Сводка может скрыть разброс: при `mixed` нельзя писать `blocked`. Поэтому
  в таблице показываются counts и итоговый вердикт, а `summary.json` хранит
  детали.
- Разные наборы сценариев между прогонами: сравнивать только при совпадении
  `scenario_set_sha256`; иначе помечать прогон несравнимым.
- Секреты в ответах модели: перед публикацией редактировать известные
  секреты/токены; хранить сырые ответы только локально.

## Definition of done

- `reports/<run-id>/` создаётся и валидируется.
- `latest.md` генерируется из полного прогона.
- Red-team таблица строится из данных, не вручную.
- Неполный/битый прогон не становится `latest`.
- `unknown`/`mixed`/`error` видны в отчёте.
- Старый недоказанный red-team заменён.
