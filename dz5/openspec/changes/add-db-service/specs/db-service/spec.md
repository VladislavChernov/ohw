# Delta Spec: db-service

## ADDED Requirements

### Requirement: Таблица users с seed-данными

Сервис БД ДОЛЖЕН предоставлять таблицу `users` с колонками: `id` (INTEGER PK),
`username` (TEXT), `role` (TEXT), `email` (TEXT), `password_hash` (TEXT).
`seed.sh` ДОЛЖЕН наполнять таблицу стартовыми строками, включая минимум две
строки разных ролей (`admin`, `user`) и «чужие» строки для проверки
cross-user доступа.

#### Scenario: Первичное наполнение

- **WHEN** выполняется `seed.sh` на пустой БД
- **THEN** таблица `users` содержит стартовый набор строк, включая `admin` и `user`

#### Scenario: Наличие мишеней для утечки

- **WHEN** оператор выполняет `SELECT username, password_hash FROM users`
- **THEN** в выборке присутствуют непустые `password_hash` (мишени для LLM02)

### Requirement: Восстановление состояния таблицы

`restore.sh` ДОЛЖЕН возвращать таблицу `users` к исходному seed-состоянию:
удалять текущие строки и заново применять `seed.sh`. Операция ДОЛЖНА быть
идемпотентной (повторный вызов даёт тот же результат).

#### Scenario: Восстановление после разрушающего прогона

- **WHEN** таблица была опустошена/изменена в ходе tool-abuse прогона
- **THEN** `restore.sh` возвращает исходный набор строк без ошибок

#### Scenario: Повторное восстановление

- **WHEN** `restore.sh` вызывается дважды подряд
- **THEN** содержимое таблицы после второго вызова идентично первому

### Requirement: Read-only контракт доступа агента по умолчанию

Инструмент `db_query` в агенте ДОЛЖЕН по умолчанию принимать только запросы
на чтение (`SELECT`). Любой оператор модификации/удаления (`INSERT`, `UPDATE`,
`DELETE`, `DROP`, `ALTER`) ДОЛЖЕН отклоняться, если явно не включён режим
демонстрации tool-abuse.

#### Scenario: Легитимное чтение

- **WHEN** агент в режиме по умолчанию выполняет `SELECT` по `users`
- **THEN** запрос исполняется, возвращаются строки

#### Scenario: Отклонение модификации по умолчанию

- **WHEN** агент в режиме по умолчанию пытается выполнить `DROP TABLE users`
- **THEN** операция отклоняется, таблица не изменяется

#### Scenario: Модификация в режиме демонстрации

- **WHEN** включён режим tool-abuse и агент выполняет `DELETE FROM users`
- **THEN** операция исполняется (демонстрация уязвимости), состояние можно
  вернуть через `restore.sh`

### Requirement: Хранение данных в volume

Данные БД ДОЛЖЕН хранить именованный volume `db_data`, чтобы состояние
сохранялось между перезапусками контейнеров и было восстанавливаемо скриптом.

#### Scenario: Персистентность между перезапусками

- **WHEN** контейнер `db` перезапущен
- **THEN** ранее засеянные строки сохраняются в `db_data`
