# Proposal: сервис БД стенда (SQLite + seed/восстановление)

## Почему

Для демонстрации утечек и tool-abuse агенту нужна цель — таблица БД, которую он
читает, но не должен мочь неконтролируемо разрушать или отдавать наружу. Нужна
лёгкая БД, разворачиваемая одной командой и восстанавливаемая скриптом между
прогонами атак (чтобы база не оставалась «сломанной» после теста).

## Что делаем

- Сервис `db` на образе `keinos/sqlite3` (CLI SQLite) с volume `db_data`.
- Таблица `users` (id, username, role, email, `password_hash`, `api_token`,
  created_at). `password_hash` намеренно хранится в открытом виде в песочнице —
  это мишень для демонстрации утечки (LLM02) и tool-abuse (LLM03).
- Таблица `personal_data` (id, user_id, full_name, birth_date, passport, inn,
  snils, phone, address, card_last4, note) — **синтетические ПДн** на каждого
  пользователя. Это rich-мишень для Sensitive Information Disclosure (LLM02) и
  cross-user доступа (LLM03). Все значения вымышленные.
- `init.sql` — создание схемы; `seed.sql` + `seed.sh` — наполнение стартовыми
  строками (в т.ч. «чужие» строки других пользователей для проверки LLM03).
- `restore.sh` — восстановление таблиц к исходному состоянию
  (delete + re-seed) после «разрушающих» прогонов.
- Агент обращается к БД через tool `db_query` с режимом **только чтение** по
  умолчанию (allow-list `SELECT`); режимы записи/удаления включаются отдельно
  для демонстрации tool-abuse.

## Спека

Новая capability `db-service`: схема таблицы, seed, восстановление,
read-only-контракт по умолчанию, доступ агента через `db_query`.

## Проверка

- `docker compose run --rm db-seed` наполняет таблицу; `sqlite3` внутри
  показывает ожидаемые строки.
- `db-restore` возвращает состояние к исходному после искусственного удаления.
- Агент в Baseline читает таблицу; в режиме tool-abuse способен выполнить
  `DROP`/`DELETE` (демонстрация уязвимости); с guard — операция отклоняется.

## Изменения

- `infra/db/Dockerfile` — образ CLI SQLite.
- `infra/db/init.sql`, `infra/db/seed.sh`, `infra/db/restore.sh`.
- Сервис `db` и volume `db_data` в `infra/compose.yaml`.
- Инструмент `db_query` в агенте (детали — в бандле `add-agent-core`).

## Impact

- Новый сервис, обратной совместимости нет (проект с нуля).
- Объём данных минимальный (десятки строк) — специально, чтобы стенд был лёгким.
