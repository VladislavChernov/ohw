# Proposal: add-demo-scripts (оркестрация демонстрации)

## Why

Стенд состоит из нескольких шагов: собрать образы, засеять БД, поднять
сервисы, проверить health, прогнать атаки по пресетам, собрать отчёт,
восстановить БД. Сейчас эти шаги разрознены в README и легко сделать
неполно/в неправильном порядке. Нужен один воспроизводимый сценарий для
Windows и Linux.

## What changes

- `infra/scripts/demo.ps1` (PowerShell 5.1+) и `infra/scripts/demo.sh`
  (bash) с одинаковым набором флагов и шагов.
- Шаги: preflight → build/up → seed → health → smoke → attack (по пресетам)
  → report → итог.
- Флаги: `-Preset`, `-Runs`, `-SkipBuild`, `-KeepUp`, `-AllowWrites`,
  `-NoAttacks`, `-Help`.
- Логи и артефакты в `reports/<run-id>/`; код возврата по результату.
- `finally`/`trap`: восстановить БД и, если не `-KeepUp`, остановить стенд.
- Не печатать секреты; не требовать интерактивного ввода.

## Non-goals

- Замена `docker compose` или CI.
- Автоматическое исправление уязвимостей.
- Запуск на macOS (bash-скрипт должен работать, но не тестируется отдельно).

## Risks

- Разные версии PowerShell/bash: избегать сложных конструкций; проверять
  `docker compose version`.
- Долгий первый запуск (загрузка модели) — таймауты health с запасом.
- `allowWrites` может испортить БД — только с явным флагом и восстановлением.
- Остановка чужих контейнеров: использовать проект `dz5-stand` и только его
  сервисы.

## Definition of done

- `demo.ps1` и `demo.sh` выполняют полный сценарий на чистой машине.
- Повторный запуск идемпотентен (seed/restore не ломают состояние).
- `-KeepUp` оставляет стенд; без флага — останавливает.
- При ошибке — ненулевой exit code и понятное сообщение.
- README ссылается на скрипты.
