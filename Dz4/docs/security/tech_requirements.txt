=== ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ К СИСТЕМЕ БЕЗОПАСНОСТИ RAG ===

1. ТРЕБОВАНИЯ К АУТЕНТИФИКАЦИИ И АВТОРИЗАЦИИ (AUTH)
- Идентификация пользователей должна осуществляться строго через централизованную систему института.
- Передача контекста безопасности (ролей) между сервисами должна быть защищена криптографически подписанными токенами (JWT).
- Время жизни сессионного токена не должно превышать установленный регламент (с учетом обновления ролей раз в полгода).

2. ТРЕБОВАНИЯ К СЛОЮ ИЗОЛЯЦИИ ДАННЫХ (DATA ISOLATION)
- Ограничение доступа к документам должно происходить на этапе выборки из БД (Pre-filtering), а не после нее (Post-filtering).
- Каждый чанк в Neo4j должен содержать обязательное свойство `allowed_roles` (список строк).
- Запросы на языке Cypher обязаны содержать предикат WHERE для проверки пересечения ролей пользователя и документа.

3. ТРЕБОВАНИЯ К ФИЛЬТРАЦИИ ВХОДА И ВЫХОДА (GUARDRAILS)
- Система должна содержать промежуточное ПО (Middleware) для валидации входящего текста на наличие паттернов Jailbreak.
- Выходящий поток данных от LLM должен проходить валидацию регулярными выражениями на исключение PII (паспорта, телефоны).
- Логирование запросов не должно сохранять персональные данные и закрытые ответы.
