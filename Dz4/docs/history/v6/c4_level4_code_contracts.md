# arc42 / C4 ARCHITECTURE PASSPORT -- LEVEL 4: ARCHITECTURAL CONTRACTS (v6.0.0)
================================================================================
РАЗДЕЛ arc42: ЯЗЫКОВО-НЕЗАВИСИМЫЕ ИНТЕРФЕЙСЫ И ТОЧКИ РАСШИРЕНИЯ (SYSTEM INTERFACES)

Этот документ фиксирует абстрактные контракты взаимодействия между компонентами ядра (Fixed Core) и инфраструктурными плагинами. Для исключения вендор-зависимости все контракты переведены на уровень сетевых и декларативных спецификаций (gRPC/Proto3 и JSON-Schema), что позволяет реализовывать высоконагруженные узлы (Query API) на компилируемых языках (Go/Rust), а ИИ-компоненты — на Python.

## 1. Спецификация Точек Расширения Системы (Extension Points)

Система v6.0.0 изолирует риски кастомизации через три строго определенных интерфейса:

### [Точка А]: Протокол Инфраструктурных Адаптеров (gRPC / REST Data Contracts)
Всякое взаимодействие ядра с базами данных, LLM-движками и эмбеддерами стандартизировано на уровне сетевого обмена. Плагин считается валидным, если его API строго соответствует структурам данных:
*   Интерфейс Хранилища (Storage Contract): Обязан принимать массив вещественных чисел (вектор) для выполнения поиска vector_search и возвращать детерминированный JSON-массив с метаданными текстовых чанков. Принимает структурированные списки для транзакционных операций upsert_nodes/upsert_edges.
*   Интерфейс Инференса (LLM Contract): Обязан поддерживать метод синхронной генерации текста (для экстракции триплетов пайплайном) и метод потоковой отдачи токенов (Chunk Stream via gRPC/HTTP-chunked) для трансляции ответа в асинхронный веб-интерфейс.

### [Точка Б]: Декларативный Контракт Домена (JSON-Schema Validation)
Интерфейс «Бизнес-Аналитик — Платформа» полностью изолирован через схему валидации YAML. При загрузке файла конфигурации `domain_profile.yaml` Config Service в автоматическом режиме проверяет:
1. Наличие и типы данных обязательных блоков: ontology, extraction, validation_rules, canonicalization.
2. Контракт Промпта: Поле extraction.prompt_template обязано содержать управляющие теги переменного контекста {text_chunk} и инжектировать строгую инструкцию форматирования ответа (Strict JSON Output).

### [Точка В]: Фабрика Системной Топологии (Topology Mapping)
Файл infra_topology.yaml расширяется через строковое лексическое сопоставление (String Identifiers). Topology Orchestrator считывает строковые ключи активных провайдеров (например: storage: "neo4j_grpc", llm: "vllm", queue_provider: "valkey_streams") и динамически коммутирует сетевые сокеты и коннекторы, выполняя роль фабрики системных драйверов.

## 2. Архитектурный Регламент Производительности (Полиморфизм Языков)

Для ликвидации архитектурных ограничений интерпретируемых языков (таких как GIL в Python), компоненты ядра разделяются по типу вычислительной нагрузки:

+──────────────────────────────────────+       +──────────────────────────────────────+

|  ВЫСОКОНАГРУЖЕННЫЙ КОНТУР (Go/Rust)  |       |      ИИ И ДАННЫЙ КОНТУР (Python)     |
+──────────────────────────────────────+       +──────────────────────────────────────+

| - Контейнер 2: Query API Gateway     |       | - Контейнер 4: Embeddings Service    |
| - Контейнер 11: Query Workers Pool   |       | - Контейнер 5: Ollama/vLLM Driver    |
| - Контейнер 10: Valkey Streams Queue |       | - Контейнер 6: Ingestion Pipeline    |
+──────────────────────────────────────+       +──────────────────────────────────────+

| Назначение: Параллельный асинхронный |       | Назначение: CUDA-вычисления на GPU,  |
| ввод-вывод, мгновенный роутинг задач,|       | регулярные выражения, строковая      |
| обслуживание сотен WebSockets-сессий.|       | канонизация, Cypher-валидация графа. |
+──────────────────────────────────────+       +──────────────────────────────────────+

Использование компилируемого языка (Go/Rust) в сетевом контуре Query Workers обеспечивает субмиллисекундное извлечение задач из оперативной очереди рантайма и гарантирует, что сетевой стек платформы не станет узким местом при росте количества одновременных пользователей в 1000 раз.
