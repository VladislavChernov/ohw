# Документация: Стратегия Ретривера и Слияния контекста (v4.0 — АРХИВ)

> **Версия:** v4.0  
> **Последнее обновление:** 2026-09-04

## 1. Доменно-агностичный Retrieval Pipeline и генерация ответа

При запросе пользователя Query API последовательно выполняет следующие шаги:

1. Расчёт мультиязычного эмбеддинга запроса (модель bge-m3 на GPU, ~50 мс)
2. Вызов Graph Retriever: Выполняется параметризованный Cypher-шаблон. Шаблон автоматически подставляет типы узлов и правила расширения связей (SIMILAR_TO) из метаданных активного Domain Profile
3. Вызов Vector Retriever: Поиск топ-N релевантных текстовых чанков в Neo4j
4. Вызов Reranker: Переранжирование чанков моделью bge-reranker-base на CPU
5. Context Assembly [НОВОЕ]: Сборка итогового промпта (см. правила в п.2)
6. LLM Generation [НОВОЕ]: Передача промпта и системных инструкций в локальный сервер Ollama (Qwen 2.5 7B Instruct на GPU). Время генерации: от 3 до 10 сек
7. Response [НОВОЕ]: Потоковый стриминг токенов ответа пользователю через SSE (Server-Sent Events) с выдачей списка источников (sources) и таймингов

## 2. Динамическая сборка контекста (Context Assembly)

Формат сборки контекста определяется флагами из Domain Profile:

- **Порядок данных:** Результаты графового поиска ("Скелет") всегда вставляются первыми, формируя логический каркас для ЛЛМ. Векторные чанки ("Тело") идут вторыми, наполняя каркас формулами, цитатами и кодом.
- **Шаблон контекста:** Подгружается по ID из профиля (context_it_v1, context_cinema_v1)
- **Окно контекста:** Жёсткий лимит в 4096 токенов контролируется программно
- **Стратегия вытеснения при переполнении лимита [ИСПРАВЛЕНО]:** Если объём контекста превышает 4096 токенов, излишки детерминированно отбрасываются. При этом первоочерёдно отбрасываются векторные чанки с наименьшим reranker-score
