## 1. Аутентификация

- **Единый механизм:** HTTP-заголовок `X-API-Key` для всех HTTP-контуров (Query :8000,
  Config :8001, Ingestion :8002, Glossary :8003, Topology Orchestrator :8005).
- **Хранение ключа:** `namespace: auth.api_key` в Config Service. Для прототипа допустимо
  `changeme` (default в `docs/06 §1`); для продакшена — распределённый секрет-менеджер
  (Vault / K8s Secret), а не YAML-конфиг.
- **MCP-контур (ADR-017):** те же ключи, что и HTTP; Query API Gateway является единой точкой
  входа для браузерных клиентов, ИИ-агентов (MCP) и CLI.
- **UI-контуры разделены (ADR-019):** конфигуратор «Бизнес-онтология» (:8501) и Topology UI
  (:8502) аутентифицируются собственными ключами к своим сервисам (Config :8001 /
  Topology :8005 соответственно).
- **Ошибка:** `401 Unauthorized` при отсутствии/неверном ключе; `500` при недоступности
  хранилища ключей.

## 2. Авторизация (роли)

| Роль | Описание | Доступ |
|------|----------|--------|
| `analyst` | Чтение графа, поисковые запросы, просмотр отчётов | Query (запросы), Glossary (resolve) |
| `configurator` | Управление онтологией и глоссариями через конфигуратор | Config API, Glossary (validate/сохранение) |
| `ingestor` | Загрузка и удаление источников | Ingestion API |
| `operator` | Управление инфраструктурой, адаптерами, метриками, топологией | Config (adapters), Topology Orchestrator :8005 + Topology UI :8502, мониторинг |

- **Разделение UI-контуров (ADR-019):** экран «Топология инфраструктуры» вынесен из
  конфигуратора в отдельное приложение Topology UI (:8502) — доступно только `operator`.
  Конфигуратор «Бизнес-онтология» (:8501) — для `configurator`/`analyst`. Каждый UI
  аутентифицируется ключом к своему сервису.
- Для прототипа допускается одна учётная запись (один ключ) с полным доступом; матрица ролей
  вступает в силу при переходе к продакшен-инсталляции.

## 3. Транспорт и защита каналов

- Внутри Docker-сети (`ohw_net`) сервисы общаются по HTTP/1.1 без TLS (изоляция сети).
- Внешние границы (Query API, Web UI конфигуратор, Topology UI) — только через TLS
  (mTLS — опционально, при наличии PKI). Для внутренней инсталляции на прототипе TLS на
  границе обязателен при доступе с внешних хостов.
- Secrets (API-ключи, пароли БД, доступ к Ollama/LM-серверам) не логируются: поля
  `X-API-Key`, `Authorization` исключаются из JSON-логов (structlog — redaction).

## 4. Защита от перегрузок

- **Rate limiting Query API (MCP-агенты):** лимиты на `graphrag.query` — n запросов/сек на ключ
  (настраивается в Config Service; политика фиксируется при вводе в эксплуатацию).
- **Rate limiting Topology API (:8005):** управление топологией — низкочастотные операторские
  действия; лимиты применяются по ключу оператора.
- **Лимит тела запроса:** на Ingestion (размер файла) и Query (длина промпта) — константы
  прототипа, значения — в `docs/infrastructure_stack.md` §5 (по мере реализации).
