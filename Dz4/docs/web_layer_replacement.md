# Документация: Замена веб-слоя (Query API Gateway)

> **Версия:** v1 (по ADR-020)
> **Последнее обновление:** 2026-09-06
>
> Как заменить язык/реализацию Query API Gateway (:8000) без переделки остальной системы.
> ADR-020 фиксирует Python/FastAPI для прототипа; этот документ — процедура перехода
> на Go/Rust или другую реализацию в рамках фазы 2.

## 1. Что такое «веб-слой» в этой системе

Query API Gateway — **граница**, а не часть ядра. Его обязанности:

- Приём `POST /query` → `202 Accepted` + `task_id` (асинхронный контракт, ADR-016).
- Раздача результата пользователю: SSE и/или WebSockets по конверту ADR-016.
- MCP-мост: инструменты `graphrag.query`, `graphrag.get_active_domain`,
  `graphrag.resolve_term`, `graphrag.get_sources` (ADR-017).
- Аутентификация `X-API-Key` (`docs/security.md` §1), rate-limiting (`security.md` §4).

Зависимость **однонаправленная**: шлюз → (Task Queue, Config :8001, Glossary :8003).
Никакие внутренние компоненты не знают о внутренностях шлюза.

## 2. Контракты, которые обязан соблюдать любой веб-слой

Заменяемая реализация обязана реализовать **на-проводные контракты как есть**, без изменения:

| Контракт | Фиксация | Что реализовать |
|----------|----------|-----------------|
| Асинхронный Query API | ADR-016, `api_reference.md` §3 | `POST /query`, `202+task_id`, `GET /query/tasks/{id}` |
| Конверт событий стриминга | ADR-016 | `{type: status\|token\|done\|error, task_id, ts, payload}` через SSE / WS |
| MCP-инструменты | ADR-017 | 4 инструмента по JSON-RCP-мосту :8000 |
| Аутентификация | `security.md` §1 | заголовок `X-API-Key`, `401` при неверном ключе |
| Ошибки | `api_reference.md` §2 | стандартные коды и формат ошибок |

Интерфейс к **Task Queue** (Valkey/Redis Streams) определяется схемой сообщения очереди
(`docs/06` §, контур v6); к Config/Glossary — HTTP-контрактами ADR-018.

> Статус контрактов стриминга — `v1-draft` (ADR-016): при замене веб-слоя нельзя менять поля
> конверта без новой ADR-записи.

## 3. Что НЕ трогается при замене веб-слоя

- Python-ядро: пайплайн 9 этапов, ретривер, Config/Glossary Service, адаптеры, Domain Profiles.
- Neo4j, Ollama, Valkey, embeddings/reranker-сервисы.
- Docker-профили, сеть `ohw_net` (меняется только образ `query-api` в `prototype/infra/compose.yaml`).
- Контракты ADR-016/017/018 (остаются SSOT для границы).
- Eval-инфраструктура, глоссарии, ролевая модель.

## 4. Процедура замены (пошагово)

1. **Зафиксировать объём.** Новая реализация обязана пройти контрактные тесты границы
   (см. приложение A) — это критерий «замена выполнена».
2. **Реализовать** новую поверхность: HTTP+SSE/WS, MCP, auth, rate-limit; читать Task Queue
   и обращаться к Config/Glossary по контрактам (§2).
3. **Обновить композ:** в `prototype/infra/compose.yaml` заменить образ `query-api`
   (профиль `llm`); при необходимости — переменные окружения (OLLAMA_URL, CONFIG_URL и т.п.).
4. **Прогнать контрактные тесты** границы (§A) и eval-срез (`prototype/infra/eval/`, ADR-015),
   чтобы убедиться, что поведение не изменилось (та же метрика groundedness/coverage).
5. **Зафиксировать решение ADR-записью** (новый ADR или update ADR-020) с указанием языка
   и причин перехода.

## 5. Когда переходить на Go/Rust (фаза 2)

- Реальная нагрузка: тысячи одновременных стримящих SSE/WS-соединений.
- Требование к лаку/перф-потолку границы (Go — зрел для MCP-экосистемы; Rust — максимум
  производительности, но выше стоимость разработки).
- Ресурсные лимиты инсталляции (образ ~20–50 МБ vs ~150+ МБ Python).

**Ограничение:** замена на Go/Rust не требует переписывания ядра — только этого шлюза (§3–§4).

## Приложение A: Контрактные тесты границы (чек-лист)

- [ ] `POST /query` без ключа → `401`.
- [ ] `POST /query` с корректным ключом → `202` + `task_id`.
- [ ] Получении результата через SSE: `status` → `token*` → `done` (поля конверта по ADR-016).
- [ ] То же через WebSocket.
- [ ] `error`-событие при недоступности Workers/очереди.
- [ ] MCP: `graphrag.query` возвращает ответ; остальные 3 инструмента — по спецификации ADR-017.
- [ ] Rate-limit: превышение лимита → корректный код/RateLimit-ответ.
- [ ] Тайминги и `sources` в `done`-событии (формат ADR-016).
