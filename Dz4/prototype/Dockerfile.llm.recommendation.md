# Рекомендация: замена LLM-контейнера на self-contained образ (Dockerfile.llm)

> **Дата:** 2026-09-13 · **Объект:** `prototype/Dockerfile.llm` (новый) → сервис `llm` в `prototype/infra/compose.yaml`
> **Статус:** рекомендация к реализации; compose-правка — один блок (§5).

---

## 1. Проблема из ревью (обоснование замены)

`review.md` (2026-09-12, ТОП-10 №8, DevOps): **«Непереносимый Windows-путь к GGUF в дефолте compose»** —
сервис `llm` монтирует веса bind-mount'ом с дефолтом `<local-path>/lmstudio-community/
Qwen2.5-Coder-7B-Instruct-abliterated-GGUF` — путь конкретной машины, зафиксированный в коммите:

- на другой машине/после переустановки стек поднимется, а `llm` молча не найдёт модель (пустой `/models`);
- модель **двойно захардкожена**: и путь, и имя файла (`LLM_GGUF_FILE`) с конкретным квантом;
- это тот же класс «ложной готовности», что и monitoring-профиль (critical_review №3), только мягче.

**Почему замена снимает проблему целиком (а не маскирует):**

| Было (bind-mount) | Стало (веса в образе) |
|---|---|
| Рантайм зависит от ФС хоста и Windows-пути в дефолте | Рантайм не зависит от хоста вовсе: веса в слое образа |
| «Лишнее скачивание» при сборке — главное опасение, поэтому веса не вшивались | **Скачивание перестало быть проблемой**: качается ровно один раз — базовый образ llama.cpp + GGUF (4.36 ГиБ); оба кэшируются как слои, повторные сборки без сети |
| Локальный файл **обязателен** (LM Studio должен быть установлен) | **Локальный файл стал необязательным**: источник — проверенный репозиторий Hugging Face; локальная копия больше не участвует ни в сборке, ни в рантайме |
| Дефолт пути = знание о конкретной машине в git | В git — только pin ревизии репо и SHA-256 файла, переносимо |

Дополнительные выгоды: переносимость (Windows-путь исчезает из дефолтов), атомарность (веса + runtime
одним артефактом `ohw/llm:prototype`), детерминизм (pin + SHA-256, §3). Цена — размер образа ~6.5 ГиБ
(принято: «образ станет больше — неважно»).

## 3. Как Dockerfile.llm решает задачу (минимально безопасно)

- **Двухстадийная сборка.** Стадия `weights` (python-slim + `huggingface_hub`) скачивает GGUF через
  `hf_hub_download(revision=HF_REVISION)`; финальная стадия — `llama.cpp:server-cuda`, куда веса копируются
  `COPY --from=weights`. В итоговом образе нет pip/даунлоадера — только runtime + модель.
- **Pin ревизии.** HF отдаёт ровно ту ревизию, что проверена; изменения в репо не затрагивают сборку.
- **Верификация SHA-256 после скачивания** (`sha256sum -c`) — при обрыве сети или изменении файла сборка
  **падает**, а не собирает образ с испорченными весами. Сильнее, чем «имя файла совпало».
- **Смена модели** — переопределить 4 build-args (`HF_REPO/HF_REVISION/HF_FILE/HF_SHA256`), без правки Dockerfile.
- Из сети качается ровно два раза за жизнь машины: базовый образ (один раз, кэш) + GGUF (кэш-слой).

## 4. Сборка

```bash
cd prototype
docker build -f Dockerfile.llm -t ohw/llm:prototype .
```

Первый `build` скачает базовый образ + веса (~4.4 ГиБ) и проверит SHA-256; последующие — мгновенны
(кэш-слои). Требуется BuildKit (Docker 23+/Compose v2.20+ — есть по README §1). Для приватного репо —
`docker build --secret id=hf_token,src=...` (в публичном bartowski токен не нужен).

## 5. Рекомендуемая правка compose (вместо существующего сервиса)

В блоке `llm` `prototype/infra/compose.yaml` заменить `image: ghcr.io/...` + `volumes:` на:

```yaml
  llm:
    build:
      context: .
      dockerfile: Dockerfile.llm
    image: ohw/llm:prototype
    profiles: ["llm"]
    container_name: ohw-llm
    networks: [ohw_net]
    ports: ["8080:8080"]
    # volumes — удалить (модель внутри образа)
    command:
      - "--model"
      - "/models/Qwen2.5-Coder-7B-Instruct-abliterated-Q4_K_M.gguf"
      - "--host"
      - "0.0.0.0"
      - "--port"
      - "8080"
      - "--ctx-size"
      - "8192"
      - "--n-gpu-layers"
      - "99"
    healthcheck: ...   # без изменений (но см. §6)
    <<: [*gpu, *logging]
```

Путь `/models/<файл>` в `command` уже совпадает с тем, куда Dockerfile кладёт модель, — совместимо с
текущей конфигурацией без других правок.

## 6. Известные оговорки (из ревью проекта)

1. **Одиночный `--profile llm build llm` упадёт** с `service "query-worker" depends on undefined service
   "config-service": invalid compose project` — кросс-профильные `depends_on` (pre-existing свойство файла).
   Рабочий обход: сборить с полным набором профилей, как в README §3. Постоянный фикс —
   `depends_on: {condition: service_started, required: false}` в 4 кросс-профильных блоках (проверено:
   валидацию compose проходит).
2. **Healthcheck** сервиса `llm` использует `python -c urllib…`, которого в образе llama.cpp теперь точно
   нет — при первом `up --wait` контейнер может застрять в `health: starting`. Заменить на TCP-пробу
   (`CMD-SHELL` + `/dev/tcp/localhost/8080`) или `curl`.
3. Кросс-профильная зависимость query-worker от `llm` сохраняется — при подъёме полного стека поведение
   не меняется.
