# Срез золотого набора: 8 вопросов с `golden_graph_evidence=true` (диагностика контура)

## Что это за срез

Восемь вопросов домена `it`, у которых в золотом наборе стоит `golden_graph_evidence: true`
и `evidence_policy: graph_required`. Граница среза задана полем, а не перечислением:
`it_graph_17 … it_graph_24` — это ровно те вопросы, которые несут флаг. Перечень
в `REVIEW-GATE.md` называл другой набор, из которого с флагом совпадал только `it_graph_17`
(расхождение зафиксировано в `infra/eval/slice-review-61050ae.md`).

`questions.jsonl` — **дословная копия** строк золотого набора `it/questions.jsonl`,
взятых по идентификаторам. Не правка и не сокращение: расхождение с эталоном здесь сделало бы
прогон бессмысленным.

## Критерий, объявленный до прогона

Прогон diagnostic-овский и **не является измерением**. Ниже — то, ради чего он делается, и то,
что в нём нельзя интерпретировать.

### Что прогон доказывает

Единственное, чего не даёт ни один другой способ: отделяет «модель не справилась» от
«контур не работает». Пока факты не сверены, эти две причины неразличимы. Успех прогона —
это контур, дошедший до конца:

1. прогон завершается end-to-end и отдаёт артефакты формы `docs/test_plan.md` §5–§6
   (`PASSPORT.md`, `run_manifest.json`, `ingest_report.json`, `qa_log.jsonl`/`qa_review.md`,
   `lift_report.json`, `preflight.log`, `failures.jsonl`);
2. `failures.jsonl` не содержит сбоев контура: сетевых ошибок, таймаутов, исключений пайплайна,
   потерянных событий;
3. по каждому вопросу видно события пайплайна и источники по осям — то есть форма ответа
   ожидаемая, а не «пусто непонятно почему».

### Что НЕ интерпретируется

- **`necessity` и любые числа графа.** Восемь вопросов написаны по проекту, а не измерены на
  стенде: `necessity` заранее не подтверждена ни для одного из них, а на усечённом корпусе
  (ниже) её величина не имеет смысла вовсе.
- **`recall@5` и `coverage`.** `golden_coverage` на этом корпусе **низкий по построению**:
  вопросы среза ссылаются на `docs/data_model.md`, `docs/invariants.md`, `docs/05_adr_log.md`,
  `docs/adapters_specification.md`, а корпус прогона — три других документа. По правилу
  `README-minimal.md` прогон на усечённом корпусе читается вместе с `golden_coverage`, и
  когда эталонные источники не попали в корпус, `recall@5` характеризует усечение, а не
  систему. Низкое значение здесь — следствие выбора дешёвого корпуса, а не находка.
- **Вердикт гейта.** Стенд прогона — оверлей `qwen2.5-3b`, а не документированный приёмочный
  (7B, проект `ohw-eval-docs-v1`). По `README-minimal.md` вердикт выдаётся на приёмочном
  стенде; всё, что получено здесь, — диагностика.

### Исключены из оценки: `it_graph_19` и `it_graph_22`

У обоих в `golden_facts` есть утверждение, что graph experiment разрешается «только ready и
актуальная `data_revision`». Это устарело: ADR-046 п.8 вывел `data_revision` из решения о
готовности, и код это фиксирует буквально — `ProjectionState.is_ready()` начинается с
`del data_revision` и смотрит только на `status` и `config_fingerprint`
(`ingestion_service/projection.py`). Провал по этим двум вопросам **не считается провалом
модели** и не идёт в оценку; сами вопросы при этом в прогоне остаются, чтобы был виден разбор.

### Если провал окажется систематическим

Провал на подтверждённых фактах — это дефект контура или схемы ответа, а не характеристика
модели, и он идёт **первым** в работу, а не в отчёт о качестве.

## Корпус и режим

Корпус — три документа (`api_reference.md`, `prototype_requirements.md`, `expert_reviews.md`):
дешевле, чем полный корпус `docs/`, и даёт ту же диагностическую ценность — «работает ли
контур». Извлечение съедает основную часть времени прогона, поэтому полный корпус здесь
не нужен.

Режим — `--retrieval-only --mode both`: обе ветки (vector-only и vector+graph expansion) без
генерации и без судьи. Контраст веток сохраняется, а самый дорогой слой не тратится.
Обе ветки используют одну ревизию, один chunking, одни embeddings и один K — различается
только graph expansion.

## Воспроизведение

```powershell
$env:RUN_CODE_COMMIT = (git rev-parse --short HEAD)
docker compose -p ohw-eval-qwen3b -f infra/compose.eval-minimal.yaml -f infra/compose.eval-qwen3b.yaml \
  run --rm --no-deps eval-runner python /app/infra/eval/run_eval.py \
  --domain it --mode both --retrieval-only \
  --corpus /repo/docs --source-prefix docs \
  --documents api_reference.md --documents prototype_requirements.md --documents expert_reviews.md \
  --dataset /app/infra/eval/pilots/golden-slice-graph/questions.jsonl \
  --out "/reports/slice-graph-$run"
```
