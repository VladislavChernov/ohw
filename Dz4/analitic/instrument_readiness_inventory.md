# Инвентаризация проверочных приборов стенда и готовности к замеру

**Команда:** codex  
**Дата:** 2026-10-04  
**Статус:** Аналитика (фаза: перед финальным eval-прогоном)  
**Язык:** русский

## 1. Введение

### 1.1 Контекст

Проект готовится к замеру на золотом наборе. Дорожная карта до замера — четыре бандла без
отметок, разбор которых начат 2026-10-03; параллельно стенд пересобирается, потому что образ
`ohw/eval-service:prototype` отстаёт от HEAD. По ходу разбора вскрылось, что часть проверочных
приборов читает **не тот набор входов, что код под ними**: счётчики опираются на сущности,
которые уже сняты, и потому не могут упасть. Это тот же класс, что прибор, который печатает
«найдено» без места нахождения, или `necessity = 0` при молчащей потере связей.

Запись отвечает на один вопрос: **какие приборы и проверки сейчас способны измерить то, для
чего они написаны, и какие дадут уверенный ноль вместо «не измеримо».**

### 1.2 Источники

- `docs/05_adr_log.md` — ADR-046 п.9 (снятие `Source`/`CONTAINS`), ADR-048 (гейт приёмки набора)
- `prototype/infra/eval/` — приборы стенда: `run_eval.py`, `run_e2e_cleanup.py`,
  `measure_projection_readiness.py`, `run_live_gate_check.py`, `run_stand_reload.py`,
  `slice_review_anchors.py`, `review_gate.py`
- `prototype/src/graphrag_proto/retrieval/adapters/inmemory.py`
- `docs/test_plan.md` §T1–T5 — сценарии уборки, задающие ожидания следующего E2E
- `openspec/changes/add-proposal-review-gate/review-records/data_revision_query_context_status.md`
- `prototype/infra/eval/slice-review-61050ae.md` — пакет ревью среза

### 1.3 Цель

Дать перечень приборов с указанием, какой из них измеряет, какой не может измерить по
причине снятой сущности, и что должно быть сделано до прогона, чтобы числа на выходе
можно было интерпретировать.

## 2. Исследованные материалы

Прочитаны: приборы в `prototype/infra/eval/`, строки 200–215 и 485–510 в

## 3. Анализ текущего состояния

### 3.1 `run_e2e_cleanup.py` считает снятое ребро как структурное (проверено)

Три места, где прибор оперирует `CONTAINS`:

- `:213` — `MATCH ()-[r:CONTAINS]->() WHERE r.domain = $domain RETURN count(r) AS c`
- `:502` — `structural_leaked = {t: c for t, c in candidates_by_type.items() if t in ("CONTAINS", "MENTIONS")}`
- `:506` — печать `CONTAINS {between}->{after}` в отчёте

ADR-046 п.9 снял ребро, и ни одна ось его не пишет. Значит `contains` всегда 0, а проверка
«структурные связи не пострадали» на его основе проходит тождественно: она не может упасть,
потому что измеряет величину, которая не меняется. Это не «проверка зелёная», это «проверки нет».

### 3.2 `docs/test_plan.md` T1–T5 задают проверку с тем же дефектом

Строки 661 и 689 (сценарий уборки, T2) требуют, чтобы число `CONTAINS` в снимке «после» равнялось
числу в снимке «между». При `CONTAINS = 0` условие истинно всегда. Отсюда же — расхождение 11 в
пакете ревью: строки тестплана задают проверку следующего E2E, которая не может выявить утечку,
потому что утекать нечему.

### 3.3 `inmemory.py:175` — остаток снятой конструкции (не проверено)

```python
if not (key[0] == arg and key[2] == "CONTAINS"):
```

Фильтр отбрасывает записи по типу ребра `CONTAINS`. Назначение не прочитано: возможно, это
защита от удаления структурной связи при уборке (тогда строка мертва), возможно — часть пути,
который ещё жив. Требует чтения функции целиком.

### 3.4 Ложные срабатывания, которые не считать дефектами

- `inmemory.py:8,36` — оператор `CONTAINS` языка Cypher (`WHERE toLower(n.x) CONTAINS toLower(t)`).
  К схеме отношения не имеет.
- `docs/test_plan.md:71` в `test_live_projection_neo4j_parity.py:71,74` — оператор `CONTAINS`
  в очистке тестовой базы.
- `test_eval_review_gate.py`, `suspended_symbols.py` — упоминания как объект проверки, а не
  как утверждение.

### 3.5 Что проверено и выглядит исправным

- `slice_review_anchors.py` — знаменатель выводится, факты без якорей помечаются явно;
  поиск якоря идёт как целое слово.
- `review_gate.py` — прямой запуск и импорт из тестов работают оба (после правки `sys.path`).
- `suspended_symbols.py` — реестр снятых сущностей в одном месте, как требует ADR-048 п.1.

## 4. Анализ предложений

| № | Предложение | Основание | Цена |
|---|---|---|---|
| 1 | Переписать `run_e2e_cleanup.py:213,502,506` на `MENTIONS` как единственное структурное ребро и добавить отдельное утверждение «`CONTAINS` не пишется ни одной осью» | §3.1 | малая |
| 2 | Переписать T1–T5 в `docs/test_plan.md` на ту же формулировку | §3.2 | малая |
| 3 | Прочитать `inmemory.py:170-180` и удалить фильтр, если он мёртв | §3.3 | малая |
| 4 | Завести гард-тест «прибор стенда не упоминает снятую сущность как действующую» наподобие `review_gate.py`, но для приборов | §3.1, §3.2 | средняя |
| 5 | Проверить `run_eval.py` целиком на тот же дефект (не прочитано) | §2 | большая |

Предложение 4 — то, что закрывает класс. Предложения 1–3 закрывают найденные экземпляры.
Предложение 5 не сделано и остаётся самым вероятным источником расхождения: `run_eval.py`
не читал ни один из нас.

## 5. Рекомендации

1. **До пересборки образа и прогона:** предложения 1–3. Это правки документации и одного
   прибора; без них прогон даст «уборка не сломала структурные связи» на основании величины,
   которая не может измениться.
2. **После прогона, до интерпретации чисел:** предложение 4. Как только приборы начнут
   использоваться как основание для выводов, они должны иметь гард на снятые сущности —
   иначе следующее снятие снова пройдёт незамеченным.
3. **Отдельно и позже:** предложение 5.

## 6. Итог

Три прибора из числа рассмотренных способны измерять то, для чего написаны
(`slice_review_anchors.py`, `review_gate.py`, `suspended_symbols.py`).
`run_e2e_cleanup.py` — нет: он измеряет снятую сущность, и его проверка структурных связей
проходит тождественно. `docs/test_plan.md` как задание для следующего E2E содержит ту же
дыру в двух строках. `run_eval.py` не проверен и остаётся главным неизвестным.

**Что здесь не измерено.** `run_eval.py` целиком (предложение 5) не прочитан; `inmemory.py`
прочитан не в объёме, позволяющем судить о жизни фильтра; `docs/test_plan.md` прочитан в
сценарии уборки, а не по всему объёму. Любой вывод «все приборы проверены» был бы здесь
неправдой: проверены четыре из шести, и один из четырёх — отрицательно.
