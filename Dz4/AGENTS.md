## 1. Дисциплина проверки

**Артефакт без критерия — это лог.** Прогон не попадает в git, если для него заранее не
записано «что проверяем» и «что считаем успехом». Иначе через месяц это дорогие буквы.
Критерий пишется первым пунктом работы, а не после первого провала.

**`n = 1` — не результат.** Один документ, один прогон, одна модель — этого хватает, чтобы
отбросить гипотезу, и не хватает, чтобы её принять. Наблюдение, подтверждённое дважды на
разном материале, — результат.

**Примеры в промтах опаснее, чем кажется.** Недообученная модель копирует пример дословно.
Выдуманное в примере соглашение об именах становится соглашением модели и ломает всё
ниже по цепочке. Никогда не вводить в пример формат, которого нет в онтологии и корпусе —
даже в запрете: упоминание тоже прививает.

**Тест вместо документации.** Если ошибка класса «можно сделать, но заметно» — закрывать
тестом, а не записью в доке. Документация не мешает повторить, тест мешает.

**Отмечать опровергнутое.** В исследовательской части проекта ценнее список «что
исключено», чем список «что сделано». Гипотеза, не подтвердившаяся на втором материале,
должна быть записана как опровергнутая, а не тихо выброшена.

**Решение принимается при давлением наблюдений — записывать с честным статусом.**
Формулировка «принято, исполнено частично» лучше, чем уверенное описание того, чего ещё
нет. ADR, написанный под давлением, должен это признавать сам.

## 2. Развилка «дёшево или дорого»

Правку, которую можно проверить на разогретом окружении без пересборки, делать сразу.
Правку, требующую пересборки, изменения схемы или миграции — выключать окружение и
идти в основной контур.

Перед экспериментом дешёво проверить, что он вообще возможен: смонтирован ли изменяемый
файл в контейнер (`docker inspect --format '{{json .Mounts}}'`), не требует ли правка кода.

Эксперимент на прогретом окружении даёт ответ за минуты и стоит в разы дешевле, чем
рефлексия по логам. Но только если критерий сформулирован до прогона.

## 3. Git

- Гейт (линтер + типы + тесты) — до коммита, всегда.
- `git add` по явным путям, не `-A`: в репозитории есть артефакты и служебные файлы,
  которые не должны попадать в коммит молча.
- Коммит не делается без прямой просьбы.
- Артефакты экспериментов — отдельным коммитом, с вердиктом в сообщении.

## 4. Windows и PowerShell

| грабля | что делать |
|---|---|
| порча кириллицы при записи | только `[System.IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding $false))`, чтение через `[System.IO.File]::ReadAllText(path, [Text.Encoding]::UTF8)` |
| не проверил, что текст цел | после правки `FFFD == 0` и `?{4,} == 0` |
| `git commit <<EOF` | PowerShell не умеет heredoc: писать сообщение в temp-файл и `git commit -F` |
| `Set-Content` даёт CRLF | ломает `tail -40` внутри скриптов; файлы писать без CRLF |
| вложенные кавычки в `sh -c` | парсер ломается: писать `.sh` файлом и `docker cp` в контейнер |
| `-Recurse` по каталогу с `node_modules` | вывод на десятки тысяч строк; фильтровать или `-Depth` |

## 5. Docker

- Гасить окружение через `docker stop`, не `down -v`: в томах лежат модели и артефакты.
- Одно тяжёлое окружение за раз: два стенда с моделями делят RAM и начинают мешать.
- Изменение файла, смонтированного в контейнер, видно без пересборки — это дешёвый контур
  для экспериментов с конфигурацией и промтами.
- `grep` по кириллице внутри контейнера молчит из-за локали. Отсутствие вывода не значит,
  что файл не обновился: сверять размер или число строк.
- Порт сервиса внутри сети не публикуется наружу: искать слушающие порты в
  `/proc/net/tcp`, а не угадывать.

## 6. Dz4

**Гейт** (из dev-контейнера `ohw-dz4-dev`, репозиторий смонтирован в `/repo`):

```
docker exec ohw-dz4-dev sh -c 'cd /repo/prototype && uv run --no-sync ruff check . && uv run --no-sync mypy src'
docker exec ohw-dz4-dev sh -c 'cd /repo/prototype && uv run --no-sync python -m pytest -q -p no:randomly'
```

**Стенд LLM** (`compose.yaml` + `compose.eval-qwen3b.yaml`):
- контейнеры называются `ohw-eval-qwen3b-<service>-1`, не `ohw-eval-qwen3b`;
- внутренний порт ingestion-api — **8002**, ключ в `AUTH_API_KEY`;
- `domain_profiles` смонтирован `:ro`, правки профиля видны без пересборки;
- `LLM_EXCHANGE_LOG=off|meta|response|full`, файл журнала в томе `ingestion_data`.

**Пробник извлечения** `prototype/infra/eval/inspect_llm_exchange.py`, запускается внутри
контейнера ingestion-api. Обязательные переменные: `INGESTION_URL`, `API_KEY`,
`CORPUS_DIR`, `ARTIFACTS_DIR`, `EXCHANGE_LOG`, `EXTRACT_LLM=true`, `PROBE_SOURCES`.
Для самодостаточного артефакта: `PROBE_VARIANT`, `PROBE_HYPOTHESIS`, `PROBE_CRITERION`,
`PROBE_CODE_VERSION` — они пишутся в `manifest.json`.

**Где что лежит:**
- спецификация до кода: `openspec/changes/<имя>/` (`proposal.md`, `tasks.md`, `design.md`,
  `specs/`), сводка — `openspec/project.md`;
- решения и их статус: `docs/05_adr_log.md`;
- артефакты прогонов: `test_artifacts/<эксперимент>/` с README, объясняющим вердикт;
- состояние для следующей сессии: `NEXT_SESSION_INSTRUCTIONS.md`.

**Правила предметной области, которые нельзя нарушать молча:**
- `source_url` и `chunk_id` — границы удаления (ADR-005);
- факты — отдельными таблицами, версия схемы в `meta` (ADR-038);
- неразрешённая ссылка — запись, а не отказ документа (ADR-037);
- русский текст в `docs/` и комментариях — UTF-8, проверять после записи.
