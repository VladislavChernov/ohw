# CONTRIBUTING

Репозиторий `Dz4` — **документационный** проект: он описывает архитектуру платформы GraphRAG
(слой адаптеров, Domain Profile, асинхронный контур) и не содержит исполняемого кода.
Единый источник правды — `CONCEPT.md` (база v5); актуальная картина архитектуры — `docs/00_hi_level_architecture.md` (v6).

## Как вносить изменения

1. **SSOT-первичность.** Сначала правится источник, затем производные документы. Если меняется
   архитектурное решение — оформите запись в `docs/05_adr_log.md` (ADR) и только потом отразите
   его эффект в остальных документах.
2. **Цепочка влияния.** Изменение концепции проходит путь: `CONCEPT.md` → `docs/00_hi_level_architecture.md`
   (Mermaid-схема + SSOT-таблица) → детальные документы `docs/01`–`docs/06` → справочники
   (`glossary.md`, `api_reference.md`, `data_model.md`, `adapters_*`) → README.
3. **Новый документ** добавляется в три точки навигации: таблицу `docs/README.md` (и «Как пользоваться»),
   таблицу корневого `README.md` и, при необходимости, «Связи с другими документами» в `docs/history.md`.
   Файл, на который никто не ссылается, — незавершённая работа.
4. **Версии и шапки.** Каждый документ содержит `Версия` и `Последнее обновление`.
   Версия увеличивается при изменении содержания; дата обновляется при каждой правке файла.
5. **Ссылки** — только на реальные файлы и существующие номера разделов (§N).
   Битые ссылки и упоминания несуществующих документов (например, `CONTRIBUTING.md` без файла) — ошибка, а не мелочь.
6. **Mermaid правится в `docs/00_hi_level_architecture.md`** — текст схемы первичен. PNG
   (`docs/assets/hi_level_architecture_v6.png`) перегенерируется после любого изменения схемы;
   расхождение текстовой и растровой схем недопустимо.
7. **Архивы не трогаем.** `docs.zip`, `docs/history/v4/`, `docs/history/v6/` — исторические срезы.
   Правки вносятся только в актуальные документы.
8. **Код-фенсы.** Экранированные бэктики в Markdown запрещены. Чётное число тройных бэктиков (```) в файле —
   обязательная pre-commit проверка.
9. **Перед pull request** проверьте: связность ссылок, чётность код-фенсов, актуальность таблиц навигации.

## Issues и pull requests

- Ошибка в документации (битая ссылка, рассинхрон с SSOT, устаревший раздел) — Issue с меткой `docs`.
- Архитектурный сдвиг — сначала ADR в `docs/05_adr_log.md`, затем PR с изменениями документов.
- Конфликт трактовок решается в пользу `CONCEPT.md`; разногласия обсуждаются в диалоге, а не перезаписью.

## Обратная связь

Координаты команды технической поддержки и регламент обращения — заполняются владельцем репозитория
(см. раздел «Лицензия и Поддержка» в `README.md`).
