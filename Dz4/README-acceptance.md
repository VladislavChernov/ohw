# Приёмка: что измеряется и почему

Короткая карта для того, кто открывает проект. Не руководство: здесь только **что именно мы
считаем и какие числа зачем**. Подробности — по ссылкам внизу.

Документ лежит в корне, а не в `docs/`, по существенной причине: `docs/` — это корпус, который
система ингестит. Файл о приёмке, положенный в корпус, меняет то, что система ест, и может
сдвинуть результаты retrieval посреди ревью эталонов.

## Одним абзацем

Система отвечает на вопросы по документации проекта. Вопросы лежат в золотом наборе. Правильность
ответа решает человек — это источник истины. Вопрос «правильный ли ответ» нельзя закрыть полностью
автоматикой, поэтому приёмка состоит из машинной части по всему набору и человеческой по части
набора.

## Схема

```
ЗОЛОТОЙ НАБОР                    74 вопроса
│
├─► система отвечает               прогон раннера по всем 74
│    считает машина                цитаты, groundedness, вклад графа
│
├─► ПОЛОВИНА КРИТЕРИЯ №1           сканирование имён по всем 74
│    «ноль выдуманных имён»        машина находит кандидатов, решение — человек
│
└─► ПОЛОВИНА КРИТЕРИЯ №2           36 вопросов  ← это число выбирается
     «каждое утверждение             человек читает глазами
      подтверждено цитатой»
     │
     └─► замер стоимости            13 вопросов — чтобы понять, по силам ли 36
```

## Три числа

| число | что это | кто решает | где описано |
|---|---|---|---|
| **74** | размер золотого набора: сколько вопросов пишется и по чему система оценивается | история набора, нижняя граница 50 задана ADR-015 | `prototype/infra/eval/README-dataset.md` |
| **36** | размер усечённого набора для ручной приёмки: сколько человек читает глазами | выбор ставки отбора, см. ниже | `prototype/infra/eval/README-dataset.md` |
| **13** | проба для замера стоимости разбора | выбирается так, чтобы попасть в каждый класс стоимости | `prototype/infra/eval/README-dataset.md` |

**74 и 36 — не одно и то же.** 36 — подмножество 74. Остальные 38 оценивает LLM-судья, который
работает как эксперимент, а не как истина.

**74 может измениться, но не через отбор.** Если при ревью факты у вопроса окажутся неверными,
вопрос заменяется или уходит. Это исправление неправильного эталона, а не выбор размера выборки.
Сейчас не прошли ревью ни один из 74: у 71 из них хотя бы один источник менялся позже даты,
указанной в самом вопросе.

## Что решено, а что открыто

| вопрос | состояние |
|---|---|
| золотой набор — один файл, а не два | решено, ADR-040 |
| какие 14 вопросов обязательны к прочтению | решено: все, где вклад графа не подтверждён, плюс самые рискованные типы |
| как отбирать остальные вопросы | решено: равномерный шаг по каждой категории, не более трети, но не меньше одного |
| по чему считается приёмка | решено: каждое утверждение подтверждено или явно не подтверждено, плюс ноль выдуманных имён |
| сколько времени есть на разбор | **предварительно**: `W=1`, `R=5`, `M=300`, `O=60` → `B ≈ 1440` мин. Значения на глаз, не измерены, и `W` убывает |
| успеете ли вы 36 вопросов | **открыто**, измеряется на 13. При `B ≈ 1440` порог невысокий: уложитесь в 19 минут на вопрос — разбираете все 74 |
| правильны ли сами эталонные факты | **открыто**, ревью обязательно до финального прогона |

## Единственное правило, которое нельзя нарушать

**Всё, что влияет на оценку, фиксируется до того, как прочитаны ответы.**

Иначе оценка превращается в подгонку: сначала смотрим результат, потом под него подбираем правило.
Проект с этим уже сталкивался — порог по хабам пришлось отменить именно потому, что его выбрали
после того, как увидели числа.

Отсюда порядок работ: зафиксировать критерий → разведочный прогон → ревью → финальный прогон.
Ревью после разведки нужно, чтобы судить не на выдумках; ревью после финального бессмысленно,
потому что уже не на что повлиять.
