# Proposal: Отбор кандидатов по пересечению сущностей вопроса

**Статус:** предложение, решение НЕ принято, код не пишется. Основание — ADR-072.

## Суть

Отбор по сущностям вопроса существует, но стоит не там, где нужен. Он применяется к строкам,
прошедшим срез обхода, тогда как применять его надо к каждому кандидату целиком — по его
собственным `context_ids`. Обход при этом не нужен вовсе: свойство уже лежит на чанке.

## Проблема, измерено

Критерий ADR-070/071: ось графа должна принести источник, которого нет в векторной выдаче.
Замеряно дважды — не выполнено.

| | результат |
|---|---|
| повторяемость осей | да (детерминированность ADR-070 достигнута) |
| новых источников от графа | **нет ни одного** |
| retrieval, с | 3.0, стабильно |

Две причины, обе установлены:

1. **Вопрос был не тот.** Замер шёл на `ready_B1/E1a/E1b` (Topology Orchestrator) и
   `ready_B2` (переключение хранилища). Ни один не называет `05_adr_log` и ни один не требует
   идти от одного решения к другому. Вопрос, который требует, в полном наборе один:
   `it_graph_23` — «ADR-031 вывел механизмы типизированной онтологии из ingest path…».
   В срез демо он не входит.
2. **Отбор стоит после среза.** Подтвердить могут не более `max_graph_nodes` сущностей; всё
   остальное получает одинаковое понижение. На вопросе про Topology Orchestrator подтверждений
   не набирается вовсе — в тексте нет ни одного `ADR-0xx`.

## Что предлагается

1. Считать пересечение сущностей вопроса по каждому кандидату целиком — векторные и мостовые
   чанки, — используя `chunk.context_ids`. Обход в этой проверке не участвует.
2. Обходу оставить одну роль: найти кандидатов из документов, которых вектор не нашёл.
3. `EXPANSION_CANDIDATE_MULTIPLIER` (ADR-071) после этого становится лишним: он существовал
   только чтобы обойти неверное место отбора.
4. В срез демо добавить вопрос, требующий цепочки решений, — иначе измерять нечего.

## Открытые вопросы — до них код не пишется

- **Мягкость отбора.** У нас понижение ×`filter_demote_scale`, в чужом методе — жёсткий
  отсев по порогу. Переносить жёсткость без замера нельзя: константа уже стоила нам
  `recall@5 −0.0417` (`graph_boost`).
- **Чем измерять.** Критерий пишется ДО прогона. Без критерия правка отбора вслепую.
- **Какие сущности из вопроса.** Сейчас это подстрочный поиск имени в тексте вопроса. Это
  дешёвый приблизитель; полноценное выделение сущностей — отдельная работа.

## Чего это не чинит

- Потерю LLM-слоя на больших объёмах (ADR-066).
- Пустой граф у `02_pipeline_and_normalizer`, `06_operations_and_risks`,
  `connectors_guide`, `defense_notes_simplifications`. Ручная разметка покрывает один
  документ из пяти, поэтому ось графа физически не может принести второй документ, пока
  разметка не расширена.
