# Tasks: операторская кнопка запуска обслуживания

Порядок обязателен: клиентский метод и его тест идут раньше разметки, потому что разметка без
проверяемого вызова нечем тестировать.

- [ ] LP-01. Клиентский метод вызова обслуживания в `demo_ui/client.py`: маршрут
  `POST /api/v1/maintenance/orphan-cleanup`, тело `{domain}`, заголовок `X-API-Key`. Без Streamlit.
- [ ] LP-02. Разбор ответа: `job_id`, `domain` и подсчёты удалённого. Подсчёты обязательны: пустой
  ответ или ответ без них — повод показать оператору «нечего удалять», а не «готово».
- [ ] LP-03. Юнит-тест метода: маршрут, тело, заголовок, разбор ответа, и отдельно — поведение при
  пустом ответе.
- [ ] LP-04. Разметка вкладки «Обслуживание» в `demo_ui/app.py`: выбор домена из уже используемого
  списка, **до** запуска видно, что будет удалено, и виден идентификатор прохода.
- [ ] LP-05. После запуска показывать фактические подсчёты из ответа, а не только факт вызова.
- [ ] LP-06. Юнит-тест разметки: до нажатия видно, что удаляется; после — подсчёты из ответа.
- [ ] LP-07. Инструкция в `docs/demo_user_guide.md`: что такое обслуживание, когда запускать, чего
  ждать, и чего оно **не** делает — в частности, не удаляет `Source`-ноды (ADR-046).
- [ ] LP-08. Проверить регистрацию инструкции в линтерах документации: документ вне гейта тихо
  расходится — это уже случалось с картой приёмки.
- [ ] LP-09. Полный `pytest`, `ruff`, `mypy` в persistent dev-контейнере с host `RUN_CODE_COMMIT`.
