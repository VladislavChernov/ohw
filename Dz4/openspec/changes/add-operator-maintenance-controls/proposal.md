# Proposal: операторская кнопка запуска обслуживания

**Статус:** предложение (2026-10-02; решение владельца — завести). Код и runtime не изменяются
до принятия бандла.

## Зачем

Планировщика уборки нет **намеренно**: `POST /api/v1/maintenance/orphan-cleanup`
(`ingestion_service/app.py:489`) удаляет данные из графа, цена ошибки — молчаливая потеря, поэтому
момент запуска выбирает оператор. Право запуска существует, но добраться до него можно только зная
адрес маршрута и формат тела запроса.

Для учебного прототипа это означает худшее: возможность, которая в демонстрации **не показывается**.
Зритель видит систему, у которой есть обслуживание, и не видит, как им воспользоваться. Демо-UI уже
умеет загружать документ, удалять его и задавать запрос — операторские действия в нём есть, а
обслуживания в нём нет.

## Что делаем

1. **Клиентский метод** в `demo_ui/client.py`: вызов обслуживания по домену. Без Streamlit, чтобы
   он юнит-тестировался так же, как остальные вызовы (в `client.py` уже выбран именно этот порядок:
   HTTP вынесен из UI, чтобы он проверялся тестом).
2. **Кнопка в UI.** Новая вкладка «Обслуживание» рядом с «Документы» и «Запросы»
   (`demo_ui/app.py:348`). Показывает: что будет удалено, кнопку запуска и результат — что именно
   удалено, с подсчётами из ответа маршрута. Домен берётся из уже выбранного, новый выбор не
   заводим.
3. **Инструкция оператора** в `docs/demo_user_guide.md`: что такое обслуживание, когда его
   запускают, чего от него ждать и чего он **не** делает. Отдельно — что уборка не удаляет
   `Source`-ноды (ADR-046), иначе оператор будет ждать результата, которого не бывает.

## Почему так, а не иначе

**Кнопка без указания, что именно будет удалено, опаснее отсутствия кнопки.** Уборка удаляет
данные без возможности отката, поэтому до запуска должно быть видно, к чему она приведёт. Маршрут
уже поддерживает это: он возвращает `job_id` и подсчёты. UI обязан показывать их, а не только
сообщать «готово».

**Отдельная вкладка, а не кнопка в сайдбаре.** Сайдбар в UI занят подключением к сервисам; обслуживание
меняет состояние графа, а не параметры запроса, и смешивать их нельзя.

**Инструкция обязательна вместе с кнопкой.** Документ о приёмке лежит в корне и регистрируется в
линтерах по той причине, что вне гейта он тихо расходится; здесь та же опасность: кнопка без
инструкции даёт возможность, о которой никто не знает, — то есть на демонстрации будет сделано
всё, кроме неё.

## Проверка

1. Юнит-тест клиентского метода: маршрут, домен, `X-API-Key`, разбор ответа с подсчётами.
2. Юнит-тест разметки: до нажатия видно, что будет удалено, и виден идентификатор прохода; после —
   фактические подсчёты из ответа.
3. Полный `pytest`, `ruff`, `mypy` в dev-контейнере с host `RUN_CODE_COMMIT`.
4. Инструкция в `docs/demo_user_guide.md` проходит регистрацию в линтерах.

## Вне scope

- Планировщик или автоматический запуск по расписанию: цена ошибки молчаливая, решение принято.
- Уборка `Source`-нод: это ADR-046, здесь только упоминание в инструкции.
- Разрешения и роли оператора: прототип однопользовательский, `X-API-Key` общий.
