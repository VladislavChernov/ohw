# Задачи

Порядок обязателен: приборы идут **до** выбора лечения, запись — **до** кода, порядок —
**до** кода. Нарушение этого порядка в проекте уже стоило нескольких замеров.

Состояние на 2026-10-17. Разделы 1 и 2 выполнены и проверены гейтом; раздел 3 — принятые
решения без кода; раздел 4 — код, который ещё предстоит написать.

- [x] `ContextResult` отдаёт `skeleton_tokens` и `body_tokens` раздельно, а не только сумму

      `skeleton_tokens`, `body_tokens`, `total_tokens`, `max_tokens`, `skeleton_token_share`

- [x] На кэш-попадании блок равен `null`, а не нулям
- [x] Сводка рукава `context_assembly`: `measured` / `cache_only` / `not_assembled`,
      `questions_unknown`, `questions_with_evidence_lines`
- [x] Ручка измерения `RETRIEVAL_EVIDENCE_MAX_LINES`: `None` — без ограничения, `0` — блока нет;

## 3. Принятые решения — ЗАПИСАТЬ (кода нет)

- [ ] **Порядок выдачи.** Реранкер задаёт порядок на основном пути; RRF — запасной путь, когда
      реранкер выключен. Они не строятся оба: кросс-энкодер даёт сопоставимую оценку каждому
      кандидату, и после этого слияние списков перестаёт быть нужным
- [ ] **Условие возврата RRF** записать явно: RRF возвращается как дешёвое сужение **перед**
      реранкером, когда кандидатов станут сотни, а не десятки. Порог не измерен — записывается
      условие, а не число
- [ ] **Фильтр — на старте мягкий.** Отклонения понижают оценку и пишутся в артефакт, а не
      выбрасывают кандидата. Причина: поле `canonical_name` местами равно целой фразе, и жёсткий
      фильтр по нему тихо съел бы эталонный документ
- [ ] **Контроль для лексических механизмов — греп, а не текущее состояние системы.** Мост
      и фильтр работают в лексическом классе, а на нашем корпусе keyword_grep находит те же
      документы, что и ось графа. Единственный нелексический шаг — реранкер
- [ ] **Порог по абсолютной оценке не включается.** Шкала `bge-reranker-base` сжата (0.001 / 0.31 /
      0.00004 на замере 2026-10-17); годится только порядок. Порог калибруется на наборе
- [ ] **`namespaces.yaml` объявляет `reranker: "bge_reranker"`, а все compose — `noop`.** Два
      источника правды расходятся, и env всегда перебивает каталог. Решить, что из них
      выражает СОСТОЯНИЕ ПО УМОЛЧАНИЮ, а что — ВКЛЮЧЕНИЕ

## 4. Код — ПИСАТЬ

### 4.1 Мост (реализован)

- [x] Метод порта хранилища: чтение текста чанка по списку `chunk_id`
- [x] Реализация в Neo4j (`Chunk.text` уже пишется при ингесте) и в InMemory
- [x] Пайплайн превращает строки обхода в кандидатов **с текстом**, а не в имена
- [x] Гард-тест: чанк, собранный обходом, читается по своему `chunk_id` — тест собирает связь
      так, как её собирает обход
- [x] Гард-тест: `None` (возможности нет) и `[]` (прочитанного нет) различимы в артефакте
- [x] Гард-тест: мост не выдаёт оценку — проверяется на чанке у ранжирования, а не на
      `relevance` источника, потому что константу оси ставит `build_sources` и это задача
      плагина, а не моста
- [x] Попутно исправлен баг: Neo4j-мост возвращал порядок `sorted(found)`, хотя комментарий
      обещал порядок обхода

### 4.2 Фильтр (реализован)

- [x] Отсечение кандидатов по пересечению сущностей с запросом, **мягкое**: понижение + запись
- [x] Счётчик и список отклонённых кандидатов в артефакте
- [x] Гард-тест: кандидат с нулевым пересечением понижен, а не выброшен, и оба случая видны
- [x] Гард-тест: имя-фраза не участвует в отборе и попадает в счётчик
- [x] Гард-тест: при выключенном графе фильтр не трогает ничего
- [x] Гард-тест: масштаб вне (0, 1] отвергается — понижение не превращается в подъём
- [x] Ключ объявлен в `READ_BY_RETRIEVAL_KEYS`, диапазон проверяется контрактом профиля

## 4.5 Осталось открытым

- [ ] **Откалибровать `filter_demote_scale`.** Само число откалибровать нечем без прогона на
      золотом наборе — это работа, требующая стенда. Что сделано вместо этого: величина едет в
      артефакте **вместе со статусом** `filter_demote_scale_status`, и дефолт помечен
      `uncalibrated_placeholder`, а значение из профиля — `profile`. Заглушка больше не читается
      как решение. Гард есть.
- [x] **Что показывать у источника без кандидата.** Решено ADR-064: `relevance` — свойство
      источника; нет кандидата — `None` с basis `none`; `graph_source_relevance` снят вместе с
      константой; метка `graph_knowledge` перенесена с оси на источник, и обе записи одного
      источника больше не могут противоречить друг другу
- [ ] **Выигрыш переранживания не измерен.** Работает и отвечает корректно, но насколько подняло
      `recall@5` — неизвестно до прогона на золотом наборе

## 4.6 Идея к обсуждению (не решение)

- [ ] **Руками размеченный граф — не артефакт разметки.** Решение владельца 2026-10-18:
      нормально настроенный ингест даст то же самое, поэтому ручная разметка меряет
      **механизм графа**, а не дефект записи. Объявление об этом сделано в `Demo/README.md`,
      обязательной последней фразой: такие связи не доказывают, что система производит их
      сама
- [ ] Наполнить граф кросс-документными связями и прогнать вопросы. Требует стенда.
      Признак `origin: "user"` уже поддержан хранилищем: ручная связь помечается им, и
      машинная запись её не перезаписывает (`neo4j.py`, `preserve_manual`). Осталось решить
      количество и типы связей
