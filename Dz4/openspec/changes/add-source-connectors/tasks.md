# Задачи

> План-бандл: **реализация отложена**. Задачи ниже декомпозируют будущий бандл
> «add-source-connectors-impl»; отмечать `[x]` — только при фактической реализации.

## 1. Контракт источника (фетчинг)

- [ ] 1.1. Ввести интерфейс `SourceProvider` (ABC): `fetch(source: SourceRef, creds) -> bytes`,
      где `SourceRef {source_url, domain, doc_type}`. Транспорт (HTTP, auth, пагинация) —
      ответственность коннектора; формат — ответственность `DocumentReader` (ADR-021).
- [ ] 1.2. Коннектор реализует `fetch` и регистрирует свой `doc_type`; в ядро код
      коннектора НЕ попадает (внешний/соседний модуль).

## 2. Регистрация коннекторов

- [ ] 2.1. Зарегистрировать коннектор в реестре источников по `doc_type`
      (аналогично PDF-паттерну в `registry.py`): `factory(doc_type)` отдаёт ридер,
      коннектор — до ридера, пишет материал в `runtime/uploads/{job_id}.{doc_type}`.
- [ ] 2.2. (Опционально, поздняя эволюция) слот `source` в топологии
      (`infra_topology.yaml` + Adapters Management API) — переключение активных
      источников на лету, в духе M3.

## 3. Ingestion API

- [ ] 3.1. Не менять существующий `POST /api/v1/ingestion/documents` (push): остаётся
      совместимым; коннекторы НЕ трогают ядро пиплайна.
- [ ] 3.2. При необходимости — отдельный эндпоинт `POST /api/v1/ingestion/sources/{id}/pull`
      (или фоновый планировщик) для pull-режима.

## 4. Тесты

- [ ] 4.1. Контрактные тесты коннектора: fetch → содержимое → `Document` (через ридер)
      → content_hash идемпотентен (ADR-014); защитит регрессионный прогон `pytest`.
- [ ] 4.2. Повторный INGEST с тем же `source_url`/`content_hash` — dedupe, без дублей
      в Document Registry.
