# Design: add-source-connectors (планирование, без кода)

## Контекст и терминология

- **Транспорт vs формат.** Две разные ответственности:
  - *коннектор / фетчер* — вытаскивает данные из внешней системы по её API
    (Jira REST, TestRail API, Confluence REST/Atlassian Documents);
  - *ридер* — парсит локальный `Path` в канонический документ (`DocumentReader`, ADR-021);
    источник-агностичен.
- **Точка присоединения сегодня** — препроцессинг перед существующим push-путем Ingestion
  API (:8002, ADR-018): коннектор материализует данные в файл, дальше всё по существующему
  коду (`app.py` → `Executor.start` → `IngestStage.read`), реестр ридеров и пайплайн не
  меняются.

## Ключевые решения

1. **Корневой сдвиг — на входе, а не в пайплайне.** Пайплайн INGEST→COMMIT работает
   только с каноническим документом и источник-агностичен (ADR-021). Коннектор существует
   до пайплайна: материал → ридер → канонический документ. Это обеспечивает «безболезненную
   встройку»: никаких правок INGEST/CHUNK/.../COMMIT, регистра, `ALLOWED_DOC_TYPES`.
2. **Два варианта подключения:**
   - *(сегодня, рекомендация)* materialize-first: коннектор тянет данные ремоут-системы и
     кладёт в `runtime/uploads/{job_id}.{doc_type}` (или вызывает `POST /documents` с
     `content`), реестр ридеров подхватывает новый `doc_type` (например «wiki», «jira»)
     без изменения ядра;
   - *(задел, будущая эволюция)* контракт `SourceProvider.fetch(...)` + (опционально) слот
     `source` в топологии для переключения активных источников на лету.
3. **Идемпотентность** — за счёт `content_hash` по каноническому виду (ADR-014): повторный
   INGEST того же источника не плодит дубли; жизненный цикл (soft-delete, версии) уже
   реализован и действует на источники любой системы.
4. **Безопасность** — креды коннекторов во внешнем секретохранилище / env, не в ядре
   (`docs/security.md` §3). Транспорт всегда HTTPS; красакция секретов в логах.
5. **Структурно — как PDF-паттерн:** коннектор — соседний модуль рядом с
   `ingestion_service` (аналогично `readers/pdf.py`), регистрация через реестр
   `factory(doc_type)`, без изменения файлов ядра.

## Модули (на будущую реализацию, НЕ создаются сейчас)

```
prototype/src/graphrag_proto/ingestion_service/
  connectors/
    base.py        # ABC SourceProvider (fetch -> bytes)
    registry.py    # реестр коннекторов по DocType
    jira.py        # пример коннектора Jira (будущий бандл, не теперь)
    testrail.py    # пример коннектора TestRail (будущий бандл, не теперь)
    confluence.py  # пример коннектора Confluence/Wiki (будущий бандл, не теперь)
```

## Не-регрессия

- `POST /api/v1/ingestion/documents` (push) — контракт без изменений.
- `registry.py::factory`, этап INGEST, Document Registry, soft-delete — не трогаются.
- M3-адаптеры (слоты graph_store / vector_store / embeddings / reranker / llm) — ортогональны:
  источник коннектится до пайплайна, адаптеры — внутри пайплайна.
- pytest/ruff/mypy — зелёные (в этом бандле код не меняется).
