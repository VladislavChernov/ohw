# Delta Spec: demo-readiness-gates

## ADDED Requirements

### Requirement: Процесс загрузки создаёт граф, а не только вектор

Загрузка документа обязана доходить до графа без ручной подготовки. Решение владельца:
процесс, создающий только вектор, — это проблема процесса, а не повод предъявлять
пользователю требование подготовить папку с кандидатами.

#### Scenario: Документ загружен из UI

- **WHEN** пользователь выбрал файл в UI ингеста и дождался завершения джобы
- **THEN** в графе появились `ContextNode` и связи для этого документа; отсутствие любого
      из них означает, что процесс не отработал, и это обязано быть видно как отказ

#### Scenario: Кандидатов для документа нет

- **WHEN** для загружаемого документа не найден файл `<документ>_candidates.json`
- **THEN** процесс либо получает кандидатов сам, либо объявляет ненастроенность конвейера
      с поимённой причиной; молчаливый переход в `vector_only` со статусом `succeeded`
      недопустим для пользовательского пути

#### Scenario: Кандидаты устарели

- **WHEN** `sha256` кандидатов не совпадает с хэшем текста документа
- **THEN** это отказ, а не предупреждение: работа по чужому списку даёт правдоподобный, но
      неверный граф

#### Scenario: Различие двух видов отсутствия кандидатов сохраняется

- **WHEN** `CANDIDATES_DIR` не задан вовсе
- **THEN** это ошибка конфигурации конвейера, а не режим `vector_only`

### Requirement: Готовность объявляется по наполненности, а не по исполняемости

Критерий готовности прототипа (`docs/prototype_requirements.md` §8) обязан включать
проверку того, что база наполнена. Пройденные стадии при пустом результате этому не
равны.

#### Scenario: Пайплайн исполнился, но нод нет

- **WHEN** все джобы в статусе `succeeded` и стадии отработали
- **THEN** гейт готовности не пройден: в базе нет `ContextNode` и связей

#### Scenario: Гейт наполнения проверяет три условия независимо

- **WHEN** объявляется готовность
- **THEN** в базе есть `ContextNode`, есть связи, и ни одна джоба не в статусе `failed`;
      нарушение любого из трёх означает неготовность

#### Scenario: Знаменатель наполнения объявлен

- **WHEN** гейт считает наполненность
- **THEN** рядом с числом нод объявлено число загруженных документов; нулевой результат при
      ненулевом числе документов и нулевой результат при пустом корпусе — разные результаты,
      и оба должны быть названы

### Requirement: Метрики готовности считаются на полном золотом наборе

Готовность объявляется по полному набору. Срез, нужный для отдельного вопроса о вкладе
графа, не заменяет набор.

#### Scenario: Метрика посчитана на срезе

- **WHEN** метрика groundedness или coverage посчитана только на вопросах с
      `golden_graph_evidence: true`
- **THEN** результат не является основанием объявлять готовность и помечается признаком
      того, что это срез

#### Scenario: Источник вопроса устарел относительно самого вопроса

- **WHEN** `golden_source` вопроса менялся позже `as_of` вопроса
- **THEN** вопрос не может подтверждать готовность, пока расхождение не закрыто; наличие
      такого вопроса объявляется числом, а не флагом

#### Scenario: Число вопросов объявлено рядом с метрикой

- **WHEN** публикуются groundedness, coverage и hallucination_rate
- **THEN** публикуется и знаменатель: сколько вопросов из скольких оценено, и какой срез

### Requirement: Проверка готовности повторяема

#### Scenario: Гейт запускается повторно

- **WHEN** гейт готовности запускается на том же наборе данных
- **THEN** результат воспроизводим, а гейт не требует ручной подготовки: подготовка,
      делаемая руками, не является частью гейта

#### Scenario: Пустой результат гейта не читается как успех

- **WHEN** гейт не нашёл ни одного документа для проверки
- **THEN** он сообщает «не измерено» и ненулевой код выхода, а не «готовность подтверждена»

**Про знаменатель:** метрики качества и счётчики наполнения публикуются вместе со своим
знаменателем. Единица измерения счётчика — документ, а не отношение и не связь: у одного
отношения два конца, и счёт по отношениям вместо документов завышает долю вдвое.
