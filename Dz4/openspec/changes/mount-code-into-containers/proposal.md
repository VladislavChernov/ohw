# Proposal: Код монтируется в контейнер, образ несёт только внешнее

## Почему

Правка правил извлечения кандидатов не попала в результат прогона: кандидаты
перегенерированы контейнером и содержали ни одного нового имени — `Glossary Service`
и `Topology Orchestrator` в файле отсутствовали. Команда отработала успешно, посчитанный
прирост «+45 имён» оказался следствием правки `docs/05_adr_log.md`, а не нового правила.

Причина — код запечён в образ (`COPY src ./src` во всех пяти Dockerfile), поэтому
устаревший образ не сообщает о себе, он возвращает чужой результат. Это молчание хуже
отказа: отказ виден по логу, молчание выглядит как успех.

Проверено на `master`: монтирования там тоже нет, запекание было с самой вехи M0 и ни разу
не пересматривалось. Значит решение не восстанавливается, а принимается впервые.

Правка дешёвая: пакет установлен в режиме редактирования (`graphrag_proto.pth` =
`/app/src`), поэтому том перекрывает путь импорта и пересборка для актуальности кода не
требуется.

## Что делаем

- Во все `compose*.yaml` добавляем том `../src → /app/src:ro`.
- Внешние инструменты (`neo4j`, `valkey`, `llm`, `reranker`) не трогаем.
- Правило отбора: сервис наш, если у него есть `build.dockerfile`, не являющийся
  внешним, **или** образ из пространства `ohw/*` без build-контекста.
- Оверлеи тоже: compose **заменяет** список `volumes` целиком, поэтому том, добавленный
  только в базовый файл, при наложении исчезает без ошибки.
- Попутно исправляем дефект путей: `PRE_INGEST_SRC=../docs` разрешался в
  `prototype/docs`, где нет ни одного `.md`, и давал «в папке нет .md» — пустой
  результат вместо ошибки.
- В `infra/checks/` кладём приборы проверки, каждый доказан откатом.

## Спека

Затрагивает требование доставки кода в контейнер, которого раньше не было: код
исполнялся из образа, и версия кода в прогоне определялась моментом сборки.

Новое требование: **сервис, исполняющий код проекта, получает актуальные исходники
через монтирование, без пересборки образа.** Детали и сценарии — в
`specs/mount-code-into-containers/spec.md`.

Не входит в спеку: разделение ingestion и query (ADR-058), выбор набора томов
(`VOL`), содержимое самих compose-файлов.

## Проверка

```powershell
# 1. Монтирование на месте во всех сервисах своего кода
powershell -ExecutionPolicy Bypass -File prototype\infra\checks\check_mounts.ps1
# ожидание: PASS, знаменатель равен числу найденных, не "0"

# 2. Правка видна БЕЗ пересборки образа
cd prototype\infra
docker compose -f compose.preingest.yaml run --rm `
  --entrypoint grep pre-ingest -c "CANDIDATE_PATTERNS" /app/src/graphrag_proto/pre_ingest/generate.py

# 3. Пути разрешаются в корень репозитория
docker compose -f compose.preingest.yaml config
# ожидание: source содержит Dz4\docs и Dz4\pre-ingest

# 4. Прибор ловит поломку (откат обязателен)
#    удалить монтирование у одного сервиса -> код 1
#    снять :ro -> код 1
#    пустая папка в verify_candidates.py -> код 2

# 5. Гейт
pytest / ruff / mypy без ослаблений
```

**Осталось открытым:** полный `trace` в ответе не отдаётся; версия кода в отчёте оценки
не называется — после монтирования образ больше не самодостаточен по коду.
