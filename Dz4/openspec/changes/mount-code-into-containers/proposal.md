# Proposal: код монтируется в контейнер, образ несёт только внешнее

## Контекст

Правка правил извлечения кандидатов (`pre_ingest/generate.py`) не попала в результат
прогона: кандидаты были перегенерированы контейнером и содержали **ни одного** из новых
имён — `Glossary Service` и `Topology Orchestrator` в файле отсутствовали. При этом команда
отработала успешно, а посчитанный прирост «+45 имён по корпусу» оказался следствием правки
`docs/05_adr_log.md`, а не нового правила.

Отчёт выглядел правдоподобно, данные принадлежали старому коду. Это «молчание хуже отказа»
из глобальных правил: устаревший образ не сообщает о себе.

## Причина, установленная чтением, а не предположением

Compose монтирует только данные; исходник не подключён ни в одном файле:

| файл | сервисов | монтирует `/app/src` |
|---|---|---|
| `compose.yaml` | 16 | нет |
| `compose.runtime.yaml` | 15 | нет |
| `compose.eval-minimal.yaml` | 8 | нет |
| `compose.eval-qwen3b.yaml` | 4 | нет |
| `compose.eval.yaml` | 3 | нет |
| `compose.preingest.yaml` | 1 | нет |

Код попадает в контейнер через `COPY src ./src` в Dockerfile. Образ при этом считается
актуальным по умолчанию, потому что тег один и тот же, — и это молчаливая ловушка.

Проверено на ветке `master`: там монтирования тоже нет, а все пять Dockerfile пекут код.
Значит это не регрессия, а исходная практика, которая ни разу не пересматривалась. Решения
не существовало, и ссылаться на «бывшее решение» не на что.

## Почему правка дешёвая

Проверено чтением образа: пакет установлен **в режиме редактирования** — в `site-packages`
лежит `graphrag_proto.pth` содержимым `/app/src`, а не копия пакета. Поэтому том
`../src → /app/src` перекрывает путь импорта, и актуальность кода не требует пересборки.

Проверено на двух образах: `ohw-pre-ingest-pre-ingest`, `ohw/eval-service`. Проверка выполнена
сравнением содержимого, а не предположением: контейнер с томом показал 6 шаблонов
правил, образ без тома — 5.

## Решение владельца

Код монтируется. Образ несёт только внешнее: зависимости, venv, модель NER, llama.cpp и
модель.

## Что меняется

1. Во все `compose*.yaml` добавляется том `../src → /app/src:ro`.
2. `compose.preingest.yaml`: дефолтные пути исправлены с `../docs`/`../pre-ingest`
   (разрешались в `prototype/docs`, где нет ни одного `.md`) на `../../docs` и
   `../../pre-ingest`.
3. `COPY src ./src` в Dockerfile остаётся: образ всё ещё нужен для зависимостей и
   внешних инструментов, и монтирование не заменяет сборку.

## Побочный дефект, найденный попутно

Дефолт `PRE_INGEST_SRC=../docs` разрешается относительно каталога `infra/`, то есть в
`prototype/docs`, а корпус лежит в корне репозитория `Dz4/docs`. Голый запуск без
переменных даёт `в папке нет .md: /data/src` — **пустой результат вместо ошибки**.
Работало только потому, что `run_pre_ingest.ps1` передаёт пути явно.

По правилам глобальной части пустой результат и отсутствие файла не должны выглядеть
одинаково, поэтому дефолт приведён к корпусу.

## Что это меняет для воспроизводимости

Образ перестаёт быть самодостаточным по коду: прогон зависит от состояния рабочей копии.
Для оценок это принято осознанно — оценка должна мерить текущий код, а не код на момент
сборки образа. Следствие: версия кода в отчёте определяется ревизией рабочей копии, и её
нужно называть при записи результата.

## Границы применимости

Измерение сделано на одном документе и одном прогоне. Оно **опровергает** «правило применилось»
и **не доказывает** «правило достаточно»: 12 новых имён на документе не дают полноту по
корпусу. Полнота на корпусе не измерена.

| что установлено | как |
|---|---|
| контейнер с томом видит 6 шаблонов, без тома — 5 | прямое сравнение в контейнере |
| `graphrag_proto.pth` = `/app/src` | чтение `site-packages` в двух образах |
| монтирования нет ни в одном compose | перебор шести файлов |
| в `master` монтирования тоже нет | `git show master:...` |

## Чего это изменение не делает

- Не убирает `build:` и `COPY src`: образ нужен для зависимостей и внешних инструментов.
- Не чинит уже записанные данные: кандидаты, сгенерированные старым кодом, перегенерируются.
- Не измеряет полноту правил на корпусе — это отдельная работа.
