## Критерий готовности, объявленный до реализации

UI нужен, когда выполняются **оба** условия:

1. требование `docs/02_pipeline_and_normalizer.md`:456 стало проверяемым — то есть хотя бы
   одна настройка **обязана** меняться без перезагрузки контейнера, а не файлом;
2. такой настройки нельзя безопасно менять через REST руками: вызов затрагивает живой стенд,
   и нужен подтверждение и видимость того, что **применено**, а не запрошено.

Оба условия проверяемы и не требуют угадывания даты. Пока нет ни одной настройки такого
рода, UI остаётся незачем — это не «красиво», а отсутствие работы для него.
