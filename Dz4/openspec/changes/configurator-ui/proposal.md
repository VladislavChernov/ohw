# Proposal: Конфигуратор нужен, и момент его готовости определён

## Решение владельца

Объявление `configurator-ui` в `compose.yaml` **остаётся** и комментируется: сервис нужен,
но пока не реализован. Реализация планируется на веху **M5**.

## Что это за сервис

Web UI «Конфигуратор «Бизнес-онтология»», порт `8501`, граница «человек ↔ конфигурация»,
рядом с Topology UI `:8502` (граница «система ↔ топология», ADR-019). Оба выбраны на
Streamlit как единый UI-стек (`add-demo-ui-e2e/design.md`:88).

Задокументирован в `docs/04_services_config.md`:19, `docs/00_hi_level_architecture.md`:28
и ADR-019. Это часть контракта, а не остаток черновика.

## Зачем он нужен — цитата из документации

`docs/02_pipeline_and_normalizer.md`:456:

> «В M5+ всё больше составляющих: загрузка документа, модель, эмбеддинги, ретрайвер, и всё
> это **должно меняться без перезагрузки контейнера**, а не файлом. Контейнер перезапускать
> — тоже можно, но как **сброс** состояния, а не как основной путь настройки.»

То есть назначение — **горячая замена частей системы**. Не «просмотр параметров удобнее»,
а требование менять состав работающего стенда без его пересборки.

Механизм уже реализован: `PUT /api/v1/config/adapters` с `{"apply": true}` переключает
реализацию слоя (Configurator API `:8005`, ADR-019). Отдельно правятся параметры Valkey,
Feature Flags и активный Domain Profile через Config Service `:8001`.

**Чего не делает UI:** он не добавляет возможности, которых нет в API. Он делает вызов,
меняющий живой стенд, безопасным для человека: с подтверждением и с показом того, что
**реально применено**, а не того, что запрошено.

Прежняя формулировка «сервис-фантом» была неверной: проверка шла только по текущей ветке.
По истории объявление есть с самого начала и никуда не девалось. Неверным было и основание
«нужен, когда параметры перестают помещать��ся в compose» — это подставленный мной критерий
вместо уже записанного в документации.

## Состояние compose сейчас

Объявление оставлено и снабжено комментарием: нужен, не реализован, профиль `configurator`
при старте упадёт, и это ожидаемо.

## Границы применимости

- Требование про M5 записано в `docs/02`, но **веха M5 не наступила** и её состав нигде не
  зафиксирован как достигнутый. Дата готовности UI не выводится из этого автоматически.
- UI не покрывает Topology UI `:8502` — это отдельный сервис с отдельным ADR-019 и в это
  изменение не входит.
- Совместимость с `demo-ui` (единственным реализованным UI) не проектировалась: два
  Streamlit-приложения на соседних портах — обычное дело, но общий код не выделялся.

## Чего это изменение не делает

- Не реализует UI и не создаёт Dockerfile.
- Не меняет `docs/` — корпус остаётся как есть.
- Не добавляет монтирование `/app/src`: сервис не собирается, тома ему не на что принимать.
