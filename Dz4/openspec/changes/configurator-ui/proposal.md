# Proposal: Конфигуратор нужен, момент готовности определён

## Почему

Объявление `configurator-ui` есть в `compose.yaml` с самой вехи M0 (`8a83c72`) и
присутствует в `master`, но образа не существует, секции `build:` нет, entrypoint
`graphrag-configurator-ui` в `pyproject.toml` отсутствует, кода UI в `src/` нет. То есть
профиль `configurator` при старте упадёт.

Раньше это было названо «сервисом-фантомом». Проверка шла только по текущей ветке и только
по `docker images`, и это было неверно: объявление задокументировано в четырёх местах и
относится к фазе 2. Ошибка в том, что неверно названо: сервис задокументирован и не
реализован, а не выброшен из черновика.

Реализация перенесена осознанно, и свидетельство есть в проекте:
`openspec/changes/add-demo-ui-e2e/design.md`:88 — Streamlit выбран как «целевой стек
фазы 2 (конфигуратор `:8501`, Topology UI `:8502`, ADR-019)». Но это единственная
строка, и нигде не зафиксировано, **когда** UI понадобится. Без этого он уйдёт в ту же
неопределённость, из которой и был вынут.

## Что делаем

- Объявление `configurator-ui` оставляем в `compose.yaml` и комментируем: нужен, не
  реализован, веха M5.
- Записываем критерий готовности, объявленный **до** реализации.
- Решение о моменте реализации принимаем при разборе вехи M5, а не сейчас: состав вехи
  не зафиксирован, и дата из критерия не выводится.

Назначение сервиса взято из документации, а не додумано.

## Спека

Новое требование: **сервис, объявленный как отложенный, обязан быть явно помечен, и
момент его готовности должен быть определён проверяемым критерием до того, как он будет
написан.** Подробности — в `specs/configurator-ui/spec.md`.

Не входит в спеку: реализация UI, Topology UI `:8502` (отдельный сервис по ADR-019),
разделение ingestion и query.

## Проверка

```powershell
# 1. Объявление на месте и помечено
Select-String -Path prototype\infra\compose.yaml -Pattern "configurator-ui"
# ожидание: сервис есть, над ним комментарий «нужен, но не реализован»

# 2. Прибор не считает это дефектом молча
powershell -ExecutionPolicy Bypass -File prototype\infra\checks\check_mounts.ps1
# ожидание: раздел «DECLARED BUT NOT RUNNABLE», итог PASS, а не ошибка монтирования

# 3. Критерий готовности записан и проверяем
Get-Content openspec\changes\configurator-ui\tasks.md -Encoding UTF8
```

**Проверяемость критерия:** оба условия проверяются без угадывания даты — есть ли
настройка, обязательная к смене без перезагрузки, и можно ли её безопасно менять через
REST руками. Пока такой настройки нет, UI незачем.

**Осталось открытым:** состав вехи M5 не зафиксирован; общий код с `demo-ui` не
проектировался; решение о реализации принимается при разборе вехи.
