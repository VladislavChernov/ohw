# Proposal: матрица демо-скриптов по платформам и видам счёта

## Почему

Запись 2026-10-18 (ADR-065) утверждала матрицу, обратную намерению владельца: на Unix/macOS
два скрипта ингеста (GPU и CPU), на Windows CPU-скрипта нет — вместо него инструкция. Код был
приведён в соответствие с этой записью, поэтому расхождение не было видно ни гейтом, ни
ревью: документация, скрипты и тесты согласованы между собой.

Владелец назвал намерение заново (2026-10-19): Windows — два вида счёта, Unix/macOS — только
процессор. Из этого следует три дефекта, каждый наблюдаем в коде:

1. **Флаг вместо файла.** `Demo/ingest.ps1:33,91-93` включает CPU-вариант флагом `-Cpu`. Это
   прямое нарушение уже записанного правила «различие выражается именем файла, флаг не
   заводится» (ADR-065).
2. **Лишние GPU-скрипты на Unix/macOS.** `Demo/demo.sh` и `Demo/ingest.sh` подкладывают
   `compose.runtime-gpu.yaml`, хотя по намерению варианта два быть не должно.
3. **Пара «стенд ↔ ингест» не согласована по виду счёта.** `Demo/demo-cpu.ps1:58-60` и
   `Demo/demo-cpu.sh:42-43` отправляют CPU-стенд за наполнением в GPU-ингест.

Попутно: `README-deployment.md:269` зовёт `Demo/demo.sh load --domain it`, а у стенда команды
`load` нет вовсе (набор команд стенда: up, down, status, export, restore).

## Что делаем

Матрица (решение владельца, 2026-10-19):

| режим | Windows, видеокарта | Windows, процессор | Linux/macOS |
|---|---|---|---|
| без ингеста (стенд) | `demo.ps1` | `demo-cpu.ps1` | `demo.sh` |
| с ингестом | `ingest.ps1` | `ingest-cpu.ps1` | `ingest.sh` |

- завести `Demo/ingest-cpu.ps1` (поведение `ingest-cpu.sh`, без GPU-оверлея);
- убрать `-Cpu` из `Demo/ingest.ps1` вместе с упоминанием в usage;
- `Demo/demo.sh` и `Demo/ingest.sh` перевести на процессор (не подкладывать GPU-оверлей,
  `LLM_NGPU_LAYERS=0`);
- удалить `Demo/demo-cpu.sh` и `Demo/ingest-cpu.sh`: вариант один — суффикс не ставится;
- подсказки в шапках и usage называют парный скрипт: CPU-стенд → CPU-ингест;
- поправить `README-deployment.md:269` и таблицы в `Demo/README.md`,
  `README-deployment.md` §3.1, `docs/infrastructure_stack.md` §4.1, `docs/prototype_requirements.md` §3.3.

Два режима остаются ровно два и различаются набором команд: стенд (без ингеста) и наполнение
(стенд вместе с `ingestion-api` плюс загрузка). Третьего варианта и флага `-WithIngest` нет —
это уже проверено и не меняется.

## Спека

`specs/demo-script-matrix/spec.md`: для каждой платформы поставляемый набор скриптов равен
объявленной матрице; вид счёта не выбирается флагом; режимы «стенд» и «наполнение» —
разные файлы; подсказка в скрипте называет парный по виду счёта скрипт.

Затрагивает: ADR-065 (пересмотр матрицы), `docs/prototype_requirements.md` §3.3,
`Demo/*.ps1`, `Demo/*.sh`, `prototype/tests/test_demo_scripts_parity.py`.

## Проверка

- `pytest prototype/tests/test_demo_scripts_parity.py` — зелёный; гард на флаг перебирает и
  `.ps1`; гард на матрицу падает, если на Unix появится GPU-скрипт или на Windows пропадёт
  CPU-скрипт.
- Поведенческий гард с подменой `docker`: `ingest-cpu.ps1` не подкладывает
  `compose.runtime-gpu.yaml`, `ingest.ps1` — подкладывает.
- Ручная проверка: `Demo/ingest-cpu.ps1 help` и `Demo/ingest.ps1 help` показывают разные
  наборы, флага `-Cpu` нет ни в одном.
- `gate.sh full` перед коммитом.
