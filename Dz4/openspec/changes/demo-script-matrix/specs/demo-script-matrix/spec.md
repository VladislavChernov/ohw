# Spec: матрица демо-скриптов

## Требование: поставляемый набор равен объявленной матрице

Для каждой платформы набор файлов в `Demo/` равен матрице ADR-065 (пересмотр 2026-10-19):

| режим | Windows, видеокарта | Windows, процессор | Linux/macOS |
|---|---|---|---|
| без ингеста (стенд) | `demo.ps1` | `demo-cpu.ps1` | `demo.sh` |
| с ингестом | `ingest.ps1` | `ingest-cpu.ps1` | `ingest.sh` |

#### Scenario: лишний скрипт

- **WHEN** в `Demo/` появился `demo-cpu.sh` или `ingest-cpu.sh`
- **THEN** гард падает и называет файл: на Unix/macOS вариант один, суффикс означает выбор,
  которого нет

#### Scenario: недостающий скрипт

- **WHEN** на Windows нет `ingest-cpu.ps1`
- **THEN** гард падает: на Windows объявлены два вида счёта, и каждый — отдельным файлом

## Требование: вид счёта не выбирается флагом

Ни один скрипт не содержит переключателя вида счёта (`--cpu`, `-Cpu`): различие выражается
именем файла.

#### Scenario: флаг вернулся

- **WHEN** в любом `Demo/*.ps1` или `Demo/*.sh` появилась строка `-Cpu` / `--cpu`
- **THEN** гард падает и называет файл

## Требование: CPU-вариант не подкладывает бронь видеокарты

CPU-скрипт собирает compose без `compose.runtime-gpu.yaml` и ставит `LLM_NGPU_LAYERS=0`;
GPU-скрипт кладёт оверлей сразу за базовым файлом. Проверяется поведением: скрипт
запускается с подменой `docker`, которая печатает аргументы.

#### Scenario: CPU-скрипт получил оверлей

- **WHEN** `ingest-cpu.ps1` или `ingest-cpu.sh` передаёт `compose.runtime-gpu.yaml` в compose
- **THEN** гард падает: CPU-вариант обходится базовым файлом

## Требование: варианты ингеста повторяют варианты стенда

Подсказка в шапке скрипта называет **парный по виду счёта** скрипт наполнения: CPU-стенд —
CPU-ингест, GPU-стенд — GPU-ингест.

#### Scenario: CPU-стенд зовёт GPU-ингест

- **WHEN** `demo-cpu.ps1` в подсказке называет `ingest.ps1` (видеокарта)
- **THEN** гард падает и называет ожидаемое имя

## Требование: два режима различаются набором команд

Стенд не знает про ингест: ни `--profile ingest`, ни оверлея ингеста, ни контейнера
`ohw-runtime-ingestion` в исполняемом коде. Наполнение поднимает стенд вместе с
`ingestion-api`. Наборы команд разные и проверяются раздельно.

#### Scenario: стенд научился загружать

- **WHEN** в `demo.*` появился `--profile ingest` или оверлей `compose.ingest.yaml`
- **THEN** гард падает: разделение вернулось в один скрипт
