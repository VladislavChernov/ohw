# eval-data - данные для двух состояний стенда

Здесь лежат данные для двух вариантов запуска: чистый старт и заполненная база.

## Раскладка

```
eval-data/
  README.md            этот файл
  ready/               заполненная база: сюда класть свой корпус
    corpus/            документы для загрузки
    pre-ingest/        списки кандидатов для них
    reports/           отчёты и метрики прогонов
  empty/               чистый старт: та же раскладка, пустая
    corpus/
    pre-ingest/
```

## Папки пустые - и это не недоработка

`ready/` и `empty/` **намеренно пусты**. Наполнять `ready/` копиями текущего корпуса
нельзя по трём причинам:

1. **Второе место хранения - это дрейф.** Корпус лежит в `docs/`, кандидаты - в
   `pre-ingest/`. Копия разъедется с оригиналом при первой же правке, и обнаружится
   это только на загрузке, как `CandidateListStaleError`.
2. **Копия не проверяет себя.** Свежесть кандидатов привязана к `sha256` документа.
   В копии этот `sha256` соответствует копии же, и расхождение с настоящим корпусом
   ничем не сигнализируется, пока кто-то не поменяет путь загрузки.
3. **Замеренная полнота правил относится к `docs/`, а не к копии.** Замер, который
   обосновывал новое правило, сделан на этом корпусе. Набор, названный «заполненной
   базой», должен указывать на него, а не повторять.

Наполнить свой набор - шаг 1 ниже. Готовый пример - сам репозиторий:

```powershell
.\prototype\infra\scripts\run_pre_ingest.ps1 -Src .\docs -Dst .\pre-ingest
```

## Порядок работы (для своего корпуса)

1. Скопировать `empty/` к себе - например в `my-run/`. Каталог в git не попадёт,
   если не закоммитить.
2. Положить `.md`-документы в `my-run/corpus/`.
3. Сгенерировать списки кандидатов:

   ```powershell
   .\prototype\infra\scripts\run_pre_ingest.ps1 -Src .\my-run\corpus -Dst .\my-run\pre-ingest
   ```

4. Поднять стенд на **пустой** базе - без этого повторная загрузка того же документа
   станет `noop` и ничего не проверит.
5. Загрузить документы, дождаться `succeeded` у каждой джобы.
6. Запустить eval. Он меряет на том, что загружено, поэтому пустая и заполненная база -
   это разные вопросы, и смешивать их нельзя.

## Почему README без расширения

Пре-ингест отбирает документы единственной строкой:

```python
return sorted(path for path in source.glob("*.md") if path.is_file())
```

То есть **только `.md`**, и никаких проверок маркеров у него нет. Файл с другим
именем он просто не увидит - поэтому все README в этих папках названы без расширения,
и это сделано намеренно, а не по недосмотру.

`.md` в таких README означал бы: файл получает `sha256`, попадает в обработку, для него
создаётся список кандидатов, и при следующем запуске стадия пересчитает и его. Файл,
который никто не менял, стал бы причиной расхождения по свежести.

## Почему здесь нет `.ingest-ignore`

Маркер `.ingest-ignore` читает только раннер eval (`run_eval.py:275`, константа
`INGEST_IGNORE_MARKER`) и означает «**не грузить** эти документы». Пре-ингест его не
читает вовсе. Положить маркер в папку с документами означало бы, что eval их не видит.

Наш каталог и так вне зоны обхода: дефолт раннера `--corpus` = `/repo/docs`
(`run_eval_run.ps1:44`), а `eval-data/` — соседняя директория.

## Что меняется при правке `docs/`

Правка документа корпуса инвалидирует его список кандидатов: в файле лежит `sha256` от
момента генерации, и при загрузке сверяется. Расхождение поднимает
`CandidateListStaleError`. Поэтому после правки любого `.md` в `corpus/` кандидаты
перегенерируются.
