# Demo — стенды для показа

Здесь живут **скрипты запуска и база, отдаваемая наружу.** Ничего больше.

Демонстрация идёт по двум наборам данных: пустая база и база с документами. Оба
различаются одним значением переменной `VOL`, оба реализованы одним и тем же
compose-файлом.

## Что где лежит

| | где | что это |
|---|---|---|
| скрипты запуска | `Demo/` | этот каталог |
| описание контуров | `prototype/infra/compose.*.yaml` | **единственное** определение стендов |
| база для показа | том Docker `ohw-runtime_empty_*`, `ohw-runtime_ready_*` | **не папка в репозитории** |

## Базы здесь нет, и это не недоработка

Наборы — это **тома Docker**, а не каталоги. `ohw-runtime_ready_neo4j` занимает ~550 МБ и
живёт вне репозитория; в git он не попадает и попасть не может.

Отсюда два следствия, о которых стоит знать заранее:

1. **Отдать базу наружу — значит отдать том.** Скрипт `export_ready.ps1` выгружает том в
   архив. Копировать базу в репозиторий нельзя: второе место хранения разъедется с
   оригиналом, и расхождение обнаружится только при следующей загрузке.
2. **Получатель может собрать базу сам** — `load_document.ps1` загружает документы через
   API. Это надёжнее тарника: архив требует совместимого Docker, а прогон требует только
   стенд.

## Почему compose-файлы не перенесены сюда

`compose.runtime.yaml` и `compose.ingest.yaml` привязаны относительными путями к своему
каталогу: `../src`, `../domain_profiles`, `./config`, `context: ..`. Копия в `Demo/` потребовала
бы переписать пути — и завела бы второе определение того же контура, которое со временем
разъедется с оригиналом. Поэтому конфигурация остаётся в `prototype/infra/`, а скрипты
отсюда просто вызывают её.

## Быстрый старт

```powershell
# Пустой стенд — система без документов
powershell -File Demo\run_demo.ps1 -Set empty

# Стенд с документами — сначала нужно заполнить набор
powershell -File Demo\run_demo.ps1 -Set ready
powershell -File Demo\load_document.ps1 -Path .\Demo\incoming\04_services_config.md -Domain it

# Состояние: контейнеры, тома, наполненность графа
powershell -File Demo\status_demo.ps1 -Set ready

# Остановить (тома сохраняются)
powershell -File Demo\stop_demo.ps1 -Set ready
```

**Готовить ничего не нужно.** Кандидаты сущностей производит сам ingestion-пайплайн перед
разбором (ADR-053, решение владельца от 2026-10-14). Отдельной стадии запуска, папки
`pre-ingest/` и переменной `CANDIDATES_DIR` больше нет — загруженный документ сразу даёт
граф, а не тихий vector-only.

**Про пароль.** Скрипты не генерируют пароль заново: том переживает перезапуск, а Neo4j
применяет `NEO4J_AUTH` только при первом старте базы. Новый пароль на уже инициализированной
базе молча игнорируется, и стенд падает как `unhealthy`. Если задать свой
`$env:NEO4J_PASSWORD` при первом поднятии — он применится; при следующих запусках нужно
указывать тот же.

## Чего этот каталог не делает

- **Не поднимает стенд для отладки кода.** Здесь нет `ingestion-api` в runtime-контуре по
  ADR-058, и правку пайплайна здесь не отладить. Для отладки есть `compose.yaml`
  (полный контур) и `compose.eval-minimal.yaml` (eval-прогон) — см. `README-deployment.md`.
- **Не измеряет качество.** Наполненность графа не равна «извлечение работает»: на наборе
  `ready` часть джоб завершается с деградацией.
- **Не заменяет приёмку.** Золотой набор и критерий готовности — в
  `prototype/infra/eval/README-dataset.md` и `docs/prototype_requirements.md` §8.

## Отладка разбора при загрузке

Файлы кандидатов после загрузки удаляются. Чтобы посмотреть, чем именно разбирался
документ, уборку выключают:

```powershell
$env:CANDIDATES_KEEP = "1"
powershell -File Demo\load_document.ps1 -Path .\docs\04_services_config.md -Domain it
```

При `1` джоба пишет в отчёт, что кандидаты оставлены для отладки, и сколько их осталось.
После отладки переменную обязательно сбросить — иначе папка будет копить файлы, и
следующий запуск примет их за списки текущей версии документов.
