# Demo

Демонстрационный стенд GraphRAG: поднять систему локально, посмотреть на наполненный
граф, задать вопрос через UI.

Работает на **Linux, macOS и Windows**. На Linux и macOS — `demo.sh`, на Windows —
`demo.ps1`. Это два файла с одной логикой; расхождение между ними закрывает тест
`prototype/tests/test_demo_scripts_parity.py`.

## Видеокарта или процессор

Два набора скриптов, разница ровно в одном — где считает языковая модель.

| | на видеокарте NVIDIA | на процессоре |
|---|---|---|
| Linux, macOS | `demo.sh` | `demo-cpu.sh` |
| Windows | `demo.ps1` | `demo-cpu.ps1` |
| нужно | видеокарта NVIDIA | ничего, кроме Docker |
| скорость ответа | минуты | десятки минут |

```sh
./Demo/demo.sh up --set ready            # на видеокарте
./Demo/demo-cpu.sh up --set ready        # на процессоре
```

На видеокарте модель занимает примерно 5,35 ГБ VRAM, поэтому помещается в карту от 8 ГБ.
Число слоёв, отданных видеокарте, задаётся переменной `RUNTIME_LLM_GPU_LAYERS`, по
умолчанию **99** — то есть вся модель. На карте меньше памяти значение надо снизить, иначе
модель не поместится.

Вариант на процессоре снижает контекст до 8192 токенов: на CPU модель целиком живёт в
ОЗУ, и длинный контекст съедает его быстрее, чем даёт пользу на демонстрации. Значение
меняется через `RUNTIME_LLM_CTX_SIZE_CPU`.

**Почему нельзя просто переключить:** бронь устройства объявляется самим compose, и была
объявлена безусловно — на машине без драйвера NVIDIA Docker не может её удовлетворить, и
стенд не поднимется вообще. Перекрыть бронь сверху нельзя: проверено, что ни
`devices: []`, ни `devices: null` её не снимают. Поэтому бронь убрана из базового файла и
вынесена в `compose.runtime-gpu.yaml`, который подкладывают только GPU-скрипты.

Тот же приём уже применён в общем слое репозитория: `infra/compose.yaml` без брони плюс
`infra/compose.gpu.yaml`, который выбирает `infra/up.sh --gpu`. Здесь сделано так же.

Модель на видеокарте занимает примерно 5,35 ГБ VRAM, поэтому помещается в карту от 8 ГБ.
Число слоёв, отданных видеокарте, задаётся `RUNTIME_LLM_GPU_LAYERS`, по умолчанию **99** —
вся модель. На карте меньше памяти значение надо снизить, иначе модель не поместится.

## Что нужно

Docker и Docker Desktop (на Linux — просто работающий `dockerd`). Больше ничего: ни
Python, ни Node на хосте не требуются, HTTP-запросы выполняются внутри контейнера.

## Быстрый старт

**Набор с документами — сначала `restore`, потом `up`.** Тома не хранятся в git, поэтому
на чистой машине набора `ready` просто не существует, и `up` поднимет пустую базу под этим
именем. Одна команда делает всё: развернуть готовый набор и запустить стенд.

```sh
# macOS / Linux
./Demo/demo.sh restore --set ready     # развернуть готовый набор из архива
./Demo/demo.sh up --set ready          # запустить стенд
./Demo/demo.sh status --set ready      # что поднято и сколько нод в базе
```

```powershell
# Windows
powershell -File Demo\demo.ps1 restore -Set ready
powershell -File Demo\demo.ps1 up -Set ready
powershell -File Demo\demo.ps1 status -Set ready
```

UI откроется на **http://localhost:8503**.

Архив лежит в репозитории, в `Demo/fixtures/` — скачивать и никуда перекладывать не нужно,
`restore` разворачивает его сам. Если он уже развёрнут, `restore` повторять не нужно.

Пустая система, наоборот, ничего не требует — тома создаются с нуля:

```sh
./Demo/demo.sh up --set empty                 # пустая база
./Demo/demo.sh up --set empty --with-ingest   # пустая база + возможность грузить документы
```

Остановить (флаги `-WithIngest` / `--with-ingest` на `down` не нужны — он убирает и их):

```sh
./Demo/demo.sh down --set ready
```

## Наборы

| набор | что это |
|---|---|
| `empty` | пустая система. Тома создаются заново, в базе ноль нод. |
| `ready` | набор с документами: 717 `ContextNode`, 432 `Chunk`, 1731 связь. |

**Набора `ready` в репозитории нет** — это тома Docker, а git хранит только файлы. Он
разворачивается из архивов в `Demo/fixtures/`:

| файл | что внутри | куда попадает |
|---|---|---|
| `ready-neo4j.tar.gz` (16,8 МБ) | граф, тексты чанков и **векторы** | том `ohw-runtime_ready_neo4j` |
| `ready-ingestion.tar.gz` (0,3 МБ) | реестр источников | том `ohw-runtime_ready_ingestion` |
| `ready-projection.tar.gz` (0,02 МБ) | состояние проекции | том `ohw-runtime_ready_projection` |

Вектора лежат внутри Neo4j, в свойстве `embedding` у нод `Chunk`, поэтому отдельного
векторного хранилища нет: поиск по векторам работает сразу после `restore`. Реестр
источников обязателен — без него сервис не знает, что документы уже загружены, и повторная
загрузка создала бы вторую копию вместо no-op.

**Сами файлы документов** — это `docs/*.md` в репозитории, оттуда они и грузились.
Копия, попавшая в том при загрузке, удаляется сразу после успеха и намеренно не хранится.

Том `query` в архив не входит: в нём только журнал задач запросов, он пуст, и compose
создаст его при первом же вопросе.

`restore` затирает содержимое томов, поэтому на уже существующих спрашивает подтверждение.

### Пустая база и база с данными — в чём разница

- **посмотреть на готовый граф** — `up --set ready` (после `restore`). Это самый быстрый
  путь, и для показа он и нужен;
- **наполнить пустую базу самому** — `up --set empty --with-ingest`, затем
  `load --path ./docs/<файл>.md`. Флаг `--with-ingest` поднимает `ingestion-api`: без него
  грузить нечем, он вынесен из основного runtime (ADR-058).

## Загрузка документа

```sh
./Demo/demo.sh load --path ./docs/00_hi_level_architecture.md --domain it
```

Скрипт спрашивает у сервиса, не загружен ли документ в текущем виде, отправляет его,
ждёт конца джобы и **проверяет, что граф вырос**. Последнее обязательно: джоба может
завершиться `succeeded` при пустом графе — это называется vector-only загрузка и выглядит
как успех.

## Учётные данные

| что | значение |
|---|---|
| Neo4j, логин | `neo4j` |
| Neo4j, пароль | `local-stand-not-a-secret` |
| Ключ API, заголовок | `X-API-Key: demo-key-2026` |

Ключ вводится прямо в UI (поле `X-API-Key` на боковой панели). В Neo4j Browser
(http://localhost:7474) вход теми же данными.

Пароль базы **не меняется**: том создан один раз, Neo4j применяет `NEO4J_AUTH` только при
первом старте, и смена пароля означала бы пересоздание тома вместе со всем наполнением.
Значение задано в обоих скриптах и нигде больше.

| 8000 | query-api | вопросы к графу |

| 8004 | embeddings-service | эмбеддинги |

```
GET  /api/v1/glossary/{domain}                       8003

```

Пример. Поле называется `query`, не `question`:

```sh
curl -s http://localhost:8000/query \
  -H 'X-API-Key: demo-key-2026' \
  -H 'Content-Type: application/json' \
  -d '{"query": "из чего состоит пайплайн?"}'
```

Ответ приходит не сразу и не в этом ответе: `/query` возвращает только `task_id`, а сам
текст идёт потоком. Статусы задачи: `queued` → `running` → `succeeded`.

```sh
# дождаться и прочитать ответ
curl -N http://localhost:8000/query/tasks/<task_id>/stream \
  -H 'X-API-Key: demo-key-2026'
```

В потоке идут события: `status` со стадиями (`embedding` → `vector` → `rerank` → `llm`),
затем `token` с кусками ответа.

**Ответ занимает несколько минут:** в стенде настоящая модель 7B, генерация не быстрая.
Это нормально, демо не сломано. На процессоре будет в несколько раз дольше.

## Полезное

```sh
./Demo/demo.sh up --set empty                 # пустая система с нуля
./Demo/demo.sh export --set ready             # пересобрать архив после правки документов
./Demo/demo.sh restore --set ready            # развернуть архив заново
./Demo/demo.sh down                           # остановить текущий набор
```

`export` останавливает Neo4j на время выгрузки и поднимает обратно. Если набор не запущен,
архив собирается из тома на диске.

## Что может помешать показать

- **Первый запуск на чистой машине иногда падает.** `embeddings-service` стартует дольше,
  чем отведённый ему healthcheck, и `docker compose --wait` успевает сдаться. Повторный
  запуск проходит, потому что сервисы уже подняты. Если так вышло — запустите ту же команду
  ещё раз.
- **Порт занят.** Стенд поднимается на фиксированных портах; если что-то уже слушает
  8503 или 8000, сначала освободите его.
- **Пустой том с именем `ready`.** Если запустить `up --set ready` без `restore`, compose
  создаст пустой том под этим именем, и база будет пустой при названии «с данными».
  Скрипт об этом предупредит.
