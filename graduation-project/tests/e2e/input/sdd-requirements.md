# Требования к CLI-пайплайну (источник: SDD.md)

Документ выделен из `SDD.md` и используется как входной файл для e2e-генерации
тест-кейсов. Каждое требование проверяемо.

## BR-1. Пайплайн по умолчанию
При запуске без флагов фаз CLI должен выполнить четыре фазы в порядке
`generate → assess → visualize → report`.

## BR-2. Отдельные фазы
Пользователь должен иметь возможность запустить только `--assess`, только
`--visualize` или только `--report`, используя файлы предыдущих фаз.

## BR-3. Снимок генерации
Фаза `generate` должна сохранять `generation.json` с rendered-текстом, всеми
вариантами генераций, тест-кейсами, промптом и метаданными.

## BR-4. JSON-отчёт
Фаза `assess` должна сохранять `quality-metrics.json` с реальными
`case_summaries` и средними метриками; JSON является источником правды.

## BR-5. Markdown-отчёт
Фаза `report` должна сохранять `report.md` с разделами «Общая информация»,
«Распределение качества», «Список сценариев», «Детализация по сценариям»,
«Визуальный отчёт» и «Источник данных».

## BR-6. Неизмеримые метрики
Если в требованиях нет идентификаторов `BR-N`, метрика покрытия должна быть
`None` и печататься как `n/a`; она не должна заменяться нулём.

## BR-7. Порог качества
При заданном `--fail-under SCORE` CLI должен вернуть код 5, если средний
`overall` ниже порога, и код 0 в противном случае.

## BR-8. Ошибка одного сценария
Если один файл требований не удалось сгенерировать, остальные файлы должны
обрабатываться, а ошибка должна попасть в `errors` и в отчёт.

## BR-9. Недоступность Ollama
Если Ollama недоступна, прогон должен прерваться с кодом 3 и понятным
сообщением, а не продолжать бесконечные повторы.

## BR-10. Общий стенд
Docker-запуск должен использовать `ohw-ollama` и образ `ohw-python:3.13` из
`infra/`, подключаться к сети `ohw_net` и не создавать собственный Ollama.

## BR-11. Валидация модели
Ответ модели должен валидироваться по схеме тест-кейсов; при невалидном ответе
должен выполняться повтор с перечнем замечаний до `--max-retries`.

## BR-12. Пять типов артефактов
Проект должен поддерживать `testcases`, `checklist`, `testplan`, `qareport` и
`coveragematrix`, используя внешние шаблоны промптов.
