# Выпускной проект — концепция

> **Версия:** 0.5.0 (проект), `PIPELINE_VERSION = 0.1.0`
> **Дата актуализации:** 2026-11-17
> **Статус:** описание текущего Runtime и target-границ. Документ объясняющий.
> Нормативные источники — [`SDD.md`](SDD.md) и [`openspec/`](openspec/);
> при расхождении они имеют приоритет над этим файлом.
>
> **Назначение.** Дать одну целостную картину продукта: зачем он существует,
> из чего состоит, какие данные передаёт между фазами и что означают термины
> в CLI, отчётах и OpenSpec. Детали реализации здесь не дублируются.

---

## 1. Назначение и границы

Проект автоматизирует **генерацию тестовой документации по требованиям** и
**оценку её качества** с помощью локальной LLM. Вход — текстовые файлы
требований `.md`/`.txt`; выход — сгенерированные артефакты пяти типов, метрики,
графики и Markdown-отчёт.

Пять типов артефактов: `testcases`, `checklist`, `testplan`, `qareport`,
`coveragematrix`. Модель по умолчанию — `qwen2.5:7b-instruct`.

**Входит в проект:**

- вендоренное ядро DZ2: загрузка и нормализация требований, шаблоны промптов,
  пресеты, Ollama-клиент, валидация ответа, retry, рендер;
- шаблоны DZ7 для пяти типов артефактов;
- детерминированные метрики качества и взвешенный `overall`;
- CLI и Streamlit-рабочее место поверх общих стадий;
- общий стенд `infra/` (`ohw-ollama`, `ohw-python:3.13`, сеть `ohw_net`);
- OpenSpec-спецификации, guard-тесты и инструменты подготовки данных.

**Не входит:** DZ6, DZ3 advanced, API-тесты, обучение модели, LLM-судья текста,
зависимость от соседних домашних заданий по path.

## 2. Сценарии использования

### CLI

Без флагов выполняются все четыре фазы в порядке
`generate → assess → visualize → report`. фазы можно запускать по отдельности
по сохранённым файлам.

```bash
python -m src.workflow --input-dir input --output-dir output
python -m src.workflow --assess --output-dir output
python -m src.workflow --dry-run --input-dir input --output-dir output/prompts
```

Ключевые возможности:

- `--continue-on-error` — продолжать при недоступности Ollama для одного файла;
- `--quality-weights` / `GRADUATION_QUALITY_WEIGHTS` — политика весов `overall`;
- `--fail-under SCORE` — код `5`, если средний `overall` ниже порога;
- `--dry-run` — собрать промпты без вызова модели и без записи `generation.json`.

### Streamlit-рабочее место

Пять вкладок: требования, промпт, генерация, метрики, отчёт. Общие стадии те же,
что в CLI. UI использует веса по умолчанию и не открывает редактор весов.

### Локально и в Docker

Проект самодостаточен: запуск через `uv`, либо `.\run.ps1` / `./run.sh`, либо
`docker compose`. Стенд поднимается из `infra/`; GPU-режим — `.\run.ps1 -Gpu`
или `./infra/up.sh graduation-project --gpu`.

## 3. Архитектура одним взглядом

```text
input/*.md|.txt
      │
      ▼
  generate ──▶ output/scenarios/*.md        (артефакты)
      │    └──▶ output/generation.json      (снимок для пересчёта)
      ▼
  assess ────▶ output/quality-metrics.json  (источник правды для метрик)
      ▼
  visualize ─▶ output/charts/*.png
      ▼
  report ────▶ output/report.md             (представление, не парсится)
```

| Слой | Компоненты | Ответственность |
|---|---|---|
| CLI/UI | `src/workflow/main.py`, `src/ui/app.py` | фазы, логирование, коды возврата, виджеты |
| Стадии | `src/workflow/stages.py` | файловые операции, общая логика для CLI и UI |
| Генерация | `src/generator/*` | inputs, normalizer, prompts, presets, Ollama, retry, renderer |
| Качество | `src/quality/assessor.py` | детерминированные метрики и агрегация |
| Контракты | `src/contracts.py`, `src/models.py` | pydantic-валидация JSON и dataclass-ы |
| Отчётность | `src/reporting/report_generator.py` | JSON и Markdown |
| Графики | `src/visualization/charts.py` | matplotlib, backend `Agg` |
| Данные clarity | `src/quality/clarity_kit.py`, `scripts/*` | экспорт фрагментов и анализ разметки |

`--dry-run` ответвляется до вызова Ollama и пишет только `output/prompts/`.

## 4. Файловый контракт

| Файл | Роль | Ключевое |
|---|---|---|
| `generation.json` | Снимок генерации для `assess` | `pipeline_version`, rendered-текст, все `generations`, `quality_weights` |
| `quality-metrics.json` | Источник правды для графиков и отчёта | реальные кейсы в `case_summaries`, метрики, `version` проекта |
| `report.md` | Человекочитаемое представление | never парсится пайплайном |
| `scenarios/*.md` | Сгенерированные артефакты | по одному файлу на входной документ |
| `charts/*.png` | Визуализация метрик | boxplot, radar, per_scenario |
| `prompts/*.txt` | Только для `--dry-run` | system/user prompt и `manifest.json` с SHA-256 |

Оба JSON-файла валидируются pydantic-моделями до построения dataclass-ов.
Ошибка называет файл и путь до поля, CLI возвращает код `2` без traceback.
Файлы без `pipeline_version` читаются как legacy; несовпадение версии — ошибка.
`version` в `quality-metrics.json` — версия **проекта**, а не контракта файлов.

## 5. Метрики качества

| Метрика | Что измеряет | Вес по умолчанию |
|---|---|---:|
| Readability | отклонение средней длины предложения от 17 слов | 0.25 |
| Clarity of goals | долю из пяти регулярных категорий измеримых формулировок | 0.25 |
| Scenario coverage | долю `BR-N` из входа, упомянутых в результате | 0.30 |
| Consistency | Jaccard между повторными генерациями или эвристика при `runs = 1` | 0.20 |

`overall` — взвешенное среднее **известных** метрик с перенормировкой весов.
Если ни одна измеримая метрика не имеет положительного веса, `overall = None`
и в отчёте печатается `n/a`. Сценарий успешен при `overall ≥ 0.5`.

**Статус clarity.** Текущая формула `0.2 × 5` работает (Runtime), но не проверена
данными. Пересмотр — Target: нужны 100–150 фрагментов, два независимых
разметчика и согласие `Cohen κ ≥ 0.6`. Пилот на двух моделях — Experiment и
проверяет только инструменты; на нём формулу не меняют.

## 6. Конфигурация и управление

Приоритет: **CLI → env → значения по умолчанию**.

| Параметр | Где задаётся | Назначение |
|---|---|---|
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT` | env / `--base-url`, `--model`, `--timeout` | подключение к модели |
| `GRADUATION_PROMPT_DIR`, `GRADUATION_PRESETS_DIR`, `GRADUATION_NORMALIZER_CONFIG` | env / `--prompt-dir` | переопределение ресурсов |
| `GRADUATION_QUALITY_WEIGHTS` | env / `--quality-weights` | веса `overall` |
| `GRADUATION_OUTPUT_DIR` | env / `--output-dir` | папка результатов |

Веса валидируются: ровно четыре метрики, конечные значения `≥ 0`, сумма `1.0`.
Ошибка даёт код `2`. `--assess` берёт веса из снимка, поэтому пересчёт не
зависит от текущего окружения.

## 7. Стенд и запуск

Общий стенд описан в `infra/compose.yaml`: `ohw-ollama` (порт 11434), образ
`ohw-python:3.13`, сеть `ohw_net`. Модель лежит в volume `ohw_ollama_models`;
при переключении CPU↔GPU она не скачивается повторно.

| Режим | Команда |
|---|---|
| CPU | `.\run.ps1` / `./run.sh` / `./infra/up.sh graduation-project` |
| NVIDIA GPU | `.\run.ps1 -Gpu` / `./infra/up.sh graduation-project --gpu` |
| AMD ROCm | `./infra/up.sh graduation-project --amd` |

Проверенный живой прогон на SDD-требованиях: `1 passed, 208 deselected`,
`overall = 0.382`, `consistency = 0.618` при `runs = 2`; пик VRAM около 5.3 ГБ
из 8 ГБ на RTX 2070 SUPER.

## 8. Принятые решения и ограничения

- **Самодостаточность:** всё нужное вендорировано; нет path-зависимости от ДЗ.
- **Без LLM-судьи:** метрики детерминированы, модель не оценивает текст.
- **Без `jsonschema`:** контракты артефактов описываются pydantic-моделями.
- **`None` вместо нуля:** неизмеримое значение не подменяется фиктивной оценкой.
- **Legacy-совместимость:** старые файлы читаются, `PIPELINE_VERSION` не повышался.
- **UI на весах по умолчанию:** редактор весов и LRU отложены как преждевременные.
- **clarity не меняется** без размеченных данных.

## 9. Глоссарий

| Термин | Значение в проекте |
|---|---|
| **Артефакт** | сгенерированный файл одного из пяти типов: testcases, checklist, testplan, qareport, coveragematrix |
| **Фаза (phase)** | шаг пайплайна: generate, assess, visualize, report |
| **Снимок (snapshot)** | `generation.json`: всё, нужно для пересчёта метрик без модели |
| **Отчёт (report)** | `quality-metrics.json` как источник правды; `report.md` — только представление |
| **Rendered** | итоговый Markdown-текст сценария, который оценивают метрики |
| **Generation / run** | один вариант генерации; `runs > 1` даёт честную консистентность |
| **Attempts** | число попыток с учётом retry до получения валидного ответа |
| **`BR-N`** | идентификатор требования (`BR-1`, `BR-12`); регистр не важен, дубликаты отбрасываются |
| **Expected / found** | IDs требований во входе и в результате; основа coverage |
| **Coverage** | `|expected ∩ found| / |expected|`; `n/a`, если ожидаемых IDs нет |
| **Consistency** | средняя попарная Jaccard-близость повторов; при `runs = 1` — эвристика по нумерации `BR-N` |
| **Readability** | `1 − |avg_words − 17| / 30`, ограниченное `[0, 1]` |
| **Tolerance** | допуск длины предложения (сейчас `30` в коде), не настраивается без данных |
| **Clarity of goals** | доля из пяти regex-категорий; формула `0.2 × категории` |
| **`signals`** | категории, которые видит текущая метрика; не являются разметкой |
| **`measurable`** | бинарное человеческое решение: есть ли проверяемая цель |
| **`rating`** | человеческая оценка чёткости фрагмента 1–5 |
| **`clarity_score`** | число метрики; не смешивать с `rating` |
| **Cohen κ** | согласие двух разметчиков с поправкой на случайное совпадение |
| **Взвешенный kappa** | согласие по оценкам 1–5 с учётом расстояния между категориями |
| **Train / holdout** | детерминированное деление фрагментов по `id`; веса выводятся на train |
| **Construct validity** | соответствует ли метрика тому, что она должна измерять |
| **`overall`** | взвешенное среднее известных метрик; `n/a`, если измеримых весов нет |
| **`n/a`** | неизмеримо, а не ноль; печатается в отчёте вместо числа |
| **`quality_weights`** | фактические веса, сохранённые в обоих JSON-файлах |
| **`pipeline_version`** | версия контракта файлов (`0.1.0`); отличается от версии проекта |
| **`version`** | версия проекта/схемы отчёта (`0.5.0`) в `quality-metrics.json` |
| **`QUALITY_THRESHOLD`** | порог успешности сценария (`0.5`) |
| **`--fail-under`** | CLI-порог для кода возврата `5` |
| **`--dry-run`** | подготовка промптов без вызова Ollama |
| **Пресет** | файл `*.toml` с дополнительными инструкциями в промпт |
| **Нормализатор** | детерминированный компонент DZ2, готовый требования перед промптом |
| **Ollama** | локальный сервер моделей в контейнере `ohw-ollama` |
| **`ohw_net`** | общая Docker-сеть проектов и инфраструктуры |
| **UI session state** | состояние Streamlit между rerun-ами; LRU пока не вводится |
