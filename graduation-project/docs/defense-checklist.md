## 1. Один абзац о проекте

Выпускной проект по файлам требований `.md`/`.txt` генерирует тестовую
документацию пяти типов (`testcases`, `checklist`, `testplan`, `qareport`,
`coveragematrix`) локальной моделью `qwen2.5:7b-instruct` и оценивает её четырьмя
детерминированными метриками. Есть CLI с четырьмя фазами, Streamlit-рабочее место
с пятью вкладками, JSON-контракт между фазами, pydantic-валидация артефактов,
графики и Markdown-отчёт. Всё нужное вендорировано; соседние ДЗ не импортируются.

## 2. Что показать на демо

```powershell
# Полный пайплайн на GPU (или .\run.ps1 для CPU)
.\run.ps1 -Gpu

# Только промпты, без Ollama
python -m src.workflow --dry-run --input-dir input --output-dir output/prompts

# Кастомные веса overall
python -m src.workflow --quality-weights `
  readability=0.40,clarity_goals=0.20,scenario_coverage=0.20,consistency=0.20

# Пересчёт метрик по сохранённому снимку
python -m src.workflow --assess --output-dir output
```

Живой e2e-тест, зафиксированный в документации:

```bash
RUN_OLLAMA_INTEGRATION=1 uv run pytest -m integration
```

Результат того прогона: `1 passed, 208 deselected in 13.86s`,
`overall = 0.382`, `consistency = 0.618` при `runs = 2`.

## 4. Метрики

| Метрика | Формула | Вес |
|---|---|---:|
| Readability | `1 − |avg_words − 17| / 30`, clamp `[0, 1]` | 0.25 |
| Clarity of goals | `0.2 × 5 regex-категорий` | 0.25 |
| Scenario coverage | `|expected ∩ found| / |expected|` по `BR-N` | 0.30 |
| Consistency | Jaccard между runs; при `runs = 1` — эвристика | 0.20 |

`overall` — взвешенное среднее известных метрик с перенормировкой. Если нет
ни одной измеримой метрики с положительным весом — `n/a`, а не `0.0`. Сценарий
успешен при `overall ≥ 0.5`; `--fail-under` меняет код возврата на `5`.

## 6. Ответы на типичные вопросы

**Почему не `jsonschema`?** Контракты артефактов описаны pydantic-моделями в
`src/contracts.py`. `jsonschema` добавил бы вторую схему и новую зависимость без
внешнего потребителя. При необходимости JSON Schema можно сгенерировать из
pydantic.

**Почему загрузка файлов валидируется?** Битый JSON или отсутствующий `filename`
раньше давали `KeyError` и traceback. Теперь ошибка называет файл и поле, CLI
возвращает код `2`. Legacy-файлы без `pipeline_version` читаются как раньше.

**Почему веса сохраняются в JSON?** `--assess` пересчитывает метрики по снимку и
должен быть независим от текущего env. Фактические веса лежат в `quality_weights`
обоих JSON-файлов; `report.md` печатает их. Приоритет: CLI → env → defaults.

**Почему `PIPELINE_VERSION = 0.1.0`, а проект 0.7.0?** Это разные вещи: версия
контракта файлов не менялась, старые артефакты читаются. `version` в
`quality-metrics.json` — версия проекта.

**Почему нет LLM-судьи?** Метрики детерминированы и воспроизводимы. Модель
используется только для генерации, а не для оценки. Два модельных «разметчика»
в clarity-пилоте — сухой прогон инструментов, не эталонная разметка.

**Почему clarity не пересмотрена?** Нет человеческой разметки. Инструменты
готовы (экспорт, гайд, kappa, train/holdout); триггер возврата записан в
`CHANGE_PROPOSAL.md`. Равные веса `0.2` на пилоте не проиграли выведенным.

**Почему UI не редактирует веса?** Пять вкладок уже покрывают сценарий; редактор
весов и LRU отложены как преждевременные без запроса от пользователей.

**Зачем `--dry-run`?** Проверять шаблоны промптов, пресеты и нормализацию без
Ollama и без записи `generation.json`. Использует те же функции сборки, что и
обычная генерация.
