# Метрики качества

Все метрики детерминированные: один и тот же текст даёт один и тот же результат.
LLM-судья не используется. Значение `None` означает «метрику нельзя измерить»;
в отчётах оно печатается как `n/a` и **не** заменяется нулём.

## 1. Readability (читаемость)

Оценивает среднюю длину предложения. Оптимум — 17 слов.

```text
avg = total_words / sentence_count
readability = clamp(1 - |avg - 17| / 30, 0, 1)
```

- `1.0` — средняя длина ровно 17 слов;
- `0.0` — отклонение 30 слов и больше;
- пустой текст → `0.0`.

Перед подсчётом удаляются code fences, разделители Markdown-таблиц и разметка.
Предложения делятся по `.`, `!`, `?`, `…`.

Пример: 8 слов → `1 - 9/30 = 0.7`.

## 2. Clarity of goals (чёткость целей)

Пять независимых категорий измеримых формулировок. Каждая добавляет `0.2`.

| № | Категория | Примеры |
|---:|---|---|
| 1 | Модальность | `должен`, `должна`, `должно`, `должны`, `must`, `shall`, `should` |
| 2 | Ожидание | `ожидаем`, `expected` |
| 3 | Проверка | `проверить`, `убедиться`, `верифицировать`, `verify` |
| 4 | Запрет | `не должен`, `нельзя`, `must not` |
| 5 | Результат | `результат`, `поведение`, `сообщение`, `result`, `behavior`, `output` |

Формула: `0.2 × количество найденных категорий`.

Ограничение: метрика поощряет формальные слова, а не смысловую полноту.
Это осознанно: она должна быть воспроизводимой.

## 3. Scenario coverage (покрытие требований)

Доля уникальных `BR-N` из входного файла, упомянутых в сгенерированном тексте.

```text
coverage = |expected ∩ found| / |expected|
```

- `expected` — идентификаторы из входного файла;
- `found` — идентификаторы в результате;
- если `expected` пуст → `None` (`n/a`);
- если `expected` есть, а `found` пуст → `0.0`.

Поиск регистронезависимый, `BR-2` и `br-2` считаются одним требованием.

## 4. Consistency (консистентность)

### При `--runs N ≥ 2`

Средняя попарная Jaccard-близость множеств слов (длина > 2) между повторными
генерациями:

```text
J(A, B) = |A ∩ B| / |A ∪ B|
consistency = mean(J(pair))
```

`1.0` — генерации совпадают, `0.0` — нет общих слов.

### При `--runs 1`

Внутренняя эвристика:

- `0.8`, если номера `BR-N` образуют непрерывную последовательность;
- `0.5` иначе.

Это **не** воспроизводимость. В отчёте поле `runs` показывает `1`, чтобы
читатель не принял эвристику за измерение.

## 5. Overall

Взвешенное среднее известных метрик:

| Метрика | Вес |
|---|---:|
| Readability | 0.25 |
| Clarity of goals | 0.25 |
| Scenario coverage | 0.30 |
| Consistency | 0.20 |

```text
overall = Σ(w_i × metric_i) / Σ(w_i)   # только известные метрики
```

Веса перенормируются, если часть метрик равна `None`. Если известных метрик
нет, `overall = 0.0`.

Сценарий считается успешным при `overall ≥ 0.5`.

## 6. Агрегация

Средние по сценариям считаются только по известным значениям. Если у всех
сценариев метрика `None`, среднее тоже `None` (`n/a`).

## 7. Ограничения

- Readability не учитывает смысл и структуру, только длину предложений.
- Clarity реагирует на ключевые слова, а не на качество формулировок.
- Coverage проверяет ссылки на `BR-N`, а не фактическое покрытие логики.
- Consistency зависит от температуры и промпта; при одном run не измеряется.
- Overall — компромиссная оценка, а не гарантия качества.
- Метрики не заменяют ревью тест-документации человеком.
