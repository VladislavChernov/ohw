# Предложение: настраиваемые веса overall (P1)

## Зачем

Сейчас веса `overall` зашиты в `src/quality/assessor.py`:
readability 0.25, clarity 0.25, coverage 0.30, consistency 0.20. Для одного
проекта важнее покрытие требований, для другого — воспроизводимость или
читаемость. Без настройки приходится менять код, а значит терять
воспроизводимость прогона и усложнять CI.

`overall` влияет на успешность сценария (`≥ 0.5`) и на `--fail-under`, поэтому
веса должны быть явными, проверяемыми и сохранёнными вместе с результатами.

## Что входит

1. `--quality-weights` в CLI:
   `readability=0.25,clarity_goals=0.25,scenario_coverage=0.30,consistency=0.20`.
2. Переменная окружения `GRADUATION_QUALITY_WEIGHTS` в том же формате.
3. Приоритет: CLI → env → значения по умолчанию.
4. Валидация:
   - ровно четыре известные метрики;
   - числа конечные и `≥ 0`;
   - сумма весов равна `1.0` (допуск `1e-6`);
   - неизвестная, пропущенная или повторная метрика — понятная ошибка.
5. Сохранение фактических весов в `generation.json` и `quality-metrics.json`
   в ключе `quality_weights`.
6. Повторное использование весов из файла стадиями `assess`; файлы без ключа
   используют значения по умолчанию.
7. Отображение весов в `report.md`.
8. Тесты парсинга, приоритета, валидации, расчёта и сериализации.
9. Документация: OpenSpec, SDD, README, user guide, `docs/metrics.md`.

## Что не входит

- UI-редактор весов: вкладка «Генерация» продолжает использовать значения по
  умолчанию. Это отдельный шаг, если появится запрос.
- Пересмотр формулы `clarity`, schema validation, `--dry-run` и остальные
  P1/P2 из `CHANGE_PROPOSAL.md`.
- Изменение порога успешности `overall ≥ 0.5`.

## Поведение по умолчанию

Без флага и env веса остаются прежними, поэтому результаты `0.1.0`
воспроизводятся один в один. Новый ключ `quality_weights` необязателен:
legacy-файлы читаются со значениями по умолчанию.

## Критерии приёмки

- `--quality-weights` меняет `overall` и сохраняется в JSON.
- Env используется, если флаг не задан; флаг важнее env.
- Неверная сумма, отрицательный вес, неизвестная или пропущенная метрика дают
  код `2` и понятное сообщение.
- `assess` по сохранённому снимку использует те же веса, что и `generate`.
- Legacy-файлы без `quality_weights` читаются с весами по умолчанию.
- `report.md` показывает использованные веса.
- `pytest`, `ruff`, `mypy` зелёные.
