# Дизайн: настраиваемые веса overall (P1)

## Контекст

`overall` считается в `weighted_overall` и используется в `assess_quality`.
Сейчас веса — константа `WEIGHTS` в `src/quality/assessor.py`. Чтобы не
протаскивать конфигурацию через все фазы заново, фактические веса становятся
частью `PipelineData` и сохраняются в обоих JSON-файлах.

## Формат

```text
--quality-weights readability=0.25,clarity_goals=0.25,scenario_coverage=0.30,consistency=0.20
GRADUATION_QUALITY_WEIGHTS=readability=0.25,clarity_goals=0.25,scenario_coverage=0.30,consistency=0.20
```

- Ключи — точные имена метрик: `readability`, `clarity_goals`,
  `scenario_coverage`, `consistency`.
- Значения — конечные неотрицательные числа.
- Сумма — `1.0` с допуском `1e-6`.
- Порядок ключей не важен; результат нормализуется в порядке `METRIC_KEYS`.
- Пробелы вокруг элементов и `=` допускаются.

## Приоритет

| Источник | Когда используется |
|---|---|
| `--quality-weights` | всегда, если задан |
| `GRADUATION_QUALITY_WEIGHTS` | если флаг не задан, а env непустая |
| значения по умолчанию | если нет ни флага, ни env |

Пустая env-строка трактуется как отсутствие значения.

## Валидация

| Ситуация | Результат |
|---|---|
| все четыре ключа, сумма 1.0 | веса принимаются |
| пропущен ключ | `ValueError` со списком пропущенных |
| неизвестный ключ | `ValueError` со списком допустимых |
| ключ повторён | `ValueError` |
| значение не число | `ValueError` |
| `NaN`, `inf`, отрицательное | `ValueError` |
| сумма ≠ 1.0 | `ValueError` с фактической суммой |

CLI превращает `ValueError` в `parser.error`, поэтому код возврата — `2`.
Python-интерфейс получает то же исключение.

## Поток данных

```text
CLI/env ──▶ resolve_quality_weights ──▶ GenerationRequest.quality_weights
                                             │
                                             ▼
                                   generate_scenarios
                                             │
                                             ▼
                     PipelineData.quality_weights ──▶ generation.json
                                             │
                                             ▼
                                      stage assess
                                             │
                                             ▼
                     quality-metrics.json + report.md
```

- `GenerationRequest.quality_weights` пустой означает «по умолчанию».
- `generate_scenarios` валидирует веса один раз и передаёт их в
  `assess_quality` для каждого сценария.
- `stages.generate` записывает фактические веса в `PipelineData`.
- `stages.assess` берёт веса из `PipelineData`, поэтому пересчёт метрик не
  зависит от текущего окружения.
- `visualize` и `report` веса не пересчитывают, а только показывают.

## Персистентность и совместимость

`quality_weights` добавляется в `generation.json` и `quality-metrics.json`.
Ключ необязательный:

- файл без ключа — legacy, используются веса по умолчанию;
- файл с невалидными весами — `ValueError`, как и при чтении битого контракта;
- `pipeline_version` не повышается: старые читатели игнорируют необязательный
  ключ, новые читатели понимают его отсутствие.

## Отчёт

В `## Общая информация` появляется строка:

```text
| Веса overall | readability=0.25, clarity_goals=0.25, scenario_coverage=0.30, consistency=0.20 |
```

JSON-отчёт содержит те же веса в `quality_weights`, поэтому число в Markdown
всегда можно пересчитать по источнику правды.

## Альтернативы

- **Четыре позиционных числа.** Компактно, но непонятно без документации и
  легко перепутать порядок; отклонено.
- **Разрешить частичные веса с автоперенормировкой.** Удобно, но скрывает
  фактическое распределение и усложняет валидацию; отклонено для 0.2.0.
- **Хранить веса только в CLI-аргументах.** Тогда `--assess` по снимку
  пересчитает метрики другими весами; отклонено.
- **Добавить UI-редактор сразу.** Расширяет объём и требует синхронизации
  session state; вынесено в отдельный шаг.
