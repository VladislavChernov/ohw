# Предложение: guard-тесты документации и лаунчеров

## Зачем

Две проблемы уже проявлялись в работе и могут вернуться незаметно:

1. Кириллица в `.md` иногда приходит битой (`U+FFFD`, управляющие символы).
   Визуально это видно не всегда, а отчёт и документация становятся мусором.
2. Лаунчеры `run.ps1` / `run.sh` / `run.cmd` легко сломать правкой: PowerShell
   5.1 не читает UTF-8 без BOM, а контракт «поднять infra, дождаться Ollama,
   передать аргументы» нигде не зафиксирован.

## Что входит

- `tests/test_docs_encoding.py` — проверка всех `.md` проекта на `U+FFFD` и
  управляющие символы; исключения: `.venv`, `output`, кэши.
- `tests/test_launchers.py` — контракт лаунчеров:
  - `run.ps1` содержит только ASCII;
  - ссылается на `..\infra\compose.yaml` и проверяет `ohw-ollama`;
  - при аргументах вызывает `compose run`, без аргументов — `compose up`;
  - `run.cmd` делегирует в `run.ps1`;
  - `run.sh` проходит `sh -n` и содержит те же шаги.
- Документация: короткое упоминание в README и `openspec/changes/tasks.md`.

## Что не входит

- Линтер Markdown, проверка орфографии, проверка ссылок.
- Изменение самих лаунчеров (только фиксация текущего контракта).
- GPU/AMD-флаги: они живут в `infra/`, а не в проекте.

## Критерии готовности

- Тесты падают на подложенном битом `.md` и на лаунчере с кириллицей.
- На текущем репозитории оба теста зелёные.
- `uv run pytest` не требует Ollama и сети.
