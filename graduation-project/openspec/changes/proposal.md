# Предложение по объёму выпускного проекта

## Что входит в реализацию

1. Генерация пяти типов тестовой документации через локальную Ollama:
   `testcases`, `checklist`, `testplan`, `qareport`, `coveragematrix`.
2. Вендоринг ядра DZ2: загрузка требований, нормализатор, промпты, пресеты,
   валидация, retry и рендеринг. Проект самодостаточен и не импортирует `../dz2`.
3. Четыре детерминированные метрики качества: читаемость, чёткость целей,
   покрытие требований, консистентность.
4. Повторная генерация `--runs N` для честной консистентности (Jaccard).
5. CLI-пайплайн: `generate -> assess -> visualize -> report`, каждая фаза может
   запускаться отдельно по сохранённым файлам.
6. JSON-отчёт как источник правды с реальными тест-кейсами.
7. Markdown-отчёт в формате задания.
8. Три PNG-графика: boxplot, radar, оценки по сценариям.
9. Docker-запуск на общем стенде `infra/` (`ohw-ollama`, `ohw-python:3.13`,
   сеть `ohw_net`), скрипты `run.ps1` / `run.sh` / `run.cmd`.
10. Unit-тесты (53+) и опциональный integration-тест с живой Ollama.
11. OpenSpec-документы, единый SDD, README и docs.

## Что сознательно не входит

- Streamlit-вкладка и любой веб-интерфейс.
- Проверка и оптимизация автотестов (DZ6).
- Собственный Ollama, собственная Docker-сеть, собственные постоянные контейнеры.
- Обучение модели, LLM-судья текста, генерация синтетических good/bad датасетов.
- Зависимость на `ai-testcase-generator` или другие пакеты ДЗ во время выполнения.
- Изменение исходников `dz2/`, `dz7/`, `dz8/`.

## Критерии готовности

- `./run.ps1` (или `./run.sh`) поднимает общий `ohw-ollama` при необходимости,
  собирает приложение и выполняет полный пайплайн.
- В `output/` появляются `scenarios/*.md`, `generation.json`,
  `quality-metrics.json`, `report.md`, `charts/*.png`.
- `uv run pytest` проходит без Ollama; integration-тест включается переменной
  `RUN_OLLAMA_INTEGRATION=1`.
- `ruff check` и `mypy src` проходят без ошибок.
- Документация описывает фактическое поведение, а не псевдокод.
