# Дизайн: веса и сброс состояния в UI

## Контекст

`GenerationRequest.quality_weights` уже поддерживается стадиями и CLI. UI
создаёт запрос без этого поля, поэтому `generate_scenarios` подставляет значения
по умолчанию. Веса нужно передать из сайдбара, не добавляя шестую вкладку.

## Состояние

`STATE_DEFAULTS` — модульный словарь со всеми ключами `session_state`, включая
`quality_weights = dict(DEFAULT_QUALITY_WEIGHTS)`. `_init_state()` использует
`setdefault`, `_reset_state()` удаляет перечисленные ключи и вызывает
`_init_state()`. Кнопка «Очистить состояние» не трогает файлы в `output/`.

## Панель весов

На сайдбаре четыре `number_input` (min `0.0`, step `0.01`). Значения пишутся в
`st.session_state["quality_weights"]`; под полями печатается
`format_quality_weights`. При неверной сумме или отрицательном значении
показывается `st.error`, но UI остаётся работоспособным.

Перед генерацией `_run_generation()` вызывает `validate_quality_weights`. При
ошибке выводится сообщение и запрос не создаётся — неверные веса не попадают в
артефакты. Валидные веса передаются в `GenerationRequest`; стадии сохраняют их в
`generation.json` и `quality-metrics.json` так же, как при CLI-запуске.

## Прочее

Вкладка «Метрики» печатает строку `Веса overall: ...` из `data.quality_weights`.
Подсказки «Сначала выполните генерацию на вкладке 2» исправлены на вкладку 3.

## Альтернативы

- **Редактор внутри вкладки «Генерация».** Добавил бы elements в уже плотную
  вкладку; сайдбар логичнее для настроек.
- **LRU вместо кнопки сброса.** Требует политики вытеснения и усложняет
 состояние без реальной необходимости; достаточно явного сброса.
- **Хранить веса только в env.** UI работает в браузере и должен показывать
  фактические веса рядом с метриками; env не даёт такой обратной связи.
