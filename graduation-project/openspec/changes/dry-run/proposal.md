# Предложение: режим `--dry-run`

## Зачем

Сейчас посмотреть, какой именно промпт уйдёт в модель, можно только после
реального прогона: текст промпта сохраняется в `generation.json` как `prompt`.
Это требует доступной Ollama и тратит время. Для отладки шаблонов, пресетов,
нормализации и правок промпта из UI нужен способ собрать те же промпты без
вызова модели.

## Что меняется

1. Флаг `--dry-run` в CLI. Он запускает только подготовку промптов и записывает
   их в `output/prompts/` без обращения к Ollama.
2. Функция `build_prompt_previews` в `src/generator/pipeline.py`: использует те
   же шаблоны, пресеты, нормализацию и user-prompt overrides, что и обычная
   генерация.
3. Стадия `stages.dry_run`: пишет `<stem>.system.txt`, `<stem>.user.txt` и
   `manifest.json` с метаданными и SHA-256 пользовательского промпта.
4. Тесты: промпты совпадают с обычным прогоном, Ollama не вызывается, снимок
   не создаётся, несовместимые фазы отклоняются.
5. Документация: OpenSpec, SDD, README, user guide, `CHANGELOG.md`.

## Что не меняется

- Обычная генерация, метрики и формат `generation.json`.
- `PIPELINE_VERSION = "0.1.0"` и `PROJECT_VERSION = "0.3.0"`.
- UI: пяти вкладок и поведения генерации это не касается.
- Веса `overall` и `--quality-weights` в dry-run не используются.

## Критерии приёмки

- `--dry-run` возвращает `0` без доступной Ollama и не создаёт
  `generation.json`.
- Пользовательский промпт из dry-run побайтово совпадает с `prompt` в снимке
  обычного прогона с теми же параметрами.
- Для `coveragematrix` в манифесте есть пояснение, что список тест-кейсов
  будет подставлен только при реальном прогоне.
- `--dry-run` вместе с `--assess`/`--visualize`/`--report` даёт код `2`.
