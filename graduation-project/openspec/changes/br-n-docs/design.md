# Дизайн: документация `BR-N` и эвристика консистентности

## Контекст

`extract_requirement_ids` ищет `BR-\d+` без учёта регистра, убирает дубликаты
и сортирует ids численно. Эти же IDs:

- задают `expected` для `scenario_coverage`;
- подставляются в правило трассируемости промпта;
- используются в эвристике `assess_internal_consistency` при `--runs 1`.

Раньше эвристика возвращала `0.5` даже при отсутствии ссылок. Нейтральная
оценка создавала видимость измерения там, где данных нет.

## Решение

```python
ids = extract_requirement_ids(text)
if len(ids) < 2:
    return None
numbers = sorted(int(value.split("-")[1]) for value in ids)
return 0.8 if numbers == list(range(numbers[0], numbers[-1] + 1)) else 0.5
```

Проверка непрерывности сохраняется: она оценивает только внутреннюю
последовательность номеров в тексте, а не совпадение с входными требованиями —
за это отвечает `scenario_coverage`.

`None` согласуется с общим правилом проекта: неизмеримое значение не подменяется
числом. `weighted_overall` перенормирует веса без этого члена.

## Альтернативы

- **Оставлять `0.5` при отсутствии ссылок.** Проще, но выдаёт оценку за
  измерение; отклонено.
- **Возвращать `0.0`.** Ещё хуже: отсутствие данных трактуется как плохое
  качество; отклонено.
- **Сравнивать ids с входными требованиями внутри эвристики.** Дублирует
  `scenario_coverage` и смешивает две метрики; отклонено.
- **Автоматически перенумеровывать требования.** Меняет пользовательские данные
  и ломает трассировку; отклонено.
