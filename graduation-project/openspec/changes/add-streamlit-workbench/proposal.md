# Предложение: Streamlit-рабочее место

## Зачем

Сейчас у проекта два фронта нет: есть CLI, файлы и графики. Для демонстрации и
ручной работы это неудобно: чтобы прогнать пайплайн, нужно помнить флаги, а
результаты смотреть в файлах. В ДЗ2 рабочее место на Streamlit уже
зарекомендовало себя, и выпускной проект — сборник ДЗ, поэтому UI должен быть
и здесь.

UI не добавляет новой бизнес-логики. Он вызывает те же стадии, что и CLI:
генерацию, оценку, визуализацию и отчёт. Поэтому результаты совпадают, а
поведение CLI не меняется.

## Что входит

1. `src/ui/` — Streamlit-приложение и launcher.
2. Пять вкладок: требования, промпт, генерация, метрики, отчёт.
3. Загрузка `.md`/`.txt`, редактирование текста, URL, тип артефакта, число
   кейсов, повторы, нормализация и пресеты.
4. Просмотр и правка промпта, собранного из шаблона DZ7 и пресетов; правка
   применяется к выбранному файлу.
5. Подключение к Ollama в боковой панели: URL, список моделей, модель, таймаут,
   температура, папка результатов.
6. Общие стадии `src/workflow/stages.py`, которые используют и CLI, и UI.
7. Просмотр метрик, графиков и `report.md`; скачивание артефактов и отчётов.
8. Docker-сервис `ui` на порту `8501`.
9. Unit-тесты UI через `streamlit.testing.v1.AppTest` без сети.
10. Документация: README, user guide, SDD, OpenSpec.

## Что сознательно не входит

- Аутентификация, роли и многопользовательский режим.
- Фоновые задания и очередь: генерация выполняется в запросе Streamlit.
- Новые метрики, графики и типы артефактов.
- API-тесты.
- Замена CLI: оба фронта остаются равноправными.

## Критерии готовности

- `uv run pytest`, `ruff check`, `mypy src` проходят без Ollama.
- UI открывается без сети и не опрашивает Ollama при старте.
- Загруженный файл проходит полный цикл: генерация → метрики → графики →
  отчёт; артефакты появляются в `output/`.
- CLI и UI используют одни и те же стадии; артефакты CLI не меняются.
- `docker compose up -d ui` открывает рабочее место на `http://localhost:8501`.
