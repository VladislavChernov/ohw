# Предложение: валидация артефактов через pydantic

## Зачем

`generation.json` и `quality-metrics.json` читаются как сырые `dict` и
раскладываются по dataclass-ам вручную. Если файл повреждён или отредактирован
руками, загрузка падает непредсказуемо:

- `ScenarioResult.from_snapshot_dict` обращается к `raw["filename"]`, поэтому
  отсутствующее поле даёт `KeyError`, который CLI не ловит, — пользователь
  видит traceback вместо кода возврата `2`;
- неверные типы (`attempts: "много"`, `scenarios: {}`) приводят к ошибкам
  `int()`/`list()` с сообщением без имени файла и поля;
- битый JSON сообщает позицию парсера, но не имя артефакта.

`pydantic` уже является зависимостью проекта, поэтому отдельная `jsonschema`
не нужна.

## Что меняется

1. Новый модуль `src/contracts.py` с pydantic-моделями:
   - `QualityMetricsPayload`;
   - `ScenarioSnapshot` и `SnapshotDocument` для `generation.json`;
   - `ScenarioReport` и `ReportDocument` для `quality-metrics.json`.
2. Загрузка артефактов валидирует JSON один раз и возвращает типизированный
   документ; dataclass-ы строятся из уже проверенных полей.
3. Ошибки чтения и валидации превращаются в `ValueError` с именем файла и
   путём до поля. CLI уже переводит `ValueError` в код `2`.
4. Legacy-поведение сохраняется: отсутствующие `pipeline_version`,
   `quality_weights`, метаданные и необязательные поля заполняются значениями
   по умолчанию.
5. Неизвестные поля игнорируются, чтобы новые необязательные ключи не ломали
   старых читателей.
6. Тесты: битый JSON, отсутствующее `filename`, неверный тип, legacy-файл,
   лишние поля, `--assess`/`--report` на повреждённом файле.
7. Документация: OpenSpec, SDD, user guide, README.

## Что не меняется

- `pipeline_version` остаётся `0.1.0`: формат файлов совместим.
- Новые зависимости не добавляются.
- `jsonschema` не вводится: внешнего потребителя схемы нет.
- Формулы метрик, веса `overall` и коды возврата не меняются.
- UI и CLI продолжают использовать одни и те же стадии загрузки.

## Критерии приёмки

- `--assess` на снимке без `filename` возвращает код `2` без traceback и
  называет файл и поле.
- `--report` на повреждённом `quality-metrics.json` ведёт себя так же.
- Валидные и legacy-файлы читаются без изменений в результатах.
- `pytest`, `ruff`, `mypy` зелёные.
