# История версий

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют SemVer. Запись описывает изменения проекта, а не историю
редактирования `SDD.md` — последняя ведётся в самом SDD.

## [Unreleased]

### Добавлено

- `docs/defense-checklist.md` — памятка к защите; статусы рекомендаций ревью
  сведены в `CHANGE_PROPOSAL.md`.
- Редактор весов `overall` в UI, валидация перед генерацией и кнопка
  «Очистить состояние»; исправлены номера вкладок в подсказках.

## [0.6.0] — 2026-11-17

### Добавлено

- `scripts/annotate_with_models.py` — подготовка промптов и валидация ответов
  моделей-разметчиков для сухого прогона инструментов clarity.
- `CONCEPT.md` — целостное описание выпускного проекта и глоссарий терминов.

### Изменено

- Анализ clarity печатает взвешенный kappa для оценок 1–5; гайд уточняет,
  что подпись «Проверяет требование» — трассируемость, а не `verification`.
- `CHANGE_PROPOSAL.md`: пересмотр clarity отложен до человеческой разметки, зафиксирован
  триггер возврата и критерии решения.

## [0.5.0] — 2026-11-16

### Добавлено

- `.\run.ps1 -Gpu` — NVIDIA CUDA-режим по образцу ДЗ: проверка nvidia-рантайма,
  подключение `infra/compose.gpu.yaml` и принудительное пересоздание
  уже запущенного CPU-контейнера.

### Изменено

- `run.sh` остаётся CPU-only и делегирует старт инфраструктуры в `infra/up.sh`.
- `docs/demo.md` и SDD: цифры живого e2e-прогона на GPU обновлены до
  `1 passed, 208 deselected`, `overall = 0.382`, `consistency = 0.618`.

## [0.4.0] — 2026-11-16

### Добавлено

- `--dry-run`: подготовка system- и user-промптов в `output/prompts/` без вызова
  Ollama и без записи `generation.json`.
- Раздел README с правилами `BR-N`: формат, регистр, уникальность и связь с
  покрытием.

### Изменено

- Эвристика консистентности при `--runs 1` возвращает `n/a` (`None`), если в
  тексте меньше двух ссылок `BR-N`, вместо нейтральных `0.5`.

## [0.3.0] — 2026-11-16

### Добавлено

- Валидация `generation.json` и `quality-metrics.json` по pydantic-моделям
  (`src/contracts.py`) до построения dataclass-ов.
- Сообщения об ошибках называют файл и путь до поля, например
  `generation.json: неверный формат артефакта — scenarios[0].filename: обязательное поле отсутствует`.
- Инструменты подготовки данных для `clarity`: экспорт фрагментов в JSONL
  (`scripts/export_clarity_sample.py`), гайд разметки (`docs/clarity-annotation.md`)
  и анализ с Cohen's kappa, корреляциями и split train/holdout
  (`scripts/analyze_clarity.py`).
- Аксессор `clarity_signals()` для диагностики категорий; формула метрики
  `assess_clarity_goals` не изменена.
- Отдельный файл истории версий `CHANGELOG.md` с записями о предыдущих релизах.

### Изменено

- `docs/demo.md`: строка `веса overall` в выводе, раздел о смене весов, пример
  ошибки повреждённого снимка и актуальные числа тестов.
- OpenSpec: новые изменения `validate-artifacts` и `clarity-data-kit`,
  уточнена спецификация контракта пайплайна.
- SDD: контракты, таблица ошибок, инструменты clarity, история документа.

### Исправлено

- Ранее повреждённый снимок мог вызвать `KeyError` и traceback; теперь это
  понятная ошибка входа с кодом возврата `2`.
- Ошибки весов в файле тоже получили префикс с именем артефакта.
- Разбор аннотаций принимает вложенный формат `{"id": ..., "annotation": {...}}`,
  описанный в гайде.
- Локальная проверка `ruff` (UP012) и `mypy`/`pytest` зелёные, CI #104–#105.

### Не изменилось

- `PIPELINE_VERSION` остался `0.1.0`: формат файлов совместим с legacy.
- Формулы метрик, веса `overall`, порог `0.5`, UI с пятью вкладками.
- `clarity` по-прежнему `5 категорий × 0.2` до появления размеченных данных.

## [0.2.0] — 2026-11-15

### Добавлено

- Настраиваемые веса `overall`: `--quality-weights` и
  `GRADUATION_QUALITY_WEIGHTS` с приоритетом CLI → env → значения по умолчанию.
- Валидация весов: ровно четыре метрики, конечные неотрицательные значения,
  сумма `1.0` с допуском `1e-6`; код возврата `2` при ошибке.
- Веса сохраняются в `generation.json` и `quality-metrics.json` как
  `quality_weights`; `--assess` берёт их из снимка.
- Строка `| Веса overall | ... |` в `report.md`.

### Исправлено

- Битая env-строка весов больше не ломает `--assess`/`--report`: env читается
  только на фазе `generate`.
- Пустой явный `--quality-weights` — ошибка, а не тихий откат к env.
- `overall = n/a`, если ни одна измеримая метрика не имеет положительного веса.
- `quality_weights: null` отклоняется, отсутствующий ключ — legacy-defaults.
- Отчёт сохраняет высокую точность дробных весов.

## [0.1.0] — 2026-11-13

### Добавлено

- Первый самостоятельный выпуск `graduation-project` без path-зависимости от
  соседних домашних заданий.
- Полный пайплайн `generate → assess → visualize → report` с общими стадиями
  для CLI и Streamlit-рабочего места.
- Вендоринг ядра DZ2: загрузка требований, нормализатор, шаблоны промптов
  пяти типов артефактов, пресеты, Ollama-клиент, валидация, retry и рендер.
- Детерминированные метрики `readability`, `clarity_goals`,
  `scenario_coverage`, `consistency` и взвешенный `overall`; `None` вместо
  подмены неизмеримых значений нулём.
- `pipeline_version` в обоих JSON-артефактах: legacy-файлы читаются,
  несовпадение версии — код `2`.
- `--continue-on-error` и per-file recovery при недоступности Ollama.
- Streamlit-рабочее место с пятью вкладками, включая правку промпта DZ7.
- Guard-тесты документации и лаунчеров, integration-тест на требованиях из SDD,
  общий стенд `infra/` (`ohw-ollama`, `ohw-python:3.13`, `ohw_net`).

### Примечания

- DZ6, DZ3 advanced и API-тесты в выпускной проект не входят.
- Модель по умолчанию — `qwen2.5:7b-instruct`.
