# Proposal: генератор API-автотестов через локальную LLM (ДЗ3)

> Черновик. Будет доработан по мере уточнения формата JSON (advanced).

## Зачем

Нужно учебное решение (Otus, ДЗ3): с помощью локальной LLM в Ollama
автоматически генерировать API-автотесты под заданный сервис. Два варианта
приложения в одном репозитории: простой (сдаваемый) и расширенный
(исследовательский, эволюция в MTWS).

## BR (бизнес-требования)

### Общие (оба варианта)

- **BR-1. Локальный LLM.** Подключаться к shared ollama из `infra/`
  (`host.docker.internal:11434`). Модель — для генерации Python/Pytest/Requests
  (simple) или JSON-тест-описаний (advanced).
- **BR-2. Чтение запроса.** Принимать входные данные (URL сервиса, Swagger-спека)
  и генерировать артефакт (код тестов или JSON-описание).
- **BR-3. Целевой сервис.** Тесты пишутся под https://jsonplaceholder.typicode.com.
- **BR-4. Swagger-парсинг.** Загружать и парсить OpenAPI-спецификацию:
  методы, пути, тела, коды ответов, схемы ответов.

### Simple (сдаваемый)

- **BR-S1. Стек кода тестов.** Сгенерированные тесты — Python 3 + Pytest + Requests.
- **BR-S2. Покрытие.** 4 теста, по одному на CRUD (модель выбирает эндпоинты).
- **BR-S3. Проверка тела ответа.** Каждый тест проверяет статус-код + тело.
- **BR-S4. Прохождение.** Тесты запускаются через `pytest` и зелёные.

### Advanced (исследовательский)

- **BR-A1. Движок тестов.** Свой движок, который принимает JSON-описание тестов
  от LLM и выполняет CRUD-запросы к API. Без pytest — свои руки.
- **BR-A2. JSON-формат от LLM.** Модель возвращает JSON-массив тестов:
  эндпоинт + метод + данные для запроса (+ опционально: ожидаемый ответ).
  Точный формат — открытый вопрос.
- **BR-A3. Валидация ответа.** Движок проверяет ответ API (статус-код, тело).
  Источник ожиданий: Swagger и/или JSON от LLM (открытый вопрос).
- **BR-A4. Отчёт.** Результат выполнения: что прошло, что упало, детали.

## Что делаем

Два подпроекта в одном репозитории (`simple/` и `advanced/`):

**Simple**: CLI/скрипт на Python: подключается к shared ollama, отправляет промпт
на генерацию pytest-кода под JSONPlaceholder (модель сама выбирает эндпоинты
по CRUD-типу из Swagger), сохраняет код, прогоняет через pytest, отчитывается.

**Advanced**: CLI/скрипт на Python: подключается к shared ollama, отправляет промпт,
модель возвращает JSON-массив тестов (эндпоинт + данные), движок выполняет
CRUD-запросы к API, проверяет ответы, формирует отчёт.

## Ограничения

- Модель — локальная в Ollama (RTX 2070 SUPER, 8 GB).
- Тесты идут на чужой внешний сервис (есть доступ к интернету) — не выдумывать
  эндпоинты, брать реальные из JSONPlaceholder.
- Репозиторий содержит и простой, и большой варианты (см. разделение ниже).

## Разделение на два варианта (структура кода)

Простой (сдаваемый) и большой (учебный/MTWS) лежат в одном репо `D:\Otus\Dz3`,
не смешиваясь:

```
D:\Otus\Dz3\
  simple\         ← простой вариант (сдаваемый): pytest-код от LLM
  advanced\       ← большой вариант (учебный): JSON от LLM + свой движок
  openspec\       ← спеки обоих вариантов
  README.md
```

Общее между ними (LLM-клиент, Swagger-парсер) — выносится в `shared/` или
остаётся в каждом подпроекте (пока не решено).

## Проверка (критерии приёмки)

### Simple
- Поднят shared ollama, выбрана модель — зафиксировано в `.env`.
- Сгенерированный pytest-файл с 4 тестами (по одному на CRUD) по JSONPlaceholder.
- Каждый тест проверяет статус-код + тело ответа.
- `pytest` — зелёно без ручных правок.

### Advanced (открытый вопрос)
- Движок выполняет CRUD-запросы к JSONPlaceholder по JSON от LLM.
- Результат — отчёт (что прошло/упало).
- Точный формат JSON и отчёта — уточняется.
