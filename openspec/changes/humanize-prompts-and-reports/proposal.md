# Proposal: human-readable assertions and failure reports

## Why

1. The model returns "bare" asserts (`assert "posts" in response.json()`):
   no assert messages, no docstrings, no comments — failures are hard to read.
2. The report's FAILURES section dumps raw pytest tracebacks including the
   full 100-post JSON payload — unusable for a human overview.

## What Changes

- Prompt (`input/prompt.txt`): require human-friendly assertions —
  assert messages on every check, docstrings, named checks per test
  (status code / schema / semantics separately), meaningful test names.
- `runner.py`: parse the `short test summary info` lines into
  `(node, reason)` pairs; add a **"Failed tests"** section to the report in a
  human format (one bullet per failure, short reason, truncated values);
  the full pytest traceback stays in the appendix (Pytest output section).
- Report marks the run report as generated by a specific model+params.

## Impact

- Affected specs: `api-test-generator`
- Affected code: `input/prompt.txt`, `src/api_testgen/runner.py`, `tests/test_core.py`
