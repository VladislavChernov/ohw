# Change: человекочитаемые ассерты и отчёты о падениях

## Почему

1. Модель выдаёт «голые» ассерты (`assert "posts" in response.json()`):
   без сообщений ассертов, docstring'ов и комментариев — падения тяжело читать.
2. Раздел FAILURES в отчёте выводит сырые трейсбеки pytest вместе с полным
   JSON из 100 постов — для человеческого обзора непригодно.

## Что меняется

- Промпт (`input/prompt.txt`): требовать человекочитаемые ассерты —
  сообщения у каждой проверки, docstring'и, именованные проверки в каждом
  тесте (статус-код / схема / семантика раздельно), осмысленные имена тестов.
- `runner.py`: парсинг строк `short test summary info` в пары
  `(узел, причина)`; в отчёте новый раздел **«Failed tests»** в человеческом
  формате (по буллету на падение, короткая причина, обрезанные значения);
  полный трейсбек pytest остаётся приложением (раздел Pytest output).
- В шапке отчёта — модель и параметры, которыми сгенерирован прогон.

## Влияние

- Спеки: `api-test-generator`
- Код: `input/prompt.txt`, `src/api_testgen/runner.py`, `tests/test_core.py`
