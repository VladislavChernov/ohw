# Оценка качества промптов Dz7

Промпты проверяются на стенде Dz2: файл требований прогоняется через
локальную Ollama, промпт и полученный артефакт оцениваются по четырём
критериям. Источник требований — рабочий документ основного проекта
(`dz2/docs/business-requirements_catalog-courses.md`, требования BR-1…BR-7),
а не демонстрационный `login.md`.

## Методика

1. Собрать готовые промпты из шаблонов (их текст — предмет оценки):

   ```bash
   cd dz7
   python3 generator.py \
       --requirements-file business-requirements_catalog-courses.md \
       --all-types --output-dir output/prompts
   ```

2. Собрать те же промпты с пресетами, чтобы оценить вклад дополнительных
   инструкций:

   ```bash
   python3 generator.py \
       --requirements-file business-requirements_catalog-courses.md \
       --all-types --preset boundary-values --preset negative-scenarios \
       --output-dir output/prompts-presets
   ```

   Для типов, к которым пресет неприменим, команда завершится ошибкой —
   поэтому в матрице ниже пары «тип + пресет» выбраны по `types`.

3. Скопировать шаблоны и пресеты на стенд (Dz2 подставит требования каждого
   входного файла сам):

   ```bash
   python3 generator.py --emit-templates --output-dir ../dz2/prompts
   python3 generator.py --emit-presets   --output-dir ../dz2/presets
   ```

4. Поднять стенд на GPU (общий ollama из `infra/`) и прогнать базовые типы.
   Требования кладутся одним файлом, чтобы в прогон не попали уже
   сгенерированные артефакты из `docs/`:

   ```powershell
   Copy-Item docs/business-requirements_catalog-courses.md input/e2e/requirements.md
   .\scripts\up-gpu.ps1
   docker compose run --rm app --count 10 --input-dir /data/input/e2e `
       --all-types --output-dir /data/output/e2e-all `
       --config /data/input/ai-testgen-e2e.toml
   ```

   `input/ai-testgen-e2e.toml` задаёт `timeout = 900`: холодная загрузка
   qwen2.5:7b на 8-ГБ GPU не укладывается в дефолтные 180 с.

   Без Docker (быстрее для одной модели): `uv run ai-testgen -n 10 --all-types`.

5. Повторить прогон с пресетами — по одному запуску на пару «тип + пресет»
   (пресет добавляет в промпт блок «Additional instructions» с запретом
   выдумывать страницы и функции, которых нет в требованиях):

   ```powershell
   $pairs = @(
       @('testcases', 'boundary-values'),
       @('checklist', 'accessibility'),
       @('testplan', 'regression'),
       @('qareport', 'negative-scenarios'),
       @('coveragematrix', 'boundary-values')
   )
   foreach ($p in $pairs) {
       docker compose run --rm app --count 10 --input-dir /data/input/e2e `
           --type $p[0] --preset $p[1] `
           --output-dir "/data/output/e2e-presets/$($p[0])-$($p[1])" `
           --config /data/input/ai-testgen-e2e.toml
   }
   ```

6. Оценить. Оценку ставит LLM-судья по той же рубрике: в рабочем месте
   кнопка «Оценить через LLM» или пакетно из CLI:

   ```powershell
   docker compose run --rm app --count 10 --input-dir /data/input/e2e `
       --all-types --evaluate --output-dir /data/output/e2e-all `
       --config /data/input/ai-testgen-e2e.toml
   ```

   Судья видит **текст промпта**, а не артефакт, и возвращает JSON с баллами,
   комментариями, цитатами и `prompt_sha256`. Каждый критерий оценивается
   отдельным вызовом со своей рубрикой: общий ответ на четыре критерия с
   примером заполнения локальная 7B-модель просто копировала (все десять
   промптов получили 3/4/4/3 — ровно числа из образца). Перед баллом судья
   обязан привести 3–5 дословных цитат из промпта; каждая проверяется на
   вхождение в текст (регистр и пунктуация не важны), выдуманные отбрасываются,
   а ответ без единой реальной цитаты с баллом выше 1 после трёх попыток
   считается ошибкой (код выхода 5). Балл 1 — исключение: элемента нет, и
   цитировать нечего, поэтому комментарий просто называет пропуск. Это отсекает
   «absent» вместо чтения: в версии без цитат модель ставила 1 за читаемость
   всем подряд.
   Файлы лежат в
   `dz2/output/quality/<type>[-<preset>]-<run-id>.json` (UTC-метка прогона в
   имени, внутри — `generated_artifact` со ссылкой на оценённый артефакт и его
   sha256); из них заполняются таблицы ниже. Человек может перепроверить и
   переписать оценку (`source=human`), но
   исходная оценка — модельная. Артефакт в таблице нужен как второй сигнал:
   если промпт хорош, а артефакт плох — это вопрос модели, а не шаблона.

Параметры прогона фиксируются, иначе оценки несравнимы: модель
(`OLLAMA_MODEL`), `temperature`, `-n`, версия шаблонов (коммит) и пресеты.
Судья всегда работает с `temperature=0.0`, генерация — с `temperature=0.7`,
версия рубрики пишется в JSON как `judge_version`.

## Критерии

| Критерий | Что оцениваем | 5 | 3 | 1 |
|---|---|---|---|---|
| Читаемость | промпт можно прочитать без расшифровки | ясная структура, короткие абзацы, нет дублей | есть длинные места, но смысл понятен | рваная структура, противоречия |
| Контекстность | хватает ли модели входных данных | URL, требования, формат и ограничения на месте | не хватает одной детали | модель должна догадываться |
| Чёткость целей | однозначно ли, что и в каком формате сделать | тип, формат, язык, разделы заданы явно | формат задан, детали размыты | непонятно, что генерировать |
| Покрытие сценариев | видны ли позитивные, негативные и граничные сценарии | есть все три группы и трассировка BR | есть позитив/негатив без границ | только happy path |

Дополнительно фиксируется, что дал пресет: какие проверки появились, не
появилось ли выдуманных требований и не размылся ли обязательный формат
(разделы, таблица, JSON).

## Результаты

Дата прогона: **2026-10-31**. Модель `qwen2.5:7b-instruct`, генерация
`temperature=0.7`, `-n 10`; судья v4, `temperature=0.0`. Стенд: Docker,
общий контейнер `ohw-ollama`, GPU RTX 2070 SUPER 8 ГБ. Сырые оценки —
`dz2/output/e2e-all/quality/*.json` и
`dz2/output/e2e-presets/*/quality/*.json`. Метки `run_id` и ссылки
`generated_artifact` добавлены миграцией уже сохранённых JSON: баллы,
комментарии и цитаты не пересчитывались.

Баллы ниже — **модельные** (`source=llm`), без правок. Отдельно, в разделе
«Проверка человеком», перечислены случаи, где комментарий судьи противоречит
тексту промпта: это ограничение 7B-судьи, а не оценка шаблона.

сортировки, решение принимается по критериям.

### Проверка человеком

Судья v4 перестал выдумывать цитаты, но по-прежнему иногда не читает
очевидные строки. Ниже — только те случаи, где утверждение проверено сборкой
промпта (`build_user_prompt`) или текстом шаблона. Баллы в JSON не
перезаписаны: сырой ответ судьи сохранён, поправки — это ревью человека.
При необходимости их можно внести через вкладку «Оценка» (`source=human`).

| Артефакт | Критерий | Балл судьи | Что проверено | Вывод |
|---|---|---|---|---|
| testcases | контекст | 3 | В промпте есть `Target site`, `All titles … must be in Russian`, JSON-формат и список полей | Балл занижен: основания «нет языка» нет. Корректнее 5. |
| testcases | цель | 3 | Поля `id, type, title, preconditions, steps, expected, requirement` перечислены явно | Балл занижен: комментарий «missing specific sections» неверен. Корректнее 5. |
| coveragematrix | контекст | 3 | `Target site: …` есть в шаблоне; таблица и ограничения заданы | Балл занижен: «missing the target URL» неверно. Корректнее 5. |
| coveragematrix | цель | 3 | Раздел `## Матрица покрытия требований` и пять колонок заданы | Балл занижен: секции и формат указаны. Корректнее 5. |
| checklist + accessibility | контекст | 3 | В промпте есть URL и строка пресета `Add an accessibility pass` | Балл занижен: оба элемента на месте. Корректнее 5. |
| qareport + negative-scenarios | покрытие | 1 | В промпте есть `Cover failure paths explicitly: invalid input, missing data, unavailable service, forbidden action` | Балл занижен: негативные сценарии прямо требуются. Корректнее 3: позитивные и граничные группы не заданы. |
| coveragematrix + boundary-values | покрытие | 3 | В промпте есть `Add boundary-value scenarios …` | Комментарий «не упомянуты границы» неверен, но балл 3 оставлен: позитивные и негативные группы матрица не задаёт. |
| qareport | покрытие | 1 | Шаблон требует список проверок по BR, а не группы сценариев | Балл оставлен: для отчёта это ожидаемо, но по рубрике «покрытие» это нижняя граница. |

Вывод по методике: четыре критерия хорошо различают шаблоны, но 7B-судья
неустойчив к длинным промптам и к критериям, которые не соответствуют типу
артефакта (матрица и QA-отчёт — не список сценариев). Для следующей версии
рубрики нужен предварительный структурный чек: судья сначала отвечает
«URL есть / языка нет / формат есть» с цитатой, и только потом ставит балл.
Пока это не сделано, таблицу выше следует читать вместе с ревью.

сгенерированы отдельным прогоном, поэтому матрица в `e2e-all` построена по
кейсам из `--all-types`, а оценка матрицы — по списку `e2e-testcases-brief.txt`.
Это разные входы одного и того же шаблона; баллы относятся к промпту с brief.
