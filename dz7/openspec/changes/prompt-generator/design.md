# Design: шаблоны промптов и контракт Dz7 → Dz2

## Кто чем владеет

```
dz7/templates/<type>.txt   — тексты промптов (источник истины)
        │  render (подстановка)
        ▼
dz7/generator.py           — CLI: requirements → готовый промпт
        │  --emit-templates / --all-types
        ▼
dz2/prompts/<type>.txt     — шаблоны, которые читает стенд
        │  render (та же схема подстановки)
        ▼
dz2 (Ollama)               — артефакт: testcases | checklist |
                             testplan | qareport | coveragematrix
```

`<type>` — канонические значения `ArtifactType` в Dz2:
`testcases`, `checklist`, `testplan`, `qareport`, `coveragematrix`.
Имя файла шаблона всегда `<type>.txt`.

## Плейсхолдеры

| Плейсхолдер | Значение |
|---|---|
| `{url}` | URL сайта; если неизвестен, строка `Target site: {url}` удаляется целиком |
| `{count}` | запрошенное число тест-кейсов |
| `{count_noun}` | `test case` / `test cases` |
| `{positive}` | число позитивных кейсов |
| `{negative}` | число негативных кейсов |
| `{requirement_rule}` | правило трассировки; пустая строка, если в требованиях нет `BR-N` |
| `{content}` | текст требований |
| `{extra}` | блок «Additional instructions» из пресетов; пустая строка без пресетов |

Подстановка — `re.sub` по `\{([a-z][a-z0-9_]*)\}`, а не `str.format`.
Причина: в шаблоне есть литеральный пример `{"cases": [...]}`, и
`str.format` упал бы на нём с `KeyError`. После подстановки оставшиеся
плейсхолдеры считаются ошибкой шаблона (опечатка в имени) — это лучше, чем
отправить модели `{content}` как текст. Левые фигурные скобки JSON
(`{"cases"`) под шаблон не подходят: после `{` идёт кавычка.

Служебные строки шаблона начинаются с `#` в первых строках файла; они
срезаются до подстановки, чтобы не попадать в промпт.

## Dz7 CLI

| Аргумент | Поведение |
|---|---|
| `--requirements TEXT` | требования строкой |
| `--requirements-file NAME` | имя файла в `--input-dir` (или прямой путь) |
| `--input-dir DIR` | входная директория Dz2, по умолчанию `../dz2/docs` |
| `--type` | один тип, по умолчанию из `config.toml` |
| `--all-types` | все пять типов |
| `--count` | по умолчанию `generation.default_count` |
| `--url` | иначе извлекается из требований |
| `--output FILE` | сохранить готовый промпт (один тип) |
| `--output-dir DIR` | каталог для `--all-types` / `--emit-templates` / `--emit-presets` |
| `--preset ID` | пресет из `presets/`; повторяемый |
| `--presets-dir DIR` | альтернативный каталог пресетов |
| `--list-presets` | напечатать `id: label [types]` и выйти |
| `--emit-templates` | скопировать шаблоны как есть (для `dz2 --prompt-dir`) |
| `--emit-presets` | скопировать пресеты как есть (для `dz2 --presets-dir`) |
| `--templates-dir DIR` | альтернативный набор шаблонов |
| `--config PATH` | TOML; по умолчанию `./config.toml` |

Без `--requirements`/`--requirements-file` (и без `--emit-*`/`--list-presets`)
команда завершается кодом 2. Неизвестный тип — код 2 со списком допустимых.

## Пресеты

```
presets/<id>.toml  ──load──►  Preset(id, label, text, types)
                                      │  --preset / UI
                                      ▼
                          select_extras(...)  ──►  {extra}
```

- `id` = имя файла; `types` по умолчанию — все пять, пустой список запрещён.
- Неприменимый к типу пресет — exit 2: иначе артефакт выглядел бы полным,
  но без нужных проверок.
- Текст нормализуется в один пункт списка на пресет.
- `--emit-presets` — единственный способ передать пресеты в Dz2 без ручного
  копирования; `dz2/tests/test_presets.py` сверяет каталоги по байтам.

## Рабочее место

Интерфейс живёт в Dz2 (`ai_testgen.ui`), потому что вызывает общее ядро
генерации; Dz7 отвечает за содержимое шаблонов и пресетов, которые интерфейс
показывает. Оценка по четырём критериям сохраняется в
`dz2/output/quality/<type>[-<preset>]-<run-id>.json` (метка прогона + ссылка
на артефакт) и переносится в `docs/prompt-quality.md`.

## Dz2: поиск шаблонов

Порядок (`resolve_prompt_dir`):

1. `--prompt-dir` (строго: нет каталога → ошибка 2);
2. `DZ2_PROMPT_DIR` (строго);
3. `./prompts`;
4. `<repo>/prompts` (editable-установка и тесты);
5. `<package>/prompts` (package data).

В Docker: `COPY prompts /app/prompts` + `ENV DZ2_PROMPT_DIR=/app/prompts`;
compose дополнительно монтирует `./prompts:/app/prompts:ro`. Нередактируемая
установка больше не зависит от расположения `__file__` относительно корня
репозитория.

## Ошибки

| Ситуация | Поведение |
|---|---|
| нет каталога шаблонов | `PromptError`, exit 2, до обращения к Ollama |
| нет `<type>.txt` | `PromptError` с именем ожидаемого файла, exit 2 |
| неизвестный плейсхолдер | `PromptError`, exit 2 |
| модель не выдала валидный артефакт | exit 4 (как раньше) |

Молчаливого отката на захардкоженный промпт нет: иначе пользователь не
узнает, что внешний шаблон не применился.

## Валидация новых типов

- `qareport` — markdown, обязательные разделы: `Введение`,
  `Тестовые сценарии`, `Дефекты`, `Рекомендации`.
- `coveragematrix` — markdown, обязательный раздел
  `Матрица покрытия требований` и Markdown-таблица (строка-разделитель
  `|---|`). Проверка таблицы добавлена в `validate_markdown(require_table=True)`.
- Оба типа — `wants_json=False`, retry-промпт — markdown-вариант.

## Тесты

Dz7 не тянет pydantic/httpx, поэтому тесты на стандартном `unittest`;
Dz2 остаётся на pytest. Обязательные регрессии:

- подстановка не ломает литеральный JSON-пример;
- `Target site` исчезает без URL;
- `requirement_rule` появляется только при `BR-N`;
- отсутствие шаблона → exit 2 и ни одного вызова LLM;
- `--prompt-dir` с sentinel-текстом влияет на отправленный промпт;
- все пять типов проходят registry/renderer/front-matter.
