# Proposal: генератор промптов, который реально питает Dz2

## Почему

ДЗ7 требует генератор, который принимает требования и выдаёт промпт, по
которому LLM строит тест-кейсы, чек-листы, тест-планы, QA-отчёты и матрицу
покрытия. Сейчас заготовка `dz7/generator.py`:

- дублирует `dz2/prompt.py` и `templates/*.txt`, при этом шаблоны не читаются
  (`load_template` не вызывается ни разу);
- содержит битую инструкцию `{"cases": [...]}"` (лишняя кавычка), из-за
  которой модель получает невалидный пример JSON;
- пишет несовместимый с Dz2 набор файлов `llm_prompt_<type>.txt`, а Dz2
  читает один `llm_prompt.txt`;
- не читает требования из файла и не использует `config.toml`;
- не имеет тестов, инструкции запуска и результатов оценки качества.

В Dz2 правка «читаем внешний промпт» тоже нерабочая: файл загружается, но
шаблон не применяется, `ArtifactHandler` удалён (модуль не импортируется),
QA-отчёт и матрица покрытия отсутствуют как типы артефактов. Значит, 2 из 5
промптов Dz7 невозможно прогнать через стенд, а остальные 3 игнорируют
внешний шаблон.

## Что делаем

- **Dz7 — единственный источник текстов промптов.** Все пять промптов живут
  в `dz7/templates/<type>.txt` с плейсхолдерами `{url}`, `{count}`,
  `{positive}`, `{negative}`, `{requirement_rule}`, `{content}`.
  `generator.py` читает шаблон, срезает служебные `#`-комментарии,
  подставляет значения и печатает/сохраняет готовый промпт.
- **CLI Dz7**: `--requirements` или `--requirements-file`, `--input-dir`
  (по умолчанию `../dz2/docs` — главный проект), `--url`, `--type`,
  `--count`, `--all-types`, `--output`, `--output-dir`, `--emit-templates`,
  `--emit-presets`, `--preset`, `--presets-dir`, `--list-presets`,
  `--templates-dir`, `--config`. Пути по умолчанию относительные,
  `config.toml` читается и применяется.
- **Dz2 читает по одному шаблону на тип артефакта** из `--prompt-dir`
  (по умолчанию `./prompts`, `DZ2_PROMPT_DIR`, затем каталог репозитория).
  Подстановка — regex по известным именам, поэтому литеральный JSON-пример
  `{"cases": [...]}` в шаблоне остаётся нетронутым. Отсутствие каталога или
  файла — явная ошибка с кодом 2, без молчаливого отката на хардкод.
- **Dz2 получает пятый тип** `coveragematrix` и `qareport`: front-matter,
  валидатор (таблица для матрицы), renderer, алиасы типов.
- **Dz2: промпты поставляются с проектом** (`dz2/prompts/*.txt`), копируются
  в Docker-образ и монтируются в compose, поэтому нередактируемая установка
  не теряет шаблоны.
- **Тесты**: Dz7 — `unittest` без внешних зависимостей; Dz2 — pytest на
  подстановку, отсутствие шаблона, все 5 типов, алиасы и сквозной
  `--prompt-dir`.
- **Пресеты**: тематические дополнения (`boundary-values`, `negative-scenarios`,
  `accessibility`, `input-validation`, `regression`, `localization`) живут в
  `dz7/presets/*.toml` и подставляются в `{extra}`; `--emit-presets`
  копирует их в Dz2 для CLI, UI и Docker.
- **Рабочее место**: Streamlit-интерфейс в Dz2 показывает собранный промпт,
  позволяет его править, генерировать артефакт, дорабатывать чатом и
  сохранять оценку по rubric в JSON.
- **Оценка качества промптов**: rubric по четырём критериям (читаемость,
  контекстность, чёткость целей, покрытие сценариев) ставит LLM-судья
  (отдельный вызов на критерий, обязательные проверяемые цитаты), человек может
  переопределить балл; прогон через Docker + Ollama и заполненный отчёт в
  `dz7/docs/prompt-quality.md`.

## Спека

Дельта `prompt-generator` (Dz7) и `testcase-generator` (Dz2): контракт
шаблонов и подстановки, поведение при отсутствии шаблона, пять типов
артефактов, валидация матрицы покрытия таблицей, поставка шаблонов в образ.

## Проверка

- `cd dz7 && python3 -m unittest discover -s tests -v` — шаблоны читаются,
  плейсхолдеры подставлены, CLI пишет файлы.
- `uv run pytest -m "not integration"` в `dz2` — регрессия + новые тесты.
- `uv run ruff check . && uv run mypy src tests` в `dz2`.
- Docker: `dz7` генерирует 5 промптов → `dz2 --prompt-dir` прогоняет их через
  Ollama → артефакты в `dz2/output`, результаты заносятся в отчёт.

## Вне рамок

- Не меняем исторические ДЗ1–ДЗ6 и не переносим общий код в `kit`.
- Не заменяем человеческое ревью: судья ставит баллы по тексту промпта, но
  человек может перепроверить и переопределить оценку (`source=human`).
