## 🔴 Критические замечания (Critical)

### 1. Шаблон промпта загружается, но игнорируется (Dz2, `handlers.py`)
**Роль:** Backend Engineer

Функция `_fill_prompt_template(template, content, url, count)` **не использует содержимое `template`**. Она игнорирует файл `llm_prompt.txt` и генерирует промпт хардкодом, дублируя логику из `prompt.py`. Файл загружается, но его контент выбрасывается.

**Риск:** Изменения в `llm_prompt.txt` не влияют на Generated Prompt. Смысл выноса в отдельный файл теряется.

**Рекомендация:** Реализовать настоящую подстановку плейсхолдеров (`{url}`, `{count}`, `{positive}`, `{negative}`, `{content}`) в шаблоне, а не генерировать строку с нуля.

---

### 2. Placeholder-подстановка не работает (Dz2, `llm_prompt.txt`)
**Роль:** Backend Engineer

Файл `llm_prompt.txt` содержит плейсхолдеры `{positive}`, `{negative}`, но `_fill_prompt_template` считает их и подставляет значениями в строку, не используя шаблон. Если 누군가 отредактирует `llm_prompt.txt` (например, изменит порядок или формулировку), это не отразится на результате.

**Рекомендация:** Сделать `_fill_prompt_template` действительно шаблонизатором:
```python
return template.format(
    url=url or "",
    count=count,
    positive=positive,
    negative=negative,
    content=content,
)
```
И добавить обработку отсутствующих ключей (safe formatting).

---

### 3. Импорты нарушают порядок PEP8 (Dz2, `handlers.py`)
**Роль:** Backend Engineer

```python
from collections.abc import Callable
from dataclasses import dataclass
from pathlib import Path          # ← должен быть раньше (stdlib)

from ai_testgen.input_doc import RequirementDoc
...
```

`from pathlib import Path` должен быть в группе стандартной библиотеки выше, а не после импортов проекта.

## 🟡 Major замечания

### 4. Локальный импорт `build_user_prompt` внутри функции (Dz2, `handlers.py`)
**Роль:** Tech Lead

```python
def _testcases_user(doc, count):
    ...
    from ai_testgen.prompt import build_user_prompt
    return build_user_prompt(doc.content, doc.url, count)
```

Локальный импорт внутри тела функции — code smell. Он используется как fallback, но лучше импортировать на уровне модуля и использовать условно.

**Рекомендация:** Вернуть `build_user_prompt` в верхний импорт модуля.

---

### 5. Dz7 не использует `dz2_root` из config.toml
**Роль:** DevOps Engineer

В `config.toml` есть секция `[paths] dz2_root = "../ohw/dz2"`, но в `generator.py` путь по умолчанию хардкоден:
```python
parser.add_argument("--output", default="D:\\Otus\\ohw\\dz2\\llm_prompt.txt", ...)
```

Конфигурационный файл игнорируется полностью.

**Рекомендация:** Читать `config.toml` в `generator.py` и использовать `dz2_root` для построения пути по умолчанию.

---

### 6. Dz7 ссылается на несуществующую директорию `tests/`
**Роль:** QA Lead

В `README.md` описана структура с `tests/test_prompts.py`, но директория не создана. Нет тестов ни для генератора промптов, ни для интеграции с Dz2.

**Рекомендация:** Создать `tests/` с unit-тестами для `fill_*_prompt` и интеграционным тестом, проверяющим, что Dz2 принимает сгенерированный промпт.

---

### 7. Нет обработки отсутствия файла шаблона в Dz2
**Роль:** QA Lead

Если `llm_prompt.txt` удалён, `_load_llm_prompt_template()` возвращает `""`, и срабатывает fallback на `build_user_prompt`. Это правильно, но неинтуитивно — пользователь может подумать, что файл подключен, а он молча игнорируется.

**Рекомендация:** Добавить warning в консоль, когда файл не найден и используется fallback.

---

## 🟢 Minor / NIT

### 8. Смешанные языки в комментариях (Dz2, `llm_prompt.txt`)
**Роль:** Tech Lead

В файле шаблона комментарии на русском, сам промпт — на английском. В `prompt.py` Dz2 комментарии и docstring на английском (по конвенции проекта: «Код и комментарии — на английском; документация — на русском»).

**Рекомендация:** Привести комментарии в `llm_prompt.txt` к английскому, или явно задокументировать исключение.

---

### 9. Нет `__init__.py` и пакетной структуры в Dz7
**Роль:** Backend Engineer

`generator.py` — отдельный скрипт без пакетной обёртки. Для маленького проекта допустимо, но если Dz7 будет расти, стоит добавить `pyproject.toml` и структуру пакета.

**Рекомендация:** Добавить минимальный `pyproject.toml` и `__init__.py`, если проект планируется развивать.

---

### 10. `coveragematrix.txt` — хорошо, но нет интеграции в Dz2
**Роль:** QA Lead

В Dz7 добавлен шаблон `coveragematrix.txt`, но в Dz2 нет обработчика `ArtifactType.COVERAGEMATRIX` и нет валидатора для матрицы покрытия.

**Рекомендация:** Либо добавить тип в Dz2, либо убрать из Dz7, чтобы не было ложного ожидания поддержки.
