# Локальная модель против субагента: сравнение на одном промпте

**Дата:** 27.10.2026
**Проект:** `dz6` — оптимизация автотестов через LLM
**Вход:** `input/example.py` — 5 тестов pytest + requests, намеренно с дефектами
(три почти одинаковых теста создания пользователя, захардкоженный URL,
нет таймаутов и teardown).
**Промпт:** `prompts/system_optimization.md` + `prompts/optimization.md` с
подставленным кодом (2084 символа) — ровно то, что уходит в Ollama.
**Артефакты:** `output/2026-10-27_14-*/example_optimized_tests.py` (локальная
модель) и `output/2026-10-27_subagent-baseline/baseline_1..3.py` (субагент).

## 1. Вопрос

Три прогона локальной модели дали результат, который нельзя было использовать.
Нужно было разделить две гипотезы:

- **H1:** виноват промпт — он просит слишком много за один раз;
- **H2:** виновата модель — она не удерживает семь ограничений одновременно.

Если тот же текст получает сильная модель и справляется, H1 не подтверждается.

## 2. Метод

1. Промпт отрендерен тем же кодом, что и в рабочем запуске
   (`render_prompt` из `src/test_optimizer.py`), без ручных правок.
2. Локальная модель: `qwen2.5:7b-instruct` (7.6B, Q4_K_M, digest
   `845dbda0ea48`), Ollama на CPU, ~7.4 токена/с, 4.5–8.5 минуты на прогон,
   3 прогона.
3. Субагент: агент общего назначения, 3 прогона. Запрет на чтение файлов
   проекта и на инструменты, `requirements_with_priorities.md` не
   предоставлялся.
4. Критерий успеха зафиксирован **до** просмотра ответов:
   - статическая валидность (`ast.parse`, `pytest --collect-only`);
   - дубли исходного файла устранены параметризацией;
   - нет `assert True`, `time.sleep`, проглоченных исключений;
   - URL и таймаут не захардкожены;
   - teardown касается только данных, созданных тестом;
   - нет выдуманных полей и сценариев, противоречащих требованиям.
5. Оценка ручная, по тексту артефакта: критерий говорит о смысле тестов, а
   числа инструмента об этом ничего не утверждают.

## 3. Прогоны локальной модели

| Прогон | Собрано тестов | Что получилось |
|---|---|---|
| 1 | 5 | Файл почти не изменён: добавлены docstrings и `TIMEOUT`, teardown удаляет **всех** пользователей |
| 2 | 5 | Фикстуры добавлены, дубли остались, таймаута нет, teardown нет, тело ошибки выдумано |
| 3 | 6 | `parametrize` на все пять кейсов, негативные ожидают `201`, остался дубль |

Во всех трёх URL захардкожен (в третьем — `BASE_URL = "http://localhost:8000"`,
во втором — дефолт `os.getenv`). Ни в одном нет teardown, который удаляет только
созданные тестом данные.

## 4. Прогоны субагента

| Прогон | Собрано тестов | Что получилось |
|---|---|---|
| 1 | 5 | Параметризация, фикстуры, env, teardown по созданным id |
| 2 | 5 | То же; фабрика payload'ов и уникальные email |
| 3 | 7 | То же + кейс «нет email» и тест на разные id (сверх задания) |

Во всех трёх URL и таймаут берутся из окружения с дефолтом, клиент один на
сессию, teardown удаляет ровно те id, которые создал тест.

## 5. Результат по критериям

| Критерий | Локальная 7B | Субагент |
|---|---|---|
| 1. `ast.parse` + `--collect-only` | 3/3 | 3/3 |
| 2. Дубли устранены параметризацией | 0/3 | 3/3 |
| 3. Нет `assert True` | 3/3 | 3/3 |
| 4. URL и таймаут не захардкожены | 0/3 | 3/3 |
| 5. Teardown только своих данных | 0/3 | 3/3 |
| 6. Нет выдуманных полей ответа | 1/3 | 3/3 |
| **Пригоден без переписывания** | **0/3** | **3/3** |

Вердикт по заранее объявленному правилу: 3/3 — «справляется», 1–2/3 —
«нестабильно», 0/3 — «не справляется».

## 6. Дополнительный прогон после исправления инструмента

Отдельно, уже после того как анализатор был переписан, сделан ещё один прогон
на том же входе и промпте: `output/2026-10-27_15-41-01/`. Он добавлен как
наблюдение, а не как четвёртая точка в таблице 0/3: критерий и размер выборки
зафиксированы до прогонов, и задним числом менять знаменатель нельзя.

Результат: 6 собранных тестов, статическая валидация пройдена, но модель
объединила валидные и невалидные данные в один цикл и ждёт `201` от невалидных,
добавила «тест на таймаут» без таймаута, оставила два захардкоженных URL и не
сделала teardown. Пригоден без переписывания: **0/1**.

Этот прогон показывает две вещи: статическая проверка ловит синтаксис и явные
заглушки, но не подмену смысла; а результат модели не изменился после того, как
анализатор был исправлен. Значит, «0 из 3» — свойство модели на этом
входе, а не следствие дефекта анализатора.

## 7. Выводы

1. **Промпт не является узким местом.** Тот же текст, те же семь требований —
   субагент удержал их три раза из трёх. Гипотеза H1 не подтвердилась.
2. **Статическая валидность ничего не различает.** Все шесть файлов проходят
   `ast` и `--collect-only`, включая тот, где негативные тесты ожидают `201`.
   Зелёная сборка — необходимое условие, а не доказательство качества.
3. **Разброс у 7B — самостоятельный результат.** Три прогона дали три разные
   стратегии, а не три версии одного решения. Это нестабильность на одном входе,
   и она не лечится правкой промпта.
4. **Оценка должна быть ручной и зафиксированной заранее.** Все различия, которые здесь
   посчитаны, видны только при чтении кода: ожидаемый статус в негативном
   тесте, наличие `timeout=`, набор удаляемых id.

## 8. Ограничения

- Вход один, промпт один, из малых моделей проверена одна. Утверждение
  «малые модели не годятся вообще» этими данными не подтверждается.
- Субагент тоже не эталон: третий прогон добавил сценарии, которых не было ни
  во входе, ни в требованиях.
- Контрольные ответы субагента получены агентом, а не через Ollama с тем же
  HTTP-вызовом. Это верхняя граница «что возможно с таким промптом», а не
  сравнение на равных по способу запуска.
- Повторяется метод, а не конкретные файлы: генерация стохастическая, новый
  прогон даст другой текст с теми же проверками.
- `n = 3` на модель достаточно, чтобы отвергнуть H1 на этом входе, и мало,
  чтобы оценить модель в целом.

## 9. Воспроизведение

Промпт рендерится функцией `render_prompt()` из `src/test_optimizer.py`
(шаблоны — `prompts/*.md`, подстановка `${source_code}`):

```python
import pathlib, sys
sys.path.insert(0, "/data")
from src.test_optimizer import render_prompt
src = pathlib.Path("/in/example.py").read_text(encoding="utf-8")
print(render_prompt("optimization", source_code=src))
```

Прогон локальной модели и проверка ответа:

```bash
docker compose run --rm app
pytest output/<каталог>/example_optimized_tests.py --collect-only -q
```

`--collect-only` ловит синтаксис, ошибки импорта и декораторов, но не смысл.
Остальные пять критериев проверяются чтением артефакта: ожидаемые статусы,
`timeout=` в HTTP-вызовах, источник URL (env или литерал), набор id в teardown,
поля ответа против `requirements_with_priorities.md`.
