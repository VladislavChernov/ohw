# Тестовые запросы (промпты) для оптимизации автотестов через LLM

**Проект:** D:\Otus\ohw\dz6  
**Используются в:** `src/test_optimizer.py` (функции `build_review_prompt`, `build_optimization_prompt`, `build_prioritization_prompt`)  
**Цель:** передать исходный код автотестов в Ollama (LLM) и получить ревью, оптимизированный код, приоритизацию.

> Актуальные тексты запросов лежат в `prompts/*.md` — это источник, который
> читает скрипт. Ниже те же запросы разобраны с пояснениями; при расхождении
> верен файл в `prompts/`.

---

## Запрос 1 — Код-ревью (что хорошо / что плохо)

**Назначение:** получить отчёт по качеству исходных автотестов.

**Системное сообщение:**
```
Ты — опытный QA Automation Engineer. Отвечай по делу, на русском языке, в формате Markdown.
```

**Пользовательский промпт:**
```
Ты — опытный QA Automation Engineer и архитектор автотестов.
Проведи код-ревью приведённых ниже автотестов на Python (pytest + requests).

Исходный код автотестов:
```python
{source_code}
```

Оцени и опиши:
1. ЧТО СДЕЛАНО ХОРОШО (положительные моменты).
2. ЧТО СДЕЛАНО ПЛОХО (проблемы, антипаттерны, дубли, риски).
   В частности укажи на:
   - дублирующие тесты и шаги,
   - похожие (near-duplicate) автотесты,
   - отсутствие фикстур и изоляции тестов,
   - жёстко заданные данные и URL,
   - отсутствие параметризации,
   - слабые assert'ы,
   - отсутствие обработки ошибок / таймаутов.
3. ОБЩАЯ ОЦЕНКА качества и рекомендации по приоритетам исправления.

Формат ответа: Markdown. Будь конструктивным и конкретным, ссылайся на номера строк и фрагменты кода.
```

## Запрос 2 — Оптимизация и генерация кода

**Назначение:** получить оптимизированный вариант автотестов (готовый код).

**Системное сообщение:**
```
Ты — опытный QA Automation Engineer. Пиши чистый, поддерживаемый код на Python + pytest. Отвечай только кодом в блоке ```python.
```

**Пользовательский промпт:**
```
Ты — опытный QA Automation Engineer. Оптимизируй приведённые ниже автотесты на Python (pytest + requests).

Исходный код:
```python
{source_code}
```

Требования к оптимизации:
- Устрани дублирующие шаги и дублирующие тесты (используй @pytest.mark.parametrize).
- Добавь фикстуры: API-клиент, создание и удаление тестового пользователя (изоляция тестов).
- Вынеси BASE_URL и тестовые данные в конфигурацию / переменные окружения.
- Усиль assert'ы (проверяй поля ответа, структуру JSON, заголовки).
- Добавь docstrings и понятные имена тестов.
- Обработай возможные ошибки сети и некорректные ответы (timeout, connection error).
- Сохрани coverage всех исходных сценариев.

Верни ТОЛЬКО готовый оптимизированный код на Python в одном блоке ```python ... ```.
Без лишних вводных слов вне блока кода.
```

## Запрос 3 — Приоритизация по требованиям

**Назначение:** сопоставить тесты с требованиями, расставить приоритеты, найти пробелы в покрытии.

**Системное сообщение:**
```
Ты — lead QA. Отвечай на русском языке, в формате Markdown-таблицы.
```

**Пользовательский промпт:**
```
Ты — lead QA. Расставь приоритеты автотестам на основе требований.

Исходные автотесты:
```python
{source_code}
```

Требования с приоритетами:
```
{requirements_text}
```

Для каждого теста укажи:
- к какому требованию (ID) он относится,
- приоритет требования (P0..P3),
- стоит ли включать в регрессионный набор,
- есть ли пробелы в покрытии требований.

Ответ в формате Markdown-таблицы.
```

## Дополнительные тестовые запросы (ручные / для доработки)

### Запрос 4 — Поиск дублирующих шагов
```
Найди в следующем коде автотестов дублирующие шаги (последовательности действий, повторяющиеся в нескольких тестах).
Предложи, какие шаги вынести в фикстуры или хелперы.
Код:
```python
{source_code}
```
Ответ: список дублей + предложенная рефакторизация.
```

### Запрос 5 — Поиск похожих (near-duplicate) тестов
```
Найди пары похожих автотестов (различаются только данными). Предложи объединить их в параметризованный тест.
Код:
```python
{source_code}
```
Ответ: таблица "Тест А | Тест Б | сходство % | рекомендация".
```

### Запрос 6 — Оценка читаемости (1–10)
```
Оцени читаемость каждого автотеста по шкале 1–10. Учти: длину функции, наличие docstrings, осмысленные имена, отсутствие хардкода.
Код:
```python
{source_code}
```
Ответ: таблица "Тест | оценка | комментарий".
```

### Запрос 7 — Покрытие требований
```
Сопоставь автотесты с требованиями (ID). Рассчитай процент покрытия требований и укажи требования без покрытия.
Требования:
```
{requirements_text}
```
Код:
```python
{source_code}
```
Ответ: таблица RTM + процент покрытия.
```

### Запрос 8 — Критерии "плохих" тестов
```
Проведи аудит следующего кода автотестов по критериям "плохих" тестов (дубли, отсутствие изоляции, хардкод, слабые assert'ы, нет обработки ошибок, флейка, нет негативных сценариев и т.д.).
Для каждого критерия укажи: присутствует ли он, пример из кода, рекомендация по исправлению.
Код:
```python
{source_code}
```
```

## Как использовать в скрипте

В `src/test_optimizer.py` запросы 1–3 реализованы как функции:
- `build_review_prompt(source_code)`
- `build_optimization_prompt(source_code)`
- `build_prioritization_prompt(source_code, requirements_text)`

Результаты записываются в каталог прогона `output/<YYYY-MM-DD_HH-MM-SS>/`:
`<stem>_code_review_report.md`, `<stem>_optimized_tests.py`,
`<stem>_optimization_report.md`.

Запуск:
```bash
python src/test_optimizer.py --no-interactive
```

Если Ollama недоступен — сработает демо-режим (fallback) с заранее подготовленными результатами.
