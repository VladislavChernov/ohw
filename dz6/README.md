# DZ6 — оптимизация автотестов с помощью LLM (Ollama)

Скрипт читает код автотестов на Python, выполняет статический анализ, отправляет
код в локальную LLM через Ollama и складывает результат прогона в отдельный
каталог: оптимизированный вариант тестов, отчёт ревью и сводный отчёт
оптимизации. Если Ollama недоступен, скрипт работает в демо-режиме и отдаёт
заранее подготовленный результат.

## Структура проекта

```
dz6/
├── input/example.py                  # Исходные автотесты (входные данные)
├── TZ.md                             # Техническое задание
├── RESEARCH_REPORT.md                # Исследование: практики, площадки, оптимизация
├── MODEL_COMPARISON_REPORT.md        # Сравнение 7B и сильной модели на одном промпте
├── optimization_requests.md          # Тестовые запросы (промпты) для оптимизации
├── requirements_with_priorities.md   # Требования к API с приоритетами (P0–P3)
├── README.md                         # Описание проекта
├── infra.yaml                        # Какие компоненты нужны из общего ../infra
├── compose.yaml                      # Приложение (Ollama берётся из ../infra)
├── Dockerfile                        # Образ приложения
├── run.sh / run.ps1                  # Запуск одной командой (Linux/WSL, Windows)
├── requirements/requirements.txt     # Python-зависимости
├── src/test_optimizer.py             # Скрипт оптимизации (Python 3 + Ollama)
├── prompts/                          # Тексты запросов к LLM (шаблоны с ${...})
│   ├── review.md
│   ├── optimization.md
│   ├── prioritization.md
│   └── system_*.md
└── output/                           # Результаты прогонов
    ├── <YYYY-MM-DD_HH-MM-SS>/        # Каталог одного прогона
    │   ├── example_optimized_tests.py
    │   ├── example_code_review_report.md
    │   └── example_optimization_report.md
    └── 2026-10-27_subagent-baseline/ # Контрольные ответы сильной модели
        └── baseline_1..3.py
```

## Что делает скрипт

1. Находит файлы с автотестами в `INPUT_DIR` (по умолчанию `input/`).
2. Считает статические метрики: тесты, дубли и near-duplicate, фикстуры,
   docstrings, захардкоженные URL, длина функций, оценка читаемости.
3. Отправляет код в Ollama: ревью, оптимизация, приоритизация по
   `requirements_with_priorities.md`.
4. Создаёт каталог прогона `output/<дата>_<время>/` (время UTC, как в
   контейнере) и сохраняет туда три файла с префиксом имени входного файла.

Тексты запросов к модели не зашиты в код: они лежат в `prompts/*.md`, а
`${source_code}` и `${requirements_text}` подставляются при отправке. Правка
промпта — это правка файла, а не строки в Python.

Каждый запуск пишет в свой каталог, поэтому прогоны не перезаписывают друг
друга и их можно сравнивать.

## Запуск

Ollama — общий компонент каталога `D:\Otus\ohw\infra`; проект объявляет его в
`infra.yaml`. Одна команда (Windows):

```powershell
cd D:\Otus\ohw\dz6
.\run.ps1
```

Linux / macOS / WSL:

```bash
cd /mnt/d/Otus/ohw/dz6
./run.sh
```

Скрипт запуска поднимает общий `ohw-ollama` (`../infra/up.sh`), собирает образ
приложения и запускает оптимизатор. Флаги: `--gpu` / `-Gpu` (NVIDIA),
`--rebuild` / `-Rebuild`, `-i FOLDER` / `-InputFolder FOLDER` (другой каталог
с тестами).

Запуск без Docker:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements/requirements.txt
python src/test_optimizer.py --no-interactive
```

Для этого варианта Ollama должна быть доступна на `http://localhost:11434`.

## Параметры окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес Ollama |
| `OLLAMA_MODEL` | `codellama:7b-instruct` (`qwen2.5:7b-instruct` в контейнере) | Модель |
| `OLLAMA_TIMEOUT` | `120` с | Таймаут запроса к LLM |
| `INPUT_DIR` | `input/` | Каталог с автотестами |
| `OUTPUT_DIR` | `output/` | Корень для каталогов прогонов |
| `PROMPTS_DIR` | `prompts/` | Шаблоны запросов к LLM |
| `REQUIREMENTS_PATH` | `requirements_with_priorities.md` | Требования для приоритизации |

## Проверка результатов

Стенда с тестируемым API в проекте нет, поэтому сгенерированные тесты
проверяются статически:

```bash
pytest output/<дата>_<время>/example_optimized_tests.py --collect-only -q
```

`--collect-only` не обращается к API: он проверяет, что файл импортируется и
декораторы вычисляются.

## Известные ограничения

- Для контейнерного запуска нужен Docker Desktop / Docker Engine с compose.
- Без Ollama скрипт работает в демо-режиме (fallback); такие результаты —
  демонстрационные.
- Сгенерированный код требует ручной проверки и утверждения перед влитием.
- Модель 7B на CPU отвечает несколько минут; таймаут в контейнере — 600 секунд.
- Встроенный статический анализ ненадёжен: регулярка склеивает несколько тестов
  в один блок, поэтому значения дублей и читаемости в отчёте — `unknown`,
  а не измеренный ноль.
- Раздел «Проделанные оптимизации» в `*_optimization_report.md` — фиксированный
  текст шаблона, а не результат прогона: он одинаков во всех прогонах и может не
  совпадать с кодом. Проверяйте каждое утверждение по артефакту.
