# Требования к автотестам с приоритетами (подготовлено заранее)

| ID | Требование | Описание | Приоритет | Источник |
|:---|:---|:---|:---|:---|
| R01 | Создание пользователя (валидные данные) | POST /users создаёт пользователя с корректным именем и email, возвращает 201 и тело с полями id/name/email | Критический (P0) | Спецификация API |
| R02 | Создание пользователя, дубликат email | Повторная регистрация с тем же email возвращает 400 | Высокий (P1) | Спецификация API |
| R03 | Создание пользователя, невалидный email | Email без @/домена возвращает 400 | Высокий (P1) | Спецификация API |
| R04 | Создание пользователя, отсутствует имя | Отсутствующее/пустое имя возвращает 400 | Средний (P2) | Спецификация API |
| R05 | Получение списка пользователей | GET /users возвращает список и общее количество | Средний (P2) | Спецификация API |
| R06 | Получение пользователя по ID | GET /users/{id} возвращает пользователя или 404 | Средний (P2) | Спецификация API |
| R07 | Удаление пользователя | DELETE /users/{id} возвращает 204, после чего GET возвращает 404 | Низкий (P3) | Спецификация API |
| R08 | Изоляция тестов | Тесты не зависят от данных, оставленных другими тестами | Критический (P0) | Политика QA |
| R09 | Параметризация повторяющихся сценариев | Одинаковые шаги с разными данными объединяются в параметризованный тест | Высокий (P1) | Политика QA |

**Легенда приоритетов:**
- **P0 — Критический:** должен быть покрыт автотестом без исключений; падение = блокирующий дефект релиза.
- **P1 — Высокий:** обязательно к покрытию, но небольшая задержка допустима.
- **P2 — Средний:** желательно покрыть, при нехватке ресурсов можно отложить.
- **P3 — Низкий:** опционально, покрытие по оставшемуся времени.
