- Источник: `/data/input/example.py`
- Модель LLM: `qwen2.5:7b-instruct` (Ollama, доступен)

- Всего тестов: 5
- Дублирующих тестов: 0
- Близких дублей (near-duplicate): 0
- Фикстур: 0
- Тестов с docstring: 0
- Жёстко заданных URL: 1
- Оценка читаемости (1–10): 0.0
- Покрытие требований: частичное (только создание пользователя)


## Найденные проблемы (ревью)
- [MEDIUM] **Жёстко заданный URL**: URL жёстко задан в коде (http://localhost:8000). Рекомендуется вынести в переменную окружения / конфиг / фикстуру. — Использовать os.getenv('BASE_URL', 'http://localhost:8000')
- [HIGH] **Отсутствуют фикстуры**: В коде нет фикстур pytest (setup/teardown, клиент API, подготовка данных). Тесты не изолированы и могут оставлять мусор в системе. — Добавить фикстуру для клиента API и фикстуру для подготовки/очистки тестовых данных.
- [MEDIUM] **Читаемость**: Средняя длина тестовой функции 31 строк (рекомендуется ≤ 10). — Вынести повторяющийся код в вспомогательные функции и фикстуры.

## Приоритизация по требованиям
```markdown
| Тест функция              | Требование ID | Приоритет требования | Включить в регрессию | Пробелы в покрытии |
|:-------------------------|:--------------|:--------------------|:--------------------|:------------------|
| test_create_user         | R01           | P0                  | Да                  | Нет               |
| test_create_user_other_name | R01          | P0                  | Да                  | Нет               |
| test_create_user_new_new_name | R01 | P0                  | Да                  | Нет               |
| test_create_user_invalid_email | R03 | P1                  | Да                  | Нет               |
| test_create_user_missing_name | R04 | P2                  | Да                  | Нет               |
| test_create_user_other_name | R02           | P1                  | Нет                 | Нет               |
| test_create_user_invalid_email | R03 | P1                  | Нет                 | Нет               |
| test_create_user_missing_name | R04 | P2                  | Нет                 | Нет               |
```

Примечание: В данном случае тесты `test_create_user_other_name`, `test_create_user_invalid_email` и `test_create_user_missing_name` повторяются и могут быть объединены в один параметризованный тест, что соответствует требованию R09 с приоритетом P1. Однако, основываясь на информации, предоставленной в таблице требований, эти тесты имеют разные ID, и мы их оценили отдельно.

## Проделанные оптимизации
1. Устранены дублирующие тесты через `@pytest.mark.parametrize`.
2. Добавлены фикстуры для клиента API и подготовки/очистки тестовых данных с тедауном.
3. Базовый URL и таймаут вынесены в переменные окружения.
4. Добавлены ретраи и таймауты к HTTP-клиенту.
5. Усилены assert'ы (проверка `id`, `name`, структуры тела).
6. Добавлены docstrings и осмысленные имена тестов.
7. Добавлены недостающие сценарии (дубликат, 404).

## Критерии "плохих" автотестов (список)
- Дублируют другие тесты без добавления новой ценности.
- Нет изоляции (оставляют данные в системе, зависят от порядка выполнения).
- Жёстко заданные данные и URL в теле теста.
- Нет assert'ов или слабые assert'ы (проверяют только статус).
- Нет обработки ошибок сети и таймаутов.
- Непонятные, неконсистентные имена тестов.
- Нет документации (docstrings / комментарии к сложным моментам).
- Смешивают несколько сценариев в одном тесте.
- Зависят от внутренней реализации (хрупкие).
- Не покрывают требования с высоким приоритетом.
