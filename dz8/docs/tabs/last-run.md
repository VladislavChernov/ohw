# Вкладка «Последний прогон»

[← User Guide](../user-guide.md) · [Глоссарий](../glossary.md)

## Что это и зачем

Быстрый обзор **самого свежего** отчёта без выбора из списка. Вкладка нужна,
чтобы сразу после запуска проверки увидеть вердикт, причины и ключевые
метрики, не переключаясь в «Отчёты» и не открывая файлы вручную.

Это витрина последнего результата, а не отдельная проверка: новых запросов к
модели она не делает.

## Как запустить в UI

Новых запросов к модели вкладка не делает — она показывает самый свежий
готовый отчёт.

1. Запустите любую проверку на другой вкладке.
2. Откройте страницу **«Проверка модели»** → вкладку **«Последний прогон»**.
3. Смотрите карточки вердикта, блок **«Причины»**, сводку и таблицу прогонов.
4. Скачайте отчёт кнопками **«Скачать report.json»** / **«Скачать report.md»**
   внизу вкладки.

## Что показывает

Вкладка берёт один самый новый `report.json` из `output/` и показывает:

| Блок | Содержимое |
|---|---|
| Заголовок | название проверки и `run_id` |
| Карточки | вердикт, модель, число прогонов, тип |
| Время | «Начат» и «Завершён» |
| Причины | `verdict.reasons`, если есть |
| Сводка | `summary` в виде раскрывающегося JSON |
| Прогоны | таблица `run`, `cell`, `validator`, `attempts`, `cases`, `br_coverage`, `latency_ms` |
| Сравнение | `comparison` для деградации |
| Скачивание | `report.json` и `report.md` |

Для деградации дополнительно видно сравнение baseline и candidate.

## Как это работает

1. `list_reports(output_dir, limit=1)` сортирует каталоги по `run_id` по
   убыванию и берёт первый.
2. Загружается `report.json`.
3. Отображаются карточки и таблицы.
4. Кнопки скачивания читают файлы из каталога отчёта.

Если отчётов нет, показывается подсказка запустить любую проверку.
Если `report.json` повреждён или имеет неподдерживаемую схему, показывается
ошибка.

## Как читать

- Сначала смотрите **вердикт** и **причины** — они объясняют, почему
  проверка не прошла.
- Затем `summary` — там все метрики; расшифровка в
  [глоссарии](../glossary.md).
- Для серии — таблица прогонов: видно, в каких именно прогонах валидатор
  упал и каково покрытие `BR`.
- Для деградации — блок `comparison`: `diff`, `overlap`, `effect_size_h`.

## Отличие от «Отчётов»

| «Последний прогон» | «Отчёты» |
|---|---|
| только самый новый отчёт | любой из сохранённых |
| быстрый обзор | полный `report.md` |
| без выбора | выпадающий список |

## CLI-аналог

```bash
/app/.venv/bin/python -m llm_degradation report --list --json
```

Показать конкретный отчёт:

```bash
... report --run-id <run_id> --format md
... report --report output/<run_id>/report.json --format json
```

## Ограничения

- Показывает только один отчёт — самый новый по строковому `run_id`.
- Не хранит историю: старые отчёты доступны на вкладке
  [«Отчёты»](reports.md), пока их не удалил retention.
- «Стенд» не создаёт `report.json`, поэтому в «Последнем прогоне» не
  появляется.
- Не пересчитывает метрики: показывает то, что записано в файле.
