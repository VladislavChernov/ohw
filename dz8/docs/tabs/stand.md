# Вкладка «Стенд»

[← User Guide](../user-guide.md) · [Глоссарий](../glossary.md)

## Что это и зачем

Самая дешёвая проверка: доступна ли Ollama, какая у неё версия, установлена ли
нужная модель и какой у неё digest. Вкладка не запускает генерацию, поэтому
её безопасно нажимать первой и сколько угодно раз.

Зачем:

- отсечь проблемы стенда до дорогих серий прогонов;
- зафиксировать версию Ollama и digest модели — без них сравнение отчётов
  разных дней некорректно;
- получить подсказку, что делать, если модели нет.

## Как запустить в UI

1. Откройте `http://localhost:8501` и в боковой панели выберите страницу
   **«Проверка модели»**.
2. Перейдите на вкладку **«Стенд»**.
3. Проверьте в боковой панели `Base URL`, модель и `timeout`.
4. Нажмите **«Проверить стенд»** на вкладке (или **«Проверить связь»** в
   боковой панели).
5. Смотрите таблицу под кнопкой: `base_url`, `ollama_version`, `model`,
   `digest`, `ok`. Зелёная строка `Ollama <версия>` — успех; красная строка
   `error` — проблема, рядом будет `command_hint` с командой установки модели.

## Входные параметры

Отдельных полей у вкладки нет: используются значения боковой панели.

| Параметр | Влияние |
|---|---|
| `Base URL` | адрес Ollama |
| `Модель` | какую модель искать в `/api/tags` |
| `timeout, с` | таймаут HTTP-запроса |

Кнопки:

- **«Проверить стенд»** — на вкладке;
- **«Проверить связь»** — дубль в боковой панели.

## Методика проверки

1. `GET /api/version` — получить версию Ollama.
2. `GET /api/tags` — получить список моделей.
3. Найти запрошенную модель по имени (с учётом `:latest` и тегов).
4. Показать таблицу: `base_url`, версия, модель, digest, список моделей.
5. Если модели нет — показать ошибку и команду `ollama pull`.

Генерация не запускается, поэтому проверка занимает доли секунды даже на
холодном стенде (модель при этом не загружается в память).

## Что показывает

| Поле | Значение |
|---|---|
| `base_url` | проверенный адрес |
| `ollama_version` | версия из `/api/version` |
| `model` | запрошенная модель |
| `digest` | digest найденной модели или `-` |
| `models` | все модели из `/api/tags` |
| `ok` | модель найдена и API отвечает |
| `error` | причина, если `ok=false` |
| `command_hint` | готовая команда для установки модели |

## Вердикт

Вкладка не пишет `report.json` и не выставляет `pass`/`fail` в отчёте.

- зелёная строка `Ollama <версия>` — стенд доступен, модель найдена;
- красная ошибка — стенд недоступен или модели нет.

## CLI

```bash
/app/.venv/bin/python -m llm_degradation health --model llama3 --json
```

Код выхода: `0` — модель найдена; `3` — Ollama недоступна или модели нет.

Пример успешного ответа:

```json
{
  "schema_version": 1,
  "ok": true,
  "kind": "health",
  "base_url": "http://ohw-ollama:11434",
  "ollama_version": "0.33.3",
  "model": "llama3",
  "digest": "365c0bd3c000a25d28ddbf732fe1c6add414de7275464c4e4d1c3b5fcb5d8ad1",
  "models": ["llama3:latest", "qwen2.5:7b-instruct"],
  "command_hint": null,
  "error": null
}
```

## Ограничения

- Не проверяет, что модель **отвечает**: это делают остальные вкладки.
- Не проверяет GPU/CPU-режим и скорость.
- Digest берётся из `/api/tags`; в новых версиях Ollama `/api/show` может не
  возвращать `digest`.
- Если `Base URL` указывает на другой хост, проверка покажет именно его, а
  не фактический контейнер.
