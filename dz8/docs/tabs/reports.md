# Вкладка «Отчёты»

[← User Guide](../user-guide.md) · [Глоссарий](../glossary.md)

## Что это и зачем

Список всех сохранённых запусков и просмотр любого из них. Вкладка нужна,
чтобы:

- сравнить результаты разных дней и моделей;
- открыть полный `report.md` без доступа к файловой системе;
- скачать `report.json` для CI, архива или разбора.

## Как запустить в UI

Отдельной кнопки запуска у вкладки нет — она только читает готовые отчёты.

1. Сначала выполните любую проверку на другой вкладке.
2. Откройте страницу **«Проверка модели»** → вкладку **«Отчёты»**.
3. Выберите запуск в выпадающем списке **«Прогон»**.
4. Читайте отрендеренный `report.md`; кнопками **«Скачать report.json»** и
   **«Скачать report.md»** сохраните файлы.

## Что показывает

1. Выпадающий список запусков в формате:

   ```
   <run_id> — <kind> — <verdict>
   ```

2. Выбранный `report.md`, отрендеренный как Markdown.
3. Кнопки **«Скачать report.json»** и **«Скачать report.md»**.

Если отчётов нет — подсказка запустить любую проверку.

## Как это работает

1. `list_reports(output_dir)` читает все `*/report.json`, сортирует по
   `run_id` по убыванию.
2. Для каждого отчёта берутся `run_id`, `kind`, `started_at`, `finished_at`,
   `model`, `verdict`, число прогонов и путь.
3. Выбранный `report.md` читается и отображается.
4. Скачивание отдаёт файлы с именем `<run_id>.json` / `<run_id>.md`.

Битые и несовместимые отчёты пропускаются: в список попадают только валидные
`report.json`.

## Что лежит в каталоге отчёта

```
output/<run_id>/
  manifest.json     окружение, вход, промпт, параметры
  normalized.md     нормализованный вход
  prompt.txt        фактический промпт
  runs/             сырые прогоны
  raw/              полные ответы модели по каждому вызову
  report.json       машиночитаемый отчёт
  report.md         человекочитаемая версия
```

`report.json` — источник истины; `report.md` генерируется из него.

### Подпапка `raw/`

`raw/` — удобная копия всех обращений к модели. Она собирается
автоматически при записи отчёта (`export_raw_logs`) и повторяет структуру
исходных прогонов:

```
raw/
  canary/
    request.json        model, temperature, seed, num_ctx, num_predict, messages
    run-01.txt          полный ответ модели (Markdown)
  runs/
    run-01/
      attempt-01.txt    полный текст первой попытки
      attempt-01.json   метаданные попытки (raw, error, latency, ...)
      attempt-02.txt
      attempt-02.json
  probes/
    H-04/
      run-01/
        request.json    system + user сообщения
        response.txt    полный ответ модели
```

- Для `consistency` и `degradation` каждая попытка (включая неудачные
  ответы, не прошедшие валидатор) сохраняется отдельной парой
  `attempt-NN.txt` + `attempt-NN.json`.
- Для `hallucinations` текстовые пробы пишут `request.json` и
  `response.txt`; пробы, которые используют `run_series`, дополнительно
  попадают в `probes/<id>/`.
- `prompt.txt` в корне запуска — только user-промпт; полная пара
  system/user лежит в `request.json`.
- `raw/` входит в каталог запуска, поэтому удаляется вместе с ним по
  retention. Это дубликат данных из `runs/` и `probes/`, зато читается
  без разбора отчёта.

## Retention

- Хранятся последние `reports.keep_runs` запусков (по умолчанию `3`).
- Очистка выполняется после записи нового отчёта.
- Удаляются только каталоги с валидным `report.json`.
- Baseline в `golden/baseline/` не удаляется.
- Переопределение: `--keep-runs N` или `LLM_LAB_KEEP_RUNS`.
- Каталоги без `report.json` (прерванный прогон) автоматически не
  удаляются — их можно убрать вручную.

## CLI

Список:

```bash
/app/.venv/bin/python -m llm_degradation report --list
/app/.venv/bin/python -m llm_degradation report --list --json
```

Один отчёт:

```bash
... report --run-id <run_id> --format md
... report --report output/<run_id>/report.json --format json
```

Код выхода: `0` при успехе, `2` при ошибке чтения отчёта.

## Как читать

- Начните с `report.md`: шапка, вердикт, причины, прогоны, сводка.
- Если нужна машинная обработка — берите `report.json`.
- Сравнивайте только сопоставимые отчёты: одна модель, один вход, один
  промпт, одинаковые параметры.
- `run_id` содержит время в UTC; сортировка по нему совпадает с порядком
  запусков.

## Ограничения

- Вкладка не запускает проверки и не пересчитывает метрики.
- Показывает не более 100 отчётов; при большем числе старые не попадут в
  список, пока их не уберёт retention.
- Нет удаления и редактирования отчётов из UI.
- Нет фильтра по типу, модели или вердикту — только общий список.
- Отчёт с другой `schema_version` не откроется.
- `report.md` отображается как есть; сырые ответы в него целиком не
  попадают (только цитаты до 300 символов). Полные ответы — в `raw/`.
- `raw/` появляется только у запусков, сделанных после добавления
  экспорта; старые отчёты остаются без него.
